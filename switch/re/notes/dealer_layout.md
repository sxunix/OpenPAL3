### 三段条（`FUN_0043d830` 构造，虚表 0x56acfc，绘制 0x43d940）

`FUN_0043dc40(a, b)` 写 `+0x44 = a`、`+0x48 = b`；`+0x50` 是方向（0 横 1 竖）。横向：
左端头 `(x1, y1, x1+a, y2)`、中段从 `x1+a` 起每 `a` 一块平铺到 `x2−a`（最后一块不裁、

（`0x43dab0`：u = 列 × a / 贴图宽）。

### 选中行上的东西（买装备页事件 `0x46c5dd` 起）

`FUN_0043ebb0(列表, 行)` 返回行锚点 `(列表.x1, 列表.y1 + (行 − 顶行) × 23)`。

- 「持有:N」提示（`+0x19aec`，`"%s:%d"`、Lang44）：`(锚x+90, 锚y, 锚x+180, 锚y+32)`，
  N = `99 − 可买数`，也就是背包里已有几个。
- 加减钮：`+0x1884c` 起是一个小部件（两个 rect、「减」`+0x1886c` id 0x195、「加」`+0x189c4`
  id 0x196，宽 24、高 40、`+0x18b24` 排法、`+0x18b28` 间隔 20）。排法 1（初值）：「加」在
  `(锚x+200, 锚y−4)`，「减」在它右边再隔 20；排法 0 两个对调。可买数为 0 时两个都置灰。

原版一单可以在好几行上各挑数量，「累计」是整单的钱，确定时一起结（卖页每类各有一个
累计，`shop.md` §5.1）。

### 滚动条（`FUN_0043e3b0` 建，`FUN_00441380/442170/442230` 摆，画 `0x4414f0`，命中 `FUN_00441e30`）

列表控件 `FUN_0043e3b0(基名, rect, 38, 27, 0)`：基名 `Communal\Scroll\scrollbar`，右边 38 像素是滚动条列。
页面再给整条 rect、上下钮 rect、滑块宽高：

    买两页（0x45bd1d / 0x46e274）：条 (731,80,769,381)  上钮 (738,94,760,120)   下钮 (738,347,760,373)  滑块 27×28
    卖页（0x471b5e，每个页签一个列表） ：条 (732,107,770,385) 上钮 (739,120,761,146)  下钮 (739,352,761,378)  滑块 27×28

贴图 `scrollbar0..9.tga`（`FUN_004413c0` 按 `%s%d.tga` 载十张，散文件，不在图集里）：0/1/2 滑块常态/悬停/按住，
3 是 16×128 的槽（画的函数里没用到），4/5/6 上钮，7/8/9 下钮。`+0xa0` 是鼠标在哪一块（0 上、1 下、2 滑块），
`+0x45`/`+0x44` 是按住。

滑块 x = 上钮 x（`+0x150` = 上钮.x − 条.x），y（`FUN_00442000`）：

    range = max − min；range ≤ 0 时不画滑块
    y = (下钮.top − 上钮.bottom − 高/2) × pos / range + 上钮.bottom，画的时候夹到 [上钮.bottom, 下钮.top − 高]

命中顺序：上钮 0、下钮 1，能滚时再看滑块 2、滑块上面的槽 3、滑块下面的槽 4。

## 5. 还价

底栏「还价」打开五个折扣钮 `bDK5..9`（id 0x111..0x115，84×50）：

```text
五折 (492,439)  六折 (576,439)  七折 (660,439)
八折 (492,491)  九折 (576,491)
```

和商人的话那块区域重叠。还价结算 `FUN_00460a90` 每还一次都先 `FUN_00461fd0(0)` 把五个钮收起
（接受、拒绝、严词拒绝都一样），商人的话才露出来；被拒了要再点「还价」。买装备页另有 `bEquipYes` (511,492,595,542) / `bEquipNo`
(635,492,719,542)，见 §5.1。

### 5.1 买的时候就穿上（2026-09-12 追到）

点击事件在一个 Ghidra 没收的函数里（0x46b4b0 起，按「消息 − 1000」查 0x46cf6c 的表；case 1 是点按钮，
按「控件 id − 0x102」查 0x46cfd0 的字节表再跳 0x46cf98）。`FUN_00462220(亮不亮)` 同时显隐这两个钮。

- **什么时候亮**：点「+」（0x46bce5：这一行数量 +1、重算累计）后，这一行数量 > 0 就清空商人的话、收起
  `+0x62f0`、`FUN_00462220(1)`（ebp 在 case 1 入口是 1）；选行（case 7，0x46c2dc）时这一行数量 > 0 且
  「已穿」数 `+0x16d9c[行]` 为 0 就亮，否则收。
- **装备 0x129**：收钮、`+0x16d00 = 1`（选人状态）、`FUN_00462280` 点亮能穿的人、`FUN_00462120`：队里能穿的
  （物品 `+0x266 + 人`）一个都没有就弹 `DAT_00dd4a3c`；只有一个就直接 `FUN_00469eb0(人, 格, 行)`（衣 0、帽 3、
  鞋 4、武器 1；饰品两格不走这条）；多个就等玩家点。
- **点人**：case 9（0x46c95a 起）按每人六个小图标的控件 id 表（0x56b4dc / 4f0 / 504 / 518 / 52c / 540）比，
  点到哪一格就 `FUN_00469eb0(人, 那一格, 行)`。
- **`FUN_00469eb0`**：这一行的数量挪一件到「已穿」`+0x16d9c`，记下谁的哪一格穿了哪一行（`+0x16d24`），
  那一格先前预订了别的就退回去；**当场改角色记录里的装备**（旧的备份在页面里），头像刷新。
- **不装备 0x130**：收钮、`+0x16d00 = 0`。
- **取消**（`FUN_0046acd0`）：每件已穿的按 `FUN_0046a8b0(人, 格)` 把备份写回，数量和已穿清零。
- 结账（`FUN_004615f0`）清掉这些状态；已穿的那几件怎么扣钱、换下来的去哪，结账前半段没逐条读 [推断：照常收钱，
  旧装备回背包]。

## 6b. 物品 3D 预览

说明面板（`Info.tga`，贴在 (218,142)）上方的黑框里是选中物品的模型。三个子页都有（`FUN_0045b990`、
`FUN_0046df40`、`FUN_00471590` 都引用 `Item\%s\%s.pol`）；买装备页的对象在 `+0x16db0`，卖页在 `+0x5328`。

- 视图控件：构造 `FUN_00439030`，虚表 0x56ac20。`FUN_00439740` 建一台自己的 `gbCamera`（`SetDimention(800,600)`，
  `+0` 视角 = 0、`+4` = 3000）。gbengine 的 `GetFOV` 读 `[this+0]`、`GetOrthoSize` 读 `[this+4]`，`SetAsCurrent`
  在视角为 0 时走正交分支，横向半宽 = `+4`、纵向 = `+4 × 高/宽`——**是正交相机**。
- 选中一行（买装备页 `0x46c41e` 起、卖页 `0x4703f0` 起）：

      weapon_type(+0x265) == 5   → FUN_0043a070(228)  FUN_00439930(330, 280, 600)
      item_type(+0x264)  == 11   → 228                 (330, 272, 600)
      id == 0x1fb2 / 0x1fc4      → 180                 (330, 252, 600)
      其余                        → 180                 (330, 268, 600)

  `FUN_0043a070(s)` 把 `+0xe8` 和相机 `+4` 设成 s；`FUN_00439930(x, y, h)`：

      dx = −(2x/800 − 1)·s        dy = (1 − 2y/600)·s        // 纵向也乘 s，照原样
      SetLookAt(eye = (dx, h − dy, 1600), at = (dx, −dy, 0), up = (0,1,0))

- 然后 `sprintf("Item\%s\%s.pol", 模型名, 模型名)` 交给 `FUN_00439230` 载入（模型名和一个全局串相等时写 "NONE"），
  再 `gbGeomNode::ReplaceTexture("Item\<模型>\<模型><图标>.tga")`。包里实际是 `.dds`（`item/PJ/` 下
  `PJ.POL`、`pj1..pj4.dds`），同一个模型按物品换颜色。`+0x16dfc` = 1 表示有模型可画。
- 渲染（虚表 1 号 `0x439410`）：`gbSceneGraph::Begin(camera)`，挂一盏方向光（四元数：绕 X 45°，再乘绕 Y 90°），
  `SetAsCurrent(3)`，每个模型 `Push → Translate → 六次 Rotate（+0xf8..+0x110）→ Scale(+0x114..) → 画 → Pop`。
  买卖页从不写这些旋转字段（扫全 exe 没有对 `+0x16ea8..+0x16ecc` 的写），**模型不转**。

移植端：radiance 的界面总画在 3D 之上，不能照原版在主画面上直接画。改成一个只放这件物品的离屏场景，每帧
`render_scene_to_target` 画进 1024×768 的渲染目标，再把黑框那一块 (256,159)-(400,340) 贴到界面上（黑框右上角
压着「身体」页签，所以只贴到 400）。相机只有透视，用 `2·atan(s / √(600²+1600²))` 的窄视角在同一位置近似正交
[近似]；光照用满环境光 [推断]。渲染引擎句柄挂在 `AssetManager` 上（宿主建资源管理器时塞进去）。代码在 `commands/item_preview.rs`（冶炼页共用，相机和贴的范围按页面传），
离屏场景和相机本身已经挪到 `openpal3/model_view.rs`，和侠义榜的 3D 视图共用（见 `cvd_playback.md` §8）。

**坑：离屏目标不能在画完的同一帧释放。** Vulkan 的 `render_scene_to_target` 当场提交，把目标自己的「画完」
信号量放进引擎的 `pending_offscreen_waits`，本帧主画面提交时等它。界面在 `update` 里画了预览、同一帧又被关掉
（冶炼页出完货按离开），`VulkanRenderTarget::drop` 把信号量销毁了，主画面去等一个已销毁的信号量，进程不留
panic 直接退出（2026-09-12 在冶炼页复现：出货后第三次 Escape 关掉命令时崩）。`item_preview.rs` 的做法：析构时把
场景和目标挂到一个线程局部的退役表里，下一次建预览时再清——那时至少隔了一帧主画面。GL 的离屏纹理
自下而上，Switch 上把 v 翻过来 [推断：还没在机器上看过]。

## 7. 移植端的取舍

- 背景（2026-10-11 查实）：原版打开时 `FUN_004bdc40` 把场景按 512×384
  （`gbCamera::SetDimention(0x200, 0x180)`）渲染进一张渲染目标，之后每帧（`0x45a493`
  调 `0x459900`）用白色、alpha 0x3e 拉满全屏叠一次。叠的方式是**加法**：`0x45995d`
  走 `FUN_00540d20`，效果 `DAT_01895058` = `gfxscript\ui_tex_color.gbf`，里面写死
  `SrcBlend = SRCALPHA; DestBlend = ONE`（见 `ui_render_states.md`）。所以画面是
  `场景 + 0.24·截图`——把场景自己当光源的一层柔光，只提亮不压暗；截图又是半分辨率
  拉满屏的，提上去的那份还带点糊。同形的还有五处：`0x47c260`、`0x4a4820`、`0x523600`、
  `0x527cd0`（鉴定）、`0x529c80`（打苍蝇）。移植端不加这一层，场景照常画。
  （第一版按「压暗」做了一层 76% 的黑，已撤掉。）
- 默认字色：控件基类 `FUN_00445aa0` 把 `+4` 设成 0xff050500（近黑）；页面里商人的话、「持有」
  「累计」都没另设，移植端统一用列表那个暗绿 RGB(0x0c,0x1f,0x00)。
- 选中行（2026-10-10 查清，2026-10-11 移植端跟上）：行文字的颜色参数和选中与否
  **无关**——`0x43e9bf` 走逐行的 `[+0x1f4][行]+0x44`（当 `[+0x4ac][行] != 0`），
  否则 `0x43e9d3` 直接 `push 0xd91780`，即全局默认 (0x40,0x40,0x3c,α=0xc8)
  深灰半透（`FUN_00445a60` 按表面格式写）。选中条是**行循环跑完之后才盖上去**
  的（循环出口 `0x43ea6d`、算矩形 `0x43eab4`、画 `0x43eb66`），条 = 贴图
  `[+0x480]` × 颜色 `[+0x498]` = (0xa8,0xa8,0xa8,α=0xc8)，靠半透让字透出来。
  `(0xa8,0xa8,0xa8,0xc8)` 这四个字节全 exe 只有 `0x43e045`..`0x43e062` 一处写、
  `0x43eb3c` 一处读，所以每个列表控件都一样。
  **条是「加」上去的，不是「盖」上去的**（2026-10-11 查实）：`0x43eb66` 调的是
  `FUN_00540c60`，用 `DAT_01895058` = `ui_tex_color.gbf`，`SrcBlend = SRCALPHA;
  DestBlend = ONE`。`ListBoxSelPic` 是 256×32、24 位不带 alpha 的一条**绿色横向
  光带**：文件第 0 行（画面最下面一行）起往上亮到第 9–10 行峰值 RGB(35,82,71)，
  第 22 行以上全黑；横向两头各约 16 像素收到黑，中间平。乘上 (0xa8,0xa8,0xa8)·0xc8
  之后，加上去那一份峰值约 (18,42,37)，所以选中行是「被绿光提亮一圈」，字还在，
  原样可读——这也正是字色不随选中变的原因。
  移植端原先反着来（条在字下、选中行字换 0xfffafa），2026-10-11 改成照原版：字一律
  用 [`INK`]，条在循环之后叠上去；imgui 只有一种混合状态，所以把该加的那份在装贴图
  时折成 alpha（`openpal3::ui_tex::bake_additive`，误差 `dst·A`，A 峰值 45/255）。
  当铺、炼妖、对话选择框三处一起改了。
  **还差一步**：原版行文字用的是上面那个 0x40403c/α=0xc8，移植端用的是页面
  其它文字那个不透明的暗绿 RGB(0x0c,0x1f,0x00)，比原版更暗；买卖这张列表走的
  是逐行还是默认那条路还没追。
  `+0x488/+0x48c/+0x490 = −4/−6/10` 也对上了：它们是加在选中条矩形上的逐边
  偏移（`0x43eb35`/`0x43eb4e`/`0x43eb46` 分别加进那四个角的坐标）。
- 按钮字居中（2026-10-11 查实）：按钮控件的构造 `FUN_0043a770`（vtable 0x56ac70）
  在 `0x43a7d9` 把对齐字段 `+0xd0` 写成 1，全 exe 只有这一处写它。画字那段
  `0x43af66` 把 `+0xd0` 当第 5 个参数递给 `FUN_00541160`（第 4 个参数 `0x43af6d`
  压的是 1 → 16 像素字），`FUN_00541210` 里 `param_5 == 1` 就是
  `x 偏移 = (右 − 字节数·字号/2 − 左)/2`、`y 偏移 = (下 − 上 − 字号)/2`，横竖都居中；
  字宽按 GBK **字节**数算。别的值一律左上角贴着矩形画，没有第三种。
  字的矩形是 `(左 + [+0x68], 上 + [+0x6c], 右, 下)`，建按钮时 `0x43a9ad`/`0x43a9b0`
  把这两个偏移置 0。
- 三态按钮 0 常态 / 1 悬停 / 2 按下（2026-10-11 查实）：状态在 `+0x60`，构造置 0，
  事件那段 `0x43ab20` 起写 1 和 2，画的时候 `0x43ae0b` 按 `[+0xb8 + 状态·4]` 取贴图。
  移植端没有「按下」这一态，2 号图用不上，原版按下时的两处变化也没做：字色三个通道
  各减 0x40（夹到 0，`0x43af04`..`0x43af48`）、字再往下挪 6（`0x43af53`）。
  另外没贴图的按钮（`+0x3c == 0`）字色是一直减 0x40 的。
