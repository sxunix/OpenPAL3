# 滑雪（SCE 107）

雪岭镇往下滑那一段。实机只有 M22 的 proc 1001「滑雪之前」调过一次，传 1003
（「坠下山崖」）。地址都是 PAL3 v1.4 未加壳 `PAL3_unpacked.exe`。

## 1. 入口与收尾

`LAB_00436f40`（一个 int 参数）：

```text
DAT_00dba254 = 参数           // **过程号**
FUN_0044f610(0xb)            // 进模式 11 = 滑雪
new 等待任务 FUN_00434ca0(0xb) → FUN_00434c40
```

模式 11 的对象在 `FUN_0044f8d0` 的 `case 0xb`：`operator_new(0x130)` +
`FUN_0052ec90` 构造 + `FUN_0052f300` + `FUN_0052ed30`。

每帧是 `FUN_0052f350`（同一个函数兼做帧时间平滑）；滑完之后：

```text
写注册表 SOFTWARE\SOFTSTAR\PAL3\S_GAME / S_GAME_C
FUN_0044f610(this->+0x12c)            // 回上一个模式
if (this->+0x12c == 0)                 // 回冒险模式那一支
    FUN_00432170(DAT_00dba254, 0)      // 把参数当过程跑
停掉两条声音流
```

脚本那头自己会核对：M22 proc 1001 在调 107 之前先
`13 var-32768, 130400`（赋值），proc 1003 开头 `8 var-32768, 130400` 再比一次
——**这个值是脚本自己写的，不是滑雪的产物**。

## 2. 滑雪途中会捡东西

这是它唯一的持久影响。

- 收集槽只有 **3 个**：`+0x50c` 存 id（三个 dword），`+0x20c` 起每 0x100
  存一个名字，件数在 `+0x518`（0x531fe2 一带清空）。
- 捡的时候（0x531ac0 一带）先 `FUN_0040dcf0` 查背包：**已经有的就不捡**，
  没有才 `FUN_00530bc0` → `FUN_00532360(id, flag)` 登记；`flag` 存进
  `+0x1dad`。
- 结算 `FUN_00532410`（跑完由 `FUN_005310c0` 在计时器归零时调）：
  ```text
  分数 = 收集件数(+0x518) × 100 + (+0x11a0) × 30
  if (收集件数 > 0 && 参数 != 0):
      逐个列出来，且 +0x1dad 非零时才 FUN_0040ccf0 真的塞进背包
  else:
      弹「0 分」那一版文本
  ```

除此之外，整段 0x52b000–0x534000 里没有动钱（`DAT_00c05f54`）、没有动角色的
精（`DAT_00c0476c`），也没有别的扣物品调用——**滑雪不花钱也不掉血**。

## 3. 移植

- SCE 107 的桩早就把参数当过程跑了（和原版 `DAT_00dba254` 那一步一致），
  所以**剧情是接得上的**。
- 没做的是滑道本身（3D 那一套）以及**途中的收集品**：原版最多能捡 3 件，
  跑完才进背包。移植端跳过这一段等于这几件东西拿不到——不发是因为不知道
  玩家会捡到什么，凭空发等于替原版编结果。
