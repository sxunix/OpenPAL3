# 滑雪（SCE 107）

雪岭镇往下滑那一段。实机只有 M22 的 proc 1001「滑雪之前」调过一次，传 1003
（「坠下山崖」）。地址都是 PAL3 v1.4 未加壳 `PAL3_unpacked.exe`。

**这个游戏是什么**：景天（角色 101，动作 h01..h06）踩着剑 J13 当雪板，沿
`Skee_path.ASE` 那条固定路径往下滑（源码 `subgame/Skee/Skee_slider.cpp`；
本文下面几节最早按 exe 读，把滑的人叫成了「雪球」，指的都是他），**没有左右
操控**，玩家只有两个动作——按住鼠标左键加速、点右键跳。滑过半程之后，在过
半程那一点放出一个雪球（等 300 毫秒）以同样的巡航速度追上来，被追上就结束。路上摆了六个障碍
（撞上就减速到停住），三件古董悬在跳起来才够得着的高度。59 秒倒计时。

## 1. 入口与收尾

`LAB_00436f40`（一个 int 参数）：

```text
DAT_00dba254 = 参数           // **过程号**
FUN_0044f610(0xb)            // 进模式 11 = 滑雪
new 等待任务 FUN_00434ca0(0xb) → FUN_00434c40
```

模式 11 的对象在 `FUN_0044f8d0` 的 `case 0xb`：`operator_new(0x130)` +
`FUN_0052ec90` 构造 + `FUN_0052f300` + `FUN_0052ed30`。

每帧是 `FUN_0052f350`；滑完之后：

```text
写注册表 SOFTWARE\SOFTSTAR\PAL3\S_GAME / S_GAME_C
FUN_0044f610(this->+0x12c)            // 回上一个模式
if (this->+0x12c == 0)                 // 回冒险模式那一支
    FUN_00432170(DAT_00dba254, 0)      // 把参数当过程跑
停掉两条声音流
```

脚本那头自己会核对：M22 proc 1001 在调 107 之前先
`13 var-32768, 130400`（赋值），proc 1003 开头 `8 var-32768, 130400` 再比一次
——**这个值是脚本自己写的，不是滑雪的产物**。

## 2. 帧时间

`FUN_0052f350` 把帧时间放进一个环形缓冲取平均，再乘 `_DAT_005f4b9c`
= **46.68** 才交给下面的每帧更新（缓冲没填满之前直接给 1.0）。所以第 3、4
节里那些速度、加速度都是「每 1/46.68 秒」的量：巡航 10.86 换算下来约
**507 单位/秒**，全长两万出头的雪道大概四十秒滚完，和 59 秒的限时对得上。

## 3. 雪球（`FUN_00531260`，2594 字节）

状态在 `+0x310`，切换走 `FUN_00530be0(n)`（顺手把旧状态存进 `+0x314`）：

| 状态 | 处理函数 | 干什么 |
|---|---|---|
| 0 | — | 正常滚 |
| 1 | `FUN_00530f70` | 撞到障碍之后掉速 |
| 2 | `FUN_00531010` | 跳在空中 |
| 3 | `FUN_005310c0` | 收尾，速度归零后结算 |

每帧主干：

```text
目标 = FUN_0052dc40(+0x290)          // 第一个累计距离 ≥ 已滚距离的路径点
       返回空 → +0x2ac=0、+0x305=1、FUN_00530c00(0)      // 滚到头了
方向(+0x284/288/28c) = Normalize(目标 − 位置(+0x278/27c/280))
位置 += 方向 × 速度(+0x294) × dt
+0x290 += |Δ位置|
+0x2a4 = 朝向角(rad × 57.29578)，+0x2a8 = 俯仰
镜头：距离 +0x2c4 = 780，方位 +0x2c8 = 90 − (朝向 − 90)，俯仰 +0x2cc = −56
```

`FUN_005309a0` 里球的初始位置就是路径点 0，`+0x290 = 0`——于是第一帧的差
向量正好是零。方向的初值 `(0, 0, −0.001)` 就是给这一帧兜底的。

各个常量（都在 `FUN_005309a0` 里写死）：

| 字段 | 值 | 是什么 |
|---|---|---|
| `+0x294` | 10.86 | **速度**（第 55 轮以前这一条记成「计时条」，是错的） |
| `+0x29c` | 10.86 | 不加速时的速度上限 |
| `+0x2a0` | 28.86 | 按住左键能冲到的上限 |
| `+0x318` | 0.12 | 没到巡航速度时每帧补的量 |
| `+0x32c` | 6.0 | 起跳初速 |
| `+0x330` | 0.03 | 下落时每帧给跳跃速度加的量 |
| `+0x320` | `+0x1e4 × 4/3` | 跳的高度上限 |
| `+0x1e4` | 球半径 | 从球的 OBB 取（`FUN_005306a0` 末尾），取的是哪一项还没钉死 |

### 加速与跳跃的输入

两个全局是**鼠标**：`DAT_00bfc5e8/f4` 是左键的事件类型和按住状态，
`DAT_00bfc5f8/604` 是右键的（在 `FUN_00442bd0` 的按钮命中里
`DAT_00bfc5f4==1 && (DAT_00bfc5e8&0xf)==1` 发左键点击消息 0x3f1，
`DAT_00bfc604==1 && (DAT_00bfc5f8&0xf)==1` 发右键 0x3f2）。滑雪读的是：

- **按住左键**（`DAT_00bfc5f4 == 1`）：状态 0 且过了半程时，
  `速度 += 0.2`（不乘 dt），封顶 `+0x2a0` = 28.86。
- **点右键**（`(DAT_00bfc5f8 & 0xf) == 1`）：状态 0 时起跳。

没有第三个输入——**这个游戏没有左右操控**，躲障碍只能靠跳过去。

### 三个状态处理函数

`FUN_00530f70`（撞后）：`Δ = dt × 0.12`。`+0x31d` 锁住就什么都不做；
`+0x31c == 0` 时速度加 Δ，到 `+0x29c` 就置 `+0x31c=1, +0x31d=1`；
`+0x31c == 1` 时速度减 Δ，减到 ≤0 就清 `+0x31c`、放声音、回状态 0。撞到
障碍时设的是 `+0x31c=1, +0x31d=0`，所以走的是「减到 0 再回状态 0」那一支。

`FUN_00531010`（跳跃）：上升（`+0x31e==1`）`+0x324 += dt × +0x328`、
`+0x334 = +0x324 + 当前 y`，`+0x324 ≥ +0x320` 转下落；下落
`+0x334 -= dt × +0x328`、`+0x328 += 0.03`，落到 `+0x334 ≤ 当前 y` 归位、
`+0x328` 复位成 6.0、回状态 0。碰撞检测在状态 2 时用 `+0x334` 当 y，所以
**跳起来就能从障碍上面过去**。

`FUN_005310c0`（收尾）：速度 `-= dt × 0.5`，掉到 0 时若 `FUN_0052f330()`
为真且 `+0x2c2` 没置位 → `FUN_00532410(+0x302)` 结算并置位。

## 4. 障碍、收集品、追上来的雪球

碰撞在 `FUN_00531260` 的 `状态 != 1 && != 3` 那一段（状态 0 和 2 都查）：
用球的 OBB（`+0x1e8`，中心加上球位置）逐个 `gbOBBox::IsColOBB`。

- **障碍**：`FUN_0052fbb0(i) = 场景 + 0x6d8 + i × 0x4c`，`i < 6`。撞上 →
  `FUN_00530be0(1)`、`+0x31d=0`、`+0x31c=1`、放撞击声。等减速状态走完
  （`+0x314 == 1` 那一帧）再把球推过障碍：`+0x290 += 障碍最大半轴 × 2`
  然后 `FUN_00531160` 把球贴到那个路径点上。
- **收集品**：`FUN_0052fc30(i) = 场景 + 0xc1c + i × 0x4c`，`i < 3`。撞上 →
  `FUN_0040dcf0` 查背包，**已经有的就不捡**；没有才把模型藏起来
  （`+0xd00 + i = 0`）、`FUN_00530bc0` → `FUN_00532360(id, +0x304)` 登记。
- **追上来的雪球**：场景的 `+0xd08` 又加载了一遍 `Ball.POL`，自己的路径
  距离在 `+0xe90`、速度 `+0xe94` = **10.86**（和玩家巡航同值），
  `+0xea0` 为真才跑（`FUN_0052fe30`，每帧还自转 16°）。判定在
  `FUN_00530f20`：`|玩家距离 − 追球距离| < 追球 OBB 半径` → 追上。
  玩家不加速就正好跑不掉，所以撞了障碍停一下基本就完。

`+0x2ac`（滚过半程没有）：`+0x23c × 0.5 ≤ +0x290` 时置 1，其中 `+0x23c`
是路径全长（路径对象就内联在球的 `+0x234`/`+0x238`/`+0x23c` 三个字段上，
正好是 `FUN_0052dc40` 里的 `in_ECX[0..2]`）。加速键和终点判定都挂在它上面。

### 摆放（`FUN_0052ed30`）

**障碍是固定的，收集品是随机的**：

```text
step = (路径点数 − 0x618) / 6           // 0x618 = 1560
下标 = 300，六个障碍每次 += step
  → 实机 4950 个点：step = 565，下标 300 / 865 / 1430 / 1995 / 2560 / 3125

收集品 i：
  上一个模式 == 4 → 直接隐藏，一件也不摆
  否则 隐藏 = FUN_0052ece0(id)             // 背包里已经有了
       r    = __ftol(球半径 +0x1e4)         // 取整
       下标 = rand15() % 路径点数 + 100      // 原版没夹，最大能到 N+99（越界）
       位置 = (点.x, 点.y + r + r/3, 点.z)   // 抬到跳跃上限那个高度
```

`r + r/3` 是整数除法，`+0x320 = +0x1e4 × 4/3` 是浮点——所以**跳到顶正好
够得着**，不跳就碰不到。

三件收集品的 id **写死在 exe 里**（`FUN_0052f6c0` 开头把 `0x1783`、
`0x178d`、`0x1781` 填进场景的 `+0x8a4`）：

| id | 名字 | 价钱 |
|---|---|---|
| 6019 | 鹿纹瓦当 | 80000 |
| 6029 | 刻辞整甲 | 98000 |
| 6017 | 盘龙古砚 | 80000 |

`basedata/SubGame/Skee/skee_sav.sv` 里也写着这三个号，但**代码没读这个
文件**（先前笔记说是从它读的，订正）。跳过滑雪等于这三件古董拿不到。

## 5. 计时与结算

倒计时在 HUD 对象的 `+0x11a0`，初值 **0x3b = 59 秒**，每 1000 ms 减 1
（`GetTickCount` 比 `+0x11b4`），减到 0 → `+0x11ac = 1`、`FUN_00530c00(1)`。
`FUN_00532960` 把秒拆成十位个位画在计时条上。

`FUN_00530c00(p)`：进状态 3、`+0x301 = p`、**`+0x302 = (p == 0)`**。

| 怎么结束 | 传的 p | `+0x302` | 发不发东西 |
|---|---|---|---|
| 路径滚到头（`FUN_0052dc40` 返回空） | 0 | 1 | 发 |
| 被追球追上（`FUN_00530f20`） | 1 | 0 | 不发 |
| 倒计时归零 | 1 | 0 | 不发 |

结算 `FUN_00532410(param)`（param 就是 `+0x302`）：

```text
分数 = 收集件数(+0x518) × 100 + 剩余秒(+0x11a0) × 30
if (剩余秒 < 1 || param == 0):
    只弹「没滑完」那版文本，分数那一栏填 0，一件也不发
else:
    逐个列出收集品；+0x1dad 非零时才 FUN_0040ccf0 真的塞进背包
```

`+0x1dad` 来自 `+0x304`，`FUN_0052ed30` 里按「上一个模式 == 4 → 0，否则
1」定。（先前笔记把发放条件写成「收集件数 > 0 && 参数 != 0」，订正成
「剩余秒 ≥ 1 && 参数 != 0」。）

除此之外，整段 0x52b000–0x534000 里没有动钱（`DAT_00c05f54`）、没有动角色
的精（`DAT_00c0476c`）——**滑雪不花钱也不掉血**。

## 6. 滑道是什么做的

资源都在 `basedata/SubGame/Skee/`：

| 路径 | 内容 |
|---|---|
| `SkeeScene/Scene/m22-6.POL` + `.DKM` | 雪道本体的模型 |
| `SkeeScene/Scene/Skee_path.ASE` | 3DS MAX 的 ASCII 导出，节点名 `skee_path`——雪道的路径线。exe 里写死的路径是 `basedata\Skee_path.ase`（游戏根目录下也有一份）|
| `SkeeScene/Ball/Ball.POL` | 滚下去的那个雪球，半轴 65.62 × 65.53 × 65.53（就是个球）|
| `SkeeScene/Obstruct/obstruct0..5.POL` | 障碍 |
| `SkeeScene/Treasure/Treasure0..7.POL` | 收集品 |
| `SkeeScene/Weapon/J13.POL` | 球上挂的那把剑（`FUN_005306a0` 里加载）|
| `skee_sav.sv` | 一行一个物品 id 的文本，内容和 exe 里写死的三个一样，但没被读 |
| `SkeeTimeBk.tga`、`sb0/sb1.tga` | 计时条和界面片 |

那十四个 `.POL`（obstruct0..5 + Treasure0..7）**字节完全相同**，都是
1310 字节的同一个盒子，半轴 72.38 × 14.91 × 27.54——所以「六种障碍」
「八种收集品的模型」这个说法要订正：只有一个模型，复制了十四份，靠贴图
和位置区分。装载循环用 `"%s%s%d.pol"` 拼名字（`FUN_0052f840`，`cmp esi,6`）。

## 7. 路径怎么读（`FUN_0052d7c0`）

扫 ASE 找 `*NODE_NAME "skee_path"` 那个 `GEOMOBJECT`，把它的 `*MESH_VERTEX`
列表摊成每点 **32 字节**：

```text
+0x00 x   +0x04 y   +0x08 z
+0x0c 累计距离 = 上一点的累计 + 本段长
+0x10 本段长 = SQRT(dx² + dy² + dz²)
+0x14/18/1c 指向下一个点的单位方向（存在**上一个**点上）
```

**坐标不是按 ASE 的顺序进去的**：那句是
`FUN_00554a81(f, "%f %f %f", 基址, 基址+8, 基址+4)`——ASE 的第二个数进
`+0x08`、第三个数进 `+0x04`，然后 `+0x08` 再取反。也就是
**`y = ASE 的 z`、`z = −ASE 的 y`**（3ds max 是 z-up，引擎是 y-up）。
写入位置按文件里那个顶点下标，不是出现顺序。全长取的是最后一个点的
`+0x0c`。

实机那条路 **4950 个点**，x 从 −10220.8 铺到 +9019.9，高度（引擎的 y，
即 ASE 的 z）从 1303.8 降到 893.5，最高 1327.2 最低 224.4，全长两万出头，
平均每段四个单位。

（先前笔记写的是「z 取反」，那是把 ASE 的第三个数当成了记录里的 z，订正。）

## 8. 移植

- 规则：`states/ski.rs`——速度模型、跳跃、撞障碍的减速与推开、收集品、
  追球、59 秒倒计时、算分与发放条件，单测覆盖。碰撞照原版是**不转的盒子
  相交**（`gbOBBox::IsColOBB` 对轴对齐盒子退化成三根轴的区间重叠）：
  - 人物盒子是**当前动作**的包围盒（`.mv3` 头里的 AABB）：滑取 h02、跳取
    h05 [推断：h01/h03/h04 不分]；`+0x1e4` 是开局（还在 c01 上）量的人高
    `box.ylen` = 76.04，跳高上限 `×4/3`、古董抬高 `76 + 76/3 = 101`；
  - 障碍是 `obstruct0..5.pol` 的盒子；古董是**物品自己的模型**
    `Item\<模型名>\<模型名>.pol`（`FUN_0052f8e0`，不是 `SkeeScene/Treasure`）；
  - 撞上当帧不推：减速到停、转回正常滑之后还压着障碍才推「最长边全长 × 2」；
  - 追球从过半程那一点放出（`+0x2b0`，300 毫秒后），先前从 0 起滚是错的。
- 路径：`states/ski_path.rs`（解析 + 按距离取点，二分 + 线性插值），
  `pal3_ski_path_census` 拿实机文件核对。
- 画面：`openpal3/ski_view.rs`，命令开始时把场景压到栈顶。雪道 `m22-6.pol`、
  景天（`Translate → Rotate(行进角, Y) → Rotate(平衡角 − 90, Z)`，角是**度**；
  收尾时转 −90、不倾斜、剑收起）、剑 J13 挂在 `tag_weapon1`（`.mv3` 里那段
  「未知数据」就是挂点轨迹：tick、位置、四元数，取的时候 slerp 后 **w 取反**）、
  六个障碍、转着的古董（每帧 6 度）、追球（绕 X 每帧滚 16 度）。镜头看点在人头
  上 200、偏航 `90 − (行进角 − 90)`、俯仰 −56、退后 780、视角 26；雪球出来时
  偏 80 度停 2.6 秒再摆回。动作：h02 循环，隔 1–3.6 秒随机换 h03/h04 一遍；
  跳 h05、落地 h04、摔 h06、起身 h01、停下 c01。
- 界面：右上计时牌 `SkeeTimeBk.tga` + 鉴定小游戏的中文数字图（十位、个位），
  雪球出来后右边 `sb0/sb1`（鼠标图，提示按左键）每 160 毫秒换一张。都是贴图
  左下角 1:1 裁。
- 还差的：开局的操作说明框（`m_ctrlinfo.DoModel`，lang 254–257，点掉才开始
  计时）和结算框（`DLG_MSGBOX`）还是文字；音乐 PI24、开头白屏淡入没接；
  收集品下标 `rand15() % N + 100` 原版会越界读到 N+99，移植端夹在最后一个点上。
