# 战斗镜头

来源 `PAL3_unpacked.exe`（`D:\Project\PAL3\Combat\CBStageCam.cpp`）。移植在
`yaobow/shared/src/openpal3/combat/camera.rs`，机位解析在 `combat/stage.rs`，
普查测试 `tests/pal3_combat_stage_census.rs::the_combat_camera_data_hangs_together`。

## 1. `cbCam.ini`：游戏只读 `EditorCam*`

`FUN_00504130` 从 `EditorCam0` 起逐个读（x、y、z、yaw、pitch、roll），读到第一个缺的编号
就停，最多 64 台，存进 CBStageCam `+0x11e8` 起的数组（每台 0x18 字节）。**exe 里没有
`DefaultCam` 这个字符串**，那十八节是编辑器留下的，游戏不读。`FUN_00504240` 是编辑器
「把当前镜头存成新的一台」（写回 ini）。实机 29 台（`EditorCam0..28`，节的先后是乱的）。

先前移植端取 `DefaultCam0`、朝向一律看原点、FOV 39°——三条都撤回。

朝向：`forward = (sin yaw·cos pitch, sin pitch, −cos yaw·cos pitch)`。正负号靠 29 台验：
这样算视线落地点离站位重心大多 < 200；x 取反大多 300~1400。

视场角：`FUN_00504540` 往相机 `+4` 写 50.0（同时 `+0x1d4` = 10000，远裁剪面）。按 4:3
水平视角理解 **[推断]**：Pal3.Unity 的垂直 39° 正是它的换算（≈ 50.6°）。

## 2. `flexcam.dat`：镜头序列

430000 字节（`FUN_00504f40`）：2000 条 0xcc 字节的记录 + 2000 个占用字节 + 100 序列 × 50
步的 i32 记录号（-1 空）。实机 36 个序列有内容：0–8、10、13、20、51–60、70–83。

记录字段（`FUN_00506340` 的读法）：

| 偏移 | 含义 |
|---|---|
| +0x15 / +0x16 | 运行时：已开始 / 已完成 |
| +0x18 | 运行时：开始时刻 |
| +0x1c | 时长（秒） |
| +0x20..+0x34 | 起点 x y z yaw pitch roll |
| +0x38..+0x4c | 终点 |
| +0x58 | 起点用记录里的（否则取当前镜头，`FUN_005062d0`） |
| +0x59 / +0x5b | 移动方式：`0x59 == 0` 一种、`0x5b != 0` 一种、其余「匀速」 |
| +0x5c / +0x5d / +0x5e | 这一步的三个动作：移镜头 `FUN_00506340` / `FUN_005075e0` / `FUN_00507b20` |
| +0x5f | 走满距离就算完 |
| +0x60 | 用真实时间（`+0x68`）而不是战斗时间（`+0x50`） |
| +0x61 | yaw 起点加 / 减一圈 |
| +0x64 | 置 `FUN_004c6410()+5`（偷袭横幅 `FUN_004fd290` 等它） |
| +0x65 | 盯着目标（`FUN_0041c900` 算朝向） |
| +0x66 / +0x68 | 跟随目标：战斗位 0..10，-1 = 战场中心 |
| +0x6c / +0x74..+0x80 | 速度 / 两段加速度的起始时刻与加速度 |

「匀速」分支：起点、总长 dist、速度 = (dist − 两段加速度路程) / 时长；每帧 位置 = 起点 +
方向 × min(t·速度 + 加速度路程, dist)，角度按 t/时长 线性插；时长 0 且有位移就直接到终点；
t ≥ 时长 算完。播放器 `FUN_005061a0` 在下一帧换下一步，步数用完就停，镜头留在最后。

## 4. 顺带：时间轴任务不是镜头

笔记 combat_flow §2 把 `FUN_004fc700` / `FUN_004fc7d0` / `FUN_004fc940` 写成「建镜头任务 /
压关键帧 / 提交」，不准确：它们是通用的时间轴任务（每组最多 32 步，记开始时刻）。开场
那组的四步 `FUN_004fd290`（3 秒，偷袭横幅）、`FUN_004fce70` / `FUN_004fcfb0`（4 秒，前
3/4 透明度 0→255、后 1/4 降回去的淡入淡出）都不移镜头。

## 5. 移植端

开战播 0 号序列（偷袭没接，一律 0 号）；分出胜负后先播 3 / 10 / 8 号散场序列，打赢
时我方活着的人做 z20 并停在最后一帧 [推断]，镜头播完才散场（快进不播）。每帧把机位交给舞台相机（位置 + `look_at(位置 +
forward)`；roll 数据全是 0，不管），播完停住。「盯着目标」（`+0x65`）也做了：这一步的朝向不插值，每帧 `look_at` 目标——战斗位
0..10 取那个人现在的位置，-1（战场中心，CBStage `+0x384..+0x38c`）按原点算 [推断]。

各标志实际用在哪（按实机 flexcam.dat 统计，36 个有内容的序列）：

| 标志 | 条数 | 序列 |
|---|---|---|
| `+0x59` 匀速分支 | 178 | 0–8、10、20、51–60、70–83（绝大多数） |
| `+0x61` yaw 走短弧 | 18 | 3、8、10、13、51、56、58、60、73–75、77、79、80、83 |
| `+0x65` 盯着目标 | 31 | 6、13、52、53、56、60、72–74、77、79、80 |
| `+0x66` 跟随目标 | 0 | ——没有任何记录用，不做 |
| `+0x5b` 另一种分支 | 2 | 77、80 |
| `+0x5d` / `+0x5e` 附带动作 | 3 / 10 | 1、77、80 / 6、13 |
| `+0x64` 等横幅 | 6 | 20、53、59 |

**散场三段（3、8、10）只开 `+0x61`，不盯目标**。败的 10 号从 yaw 3.107 转到 −1.78：
不加一圈要转 280°，减一圈后只转 80°，镜头转向右边、把敌人放进画面，倒下的景天会出画
——那就是数据本来的样子（实机见过，先前一度以为是没盯目标，撤回）。

没做：另外两种移动方式（`+0x59 == 0`、`+0x5b`）、
`+0x5d`/`+0x5e` 两个动作、表里其余序列的触发、震屏（`FUN_005054f0` 的 `+0x68ffc`）。

实机（2026-09-11）：开战第一帧贴近敌人，0.8 秒后拉到 EditorCam0；比先前的 DefaultCam0
取景低、近，岩壁和树都进了画面。
