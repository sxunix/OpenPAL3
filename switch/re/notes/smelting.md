# 冶炼（SCE 146 `UIShowSmeltingMenu`）

莫子牙的炼妖壶：拿尸块配矿石炼东西。地址都是 PAL3 v1.4 未加壳
`PAL3_unpacked.exe`。

## 1. 入口

`LAB_00436a10`（opcode 146，一个 int 参数）：

```text
FUN_0044f610(3)             // 进模式 3 = 冶炼
DAT_00dba240 = 参数          // 这是个**过程号**，不是「种类」
new 等待任务 FUN_00434ca0(3) → FUN_00434c40   // 脚本挂起到模式结束
```

参数是过程号：确认那个按钮（`FUN_0047c430` 的 `param_2 == 0x403`）会
`FUN_00432170(DAT_00dba240, 0)` 把它当脚本跑。实机里只有一处用到这个命令，
Q13 的 proc 1409「莫子牙冶炼」，传的 1410 是「莫子牙聊天」——四段对白，
没有给东西的指令。

## 2. 配方表 `FUN_0047a580`

```text
FUN_0040d010(10)  → 尸块（ItemType 12）
FUN_0040d010(3)   → 矿石或尸块（ItemType 5 或 12）
for 尸块 in 尸块表:
    for 候选 in 矿石表:
        if 尸块.ore_id (物品 +0x308) == 候选.id:
            一条配方：产物 = 尸块.product_id (+0x30c)
```

两张表都是从背包按 id 升序抓的，所以配方的顺序就是背包顺序。行里记的是
尸块 id（`+0x1704`）、矿石 id（`+0x1708`）和两边的数量
（`+0x16fc` 尸块、`+0x1700` 矿石）。

`FUN_0040d010` 的分支号与物品类型：case 3 = type 5 或 12，case 10 = type 12
（同一张 switch 也管道具页和战斗道具页，见 `item_use.md` §2.1）。

## 3. 加入与撤销

- `FUN_0047aab0(行)`：两边数量各减一，**当场从背包里各扣掉一个**
  （`FUN_0040cf60`）。数量减到负数就弹提示、把这一行的两个计数清零。
- `FUN_0047adf0(行)`：撤销，数量各加一，把两样东西还回背包
  （`FUN_0040ccf0`）。
- `+0x2a778` 是已经排进队列的对数（加一/减一）。

## 4. 产物什么时候进背包

**炼够 5 秒才给**，在每帧的 `FUN_0047b3b0`（0x47b3b0）里：

```text
if (this->+0x2a774 == 0) return;              // 没在炼就跳过
if (!this->+0x2a744) { this->+0x2a740 = timeGetTime(); this->+0x2a744 = 1; }
now = timeGetTime();
if (now - this->+0x2a740 <= 0x1388) return;   // 5000 毫秒没到
this->+0x2a740 = now; this->+0x2a744 = 0;
FUN_0047b140(this, this->+0x27c34);           // 显示产物说明
FUN_0040ccf0(&this[(this->+0x27c34 + 0xe4) * 0xc]);   // 产物进背包，数量 1
…弹一句「用 X 和 Y 炼出了 Z」…
this->+0x2a775 = 1; this->+0x2a774 = 0;       // 这一炉结束
this->+0x27c34 = -1;
```

`(行 + 0xe4) * 0xc` 就是 `+0xab0 + 行*0xc` 那个三元组——`FUN_0047a580` 建表
时写的 `{产物 id, 1, 数据库指针}`，正好是 `FUN_0040ccf0` 的入参形状。

`+0x2a774`（正在冶炼）在确认那一支置 1（0x47ba36），火花特效
`FUN_0047b3b0` 的另一半（0x47b200 起）也拿它当闸。**一次确认只出一件**，
给完就把标记清掉、选中行置 −1，中间没有回到发货那一步的分支。

早先在 .text 里按 4 字节位移搜 `0x14f8` 搜不到读的地方，是因为行基址是
`esi + 行*0x31c`，代码用的是 `lea` + 小位移，立即数里根本不出现 0x14f8。
换成「找 `FUN_0040ccf0` 的全部调用点」一下就找到了（0x47b43f）。

## 5. 移植

- `shared/src/openpal3/states/smelting.rs`：`recipes(db, 背包)` 照 §2 的两重
  循环列配方。
- `scripting/sce/commands/smelting.rs`：SCE 146 的实现，冶炼期间阻塞脚本，
  关掉时跑参数里的那个过程。界面是文字浮层，不是原版那一套。
  **和原版的差别**：原版分「加入队列」（当场扣材料）和「确认」（等 5 秒出
  一件）两步，移植端并成一步——确认就扣材料，等满 §4 的 5 秒再把产物给出
  来，顺序和数量与原版一致，少的是队列页和火花特效。
