来源：`re/PAL3_unpacked.exe`（StarForce 脱壳后），Ghidra 反编译 `re/out/decompiled.c`
+ capstone 反汇编（`switch/re/x86dis.py`）。所有坐标均为 800×600 原生像素。
标注 [推断] 的条目未在代码里 100% 闭环，其余均直接读自指令。

**渲染模型见 `state_page_layout.md` 第 0 节**（贴图按 TLI 原生尺寸贴在 rect 左上角、
不拉伸；文本 rect 四边内缩 8、字号档 1 = 16px 字格、ASCII 前进 8 / 汉字 16、行距 16、
字形以 rect.y+8+16 为底边、单行 rect 高恒为 32）。
本页所有文本控件同样调 `FUN_004427a0(0)`，即 16px。
**底部工具栏与 TimeMoney 页头同道具页**（见 `item_page_layout.md` 第 6 节）。

入口：
- `FUN_0047f590(param)` —— 页面框架：页原点 (0,0)、页尺寸取 this+0x58/0x5c，
  Frame_Line、TimeMoney、金钱/时间文本、工具栏 `FUN_004826a0()`，
  以及**两个 3D CVD 节点**（见第 1 节）。末尾调 `FUN_0047ecb0()`。
- `FUN_0047ecb0` —— 页内控件 init：翻页按钮 ×2、六个分类页签、19 个文本控件。
- `FUN_0047fd90(分类, 模式)` —— 切换某个分类页签的**左/右侧摆放**与贴图。
- `FUN_0047f450` —— 把"已见过的战斗角色"按 `CombatActorType` 分进六个桶。
- `FUN_0047f390` —— 从全局"已遭遇"容器复制 id 列表到 `this+0x27154/0x27158`。
- `FUN_00482140(分类)` —— 把当前页那一只怪的字段写进 19 个文本控件。
- `FUN_00480600(msg, id, ...)` —— 消息处理：翻页按钮、工具栏跳转、开关页。
- `FUN_00478fd0(id)` —— 在 gdb 战斗角色表里线性查 id，返回**记录本身的指针**
  （表基址 `+0xa0`、步长 `0x354` = 852，与 `gdb_database.md` 完全一致）。

> **这一页没有右侧队伍牌。** 其他五页的排布函数都会用基准 rect (686,62,796,157)

## 4. 一只怪一页：内容与字段（FUN_00482140）

`FUN_00478fd0(id)` 返回的就是 **gdb `CombatActorInfo` 记录本身**，
所以下面的偏移可直接对照 `gdb_database.md`：

| 写入顺序 | 内容 | 记录偏移 | gdb 字段 |
|---|---|---|---|
| 1 | 分类名 + `"第 N 页"` | — | 语言串 `DAT_00dc433c` 等 + `%d`(当前页+1) |
| 2 | 怪物名 | +0x258 (600) | `name` |
| 3 | 精 | +0x27c | `attribute_values[0]` Hp |
| 4 | 神 | +0x284 | `attribute_values[2]` Mp |
| 5 | 水 | +0x298 | `attribute_values[7]` |
| 6 | 火 | +0x29c | `attribute_values[8]` |
| 7 | 雷 | +0x2a4 | `attribute_values[10]` |
| 8 | 风 | +0x2a0 | `attribute_values[9]` |
| 9 | 土 | +0x2a8 | `attribute_values[11]` |
| 10 | 武 | +0x288 | `attribute_values[3]` |
| 11 | 防 | +0x28c | `attribute_values[4]` |
| 12 | 速 | +0x290 | `attribute_values[5]` |
| 13 | 运 | +0x294 | `attribute_values[6]` |
| 14 | 经验 | +0x2e4 | `experience` |
| 15–18 | 四个仙术名 | +0x2f8 起 4 个 u32 | `skill_ids[0..3]` |
| 19 | 描述 | +0x006 | `description` |

- 五灵的**显示顺序是 水火雷风土**（与仙术页页签顺序一致），不是数据库数组的
  水火风雷土。第 5–9 项带语言串标签（`DAT_00dc3c3c` … `DAT_00dc403c`），
  格式 `"%s: %d"`；第 3/4/10–14 项是裸 `%d`。
- 仙术名：`FUN_00479080(skill_id)` 取仙术记录，名字在 **+0x1c**
  （gdb `SkillInfo.name`）。`skill_id == 0` 时写空串**且不推进 rect 游标** ——
  即非空技能会依次占用 `this+0x26764` 里那 4 个 rect（542, 128+28k），**向上压紧**。
- 最后 `FUN_00439230(rec+0x206, 0x32)` 用记录里的 `model_id` 换掉怪物 3D 模型。
- 该分类页数为 0 时，19 个控件全写 `DAT_00c10d38`（空串）。

[推断] 控件与字段的具体绑定（哪个 rect 显示哪一项）没有逐个闭环 ——
`FUN_004427c0` 的 `this` 被反编译丢了。按写入顺序与控件建立顺序对齐，
最合理的读法是：第 5 组（x426、五行竖排）是精/神/武/防/速/运一类的属性行，
第 4 组（y464、五个横排）是五灵数值行，第 6 组是四个仙术名（这一条由
`FUN_00445fa0(this+0x26764+k*0x10)` 确证），第 7 个是描述块，
第 1 个是竖排的分类标题。

## 5. 翻页（FUN_00480600 的 0xa00604 / 0xa00605 分支）

状态变量：

| 变量 | 含义 |
|---|---|
| `this+0x27ad8` / `0x27ad4` | 当前分类（0..5），两份互相同步 |
| `this+0x27ae0` | 当前分类内的页号（0 基） |
| `this+0x2715c + cat*4` | 该分类的页数（= 已见过的该类怪物数） |
| `this+0x27bc4` | 当前装载的翻页 CVD：1 = pgdw，2 = pgup |
| `this+0x27bc0` | 翻页方向标记（1 / 0 / −1） |

- **Pgup 0xa00604**，rect **(68,368,90,404)**，贴图基名 `JusticeBook\Pgup`，
  禁用态 `UnUp.tga`（`FUN_0043aa00` 设的第二贴图）。原生 18×34。
  页号 −1；减到 0 以下就退到上一分类，退过 0 则夹住不动。
- **Pgdw 0xa00605**，rect **(690,368,712,404)**，基名 `JusticeBook\Pgdw`，
  禁用态 `UnDw.tga`。原生 18×34。
  页号 +1；超出本分类页数就进下一分类，`cat >= 6` 时夹住不动。
- 两者都：若 `this+0x27bc4` 不是本方向，先
  `FUN_00439230("JusticeBook\CVD\pgup.CVD" 或 "pgdw.CVD", 0)` 换模型；
  然后 `SetAnimLoop(1)`、`SetTimeScale(2.0)` 放动画，并播音效 `wa016`。
  **翻页确实是 3D CVD 模型动画**，不是贴图序列。
- 关页时 `FUN_00439230(close.CVD, 0)` + `SetTimeScale(0.0)`。

工具栏跳转（同一函数的 0x3e9 分支，`FUN_004a5010(n)`）：
0xa00102→0 状态、0xa00103→3 仙术、0xa00104→2 装备、0xa00105→1 道具、
0xa00106→5 剑、0xa00108→4 阵法、0xa00109→7 系统、0xa00110→9（退出）。
按钮音效 `wa001`。`FUN_00482bb0` 按 `DAT_00de5f92` / `DAT_00de5f93` 两个全局
把阵法/剑两个按钮换成 `No…`/`Un…` 贴图（未解锁时置灰）。

## 6. 一只怪怎么才会出现在榜上

`FUN_0047f390`：

```
count = FUN_0040f030();              // 容器 size
this+0x27158 = count;
this+0x27154 = new int[count];
for i: this+0x27154[i] = FUN_0040f050(i);   // 容器 at(i)
```

`FUN_0040f030/0040f050/0040f000` 是同一个对象上的 size / at(i) / contains(id)：
对象里 `+4` 是 begin、`+8` 是 end（一个 `std::vector<int>` 式的 id 集合）。
开页时 `FUN_0047f450` 再把它按 `CombatActorType` 分成六桶，
所以**榜上只列这个集合里出现过的怪**，页数 = 该类的数量。

[未解决] 往这个集合里 push 的地方没找到（`FUN_0047f390` 里那次调用的 `this`
被反编译丢了，附近的 `FUN_0040f060/0040f0c0` 是同地址段的另一批函数，无关）。
按语义应当是每场战斗开始时把参战怪物 id 记进去。
