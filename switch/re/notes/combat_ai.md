## 1. 人格的选择规则：**按剩余血量分档**（`FUN_004f3a50`）

选人格用的**不是**怪物数据库里的任何字段，而是**当前血量占比**：

```c
char 血档(战斗位) {                       // FUN_004f3a50，0x4f3a50
    cur = 精当前(+0x24c);
    max = 精上限(+0x250);
    if (cur == max)                    return 1;   // 满血
    if (max / 2 <= cur && cur < max)   return 2;   // 半血以上
    if ((max + (max>>31 & 3)) >> 2 <= cur) return 3;   // 四分之一以上
    return (cur < 1) + 4;                          // 4 = 残血，5 = 已倒
}
```

`FUN_004d7120` 的分派（`switch (血档 − 1)`）：

| 血档 | 行为体 | 说明 |
|---|---|---|
| 1 满血 / 2 半血以上 | `FUN_004d71e0` | 常态 |
| 3 四分之一以上 | `FUN_004d7820` | |
| 4 残血 | `FUN_004d7ef0` | |
| 5 已倒 | —— | 直接返回 0 |

**"乱"（k = 0x12）会覆盖上表**：只要中了乱且血档 ≠ 5，一律走
`FUN_004d8580`（混乱行为体）。

> 也就是说**同一只怪在掉血过程中会换打法**，而不是每只怪有固定性格。
> 数据库里的 `normal_attack_mode_id` / `special_action_id` / `properties[10]`
> 都没有参与这个选择。

## 2. 共用内核 `FUN_004f4aa0(战斗位, 仙术ID)`

九个技能挑选器全部调它。它做两件事：

```c
int 技能分值(战斗位, 仙术ID) {             // 0x4f4aa0
    side = FUN_004f3bc0(战斗位);           // 0 不在场 / 1 我方 / 2 敌方
                                           // = (战斗位 > 4) + 1
    if (side == 1) {                       // 我方：得真的会用
        if (!会用(0x105, 仙术ID)) &&        // 仙术库
            !会用(0x104, 仙术ID))  return 0; // 特技库
    } else if (side == 2) {                // 怪物：得在 skill_ids[0..3] 里
        if (仙术ID 不在 skill_ids)  return 0;
    } else return 0;

    return (short)技能记录[0x250];          // = SkillInfo.attribute_impact_value[0]
}                                           //   即该技能对「精」的影响值
```

**返回值就是这条技能能改动多少精**（治疗为正、伤害为负）。整套 AI 的
打分就建立在这一个数上。

`FUN_004f6da0(cmd)` 判断"会不会用"，顺带交代了两个技能库的位置：

| cmd | 我方查哪里 | 规模 |
|---|---|---|
| `0x104` 特技 | 战斗位 `+0x2c8` | 6 条 |
| `0x105` 仙术 | 战斗位 `+0x2e8`，每行 8 条、行距 0x20，共 6 行 | 48 格 |
| 任意（怪物） | gdb `skill_ids[0..3]` | 4 条 |

（48 格的仙术库正是仙术页那 8 桶 × 6 行的同一块数据，见 `magic_page_layout.md`。）

## 3. 九个技能挑选器

九个函数是**同一套骨架**，只差"筛哪一类技能"：

```c
仙术ID 挑一个(战斗位, 要全体吗, 目标数值) {
    if (!能行动(战斗位)) return 0;
    候选 = [];
    for (技能 in 技能库(战斗位)) {                 // 我方 48 格 / 怪物 4 条
        if (技能.skill_type != T)          continue;
        if (技能.target_range_type != (要全体吗 ? A : B)) continue;
        if (!FUN_004f7500(技能))            continue;   // 会用 + 付得起
        候选.push(技能);
    }
    // 取「分值绝对值」与「目标数值绝对值」相差最小的那条
    return argmin_技能 | |技能分值(战斗位, 技能)| − |目标数值| |;
}
```

**打分方式是"最接近"，不是"最大"** —— 这是整套 AI 最有意思的地方：
治疗不会过量、攻击也倾向于刚好打死。

| 函数 | 技能库 | `skill_type` | 全体(=1) | 单体(=0) | 用途 |
|---|---|---|---|---|---|
| `FUN_004f4da0` | 仙术 | 3 恢复 | 2 我方全体 | 1 我方单体 | 治疗 |
| `FUN_004f5070` | 仙术 | 2 伤害 | 4 敌方全体 | 3 敌方单体 | 攻击 |
| `FUN_004f5330` | 仙术 | 1 辅助 | 2 我方全体 | 1 我方单体 | 增益 |
| `FUN_004f5d00` | 仙术 | 非 0 | 2 | 1 | **复活**（见下） |
| `FUN_004f6370` | 仙术 | 非 0 | 2 | 1 | **解状态**（见下） |
| `FUN_004f55d0` | 特技 | 0 | 2 | 1 | 我方向特技 |
| `FUN_004f57a0` | 特技 | 0 | 4 | 3 | 敌方向特技 |
| `FUN_004f6000` | 特技 | 0 | 2 | 1 | 同 55d0 [未解决：差异] |
| `FUN_004f6690` | 特技 | 0 | 2 | 1 | 同上 [未解决：差异] |

后两组额外加一道状态谓词：

- `FUN_004f6cd0(cmd)`：技能 `+0x29a == 2`。`0x29a` 落在
  `SkillInfo.combat_state_impact_types`（i16[31] @ 618）的第 **24** 格，
  值 2 = `Remove` → **"能解除死亡"**，即复活术。`FUN_004f5d00` 用它。
- `FUN_004f6d30(cmd, k)`：技能 `+0x268 + k*2 == 2`，k 是 **1 基**的状态号
  （即 `k = 枚举 + 1`，与状态标记数组同一套编号）→ **"能解除状态 k"**。
  `FUN_004f6370` 用它，要解哪个状态由调用方传入。

> 道具分支（cmd `0x106`）读 `物品 +0x2ba + k*2` / `+0x2ec`。按 k=25（死亡）
> 算得 `0x2ec`，反推数组基址 0x2bc。**这个 [存疑] 已经消掉**：0x2bc 不是
> `combat_state_impact_types`（那个在 0x29c，是 u8[31]），而是
> `combat_state_impact_value`——i16[31]，按 short 步长读正是对的。值的语义
> 是 1 加 / 2 解，见 `item_use.md`。

## 4. 具体动作

行为体调用的是"动作"函数，每个动作 = 一个挑选器 + 一次排程，
成功返回 1。**全部以 `!乱(0x12) && !狂(0x13)` 为前置**。

| 动作 | 用的挑选器 | 送进去的"目标数值" | 含义 |
|---|---|---|---|
| `FUN_004d9740` | ——（无技能） | —— | **普攻**，动作码 `0x103` |
| `FUN_004d9920` | `FUN_004f4da0(位, 0, …)` | 目标的 **精上限 − 精当前** | 单体治疗：**按缺多少血挑药** |
| `FUN_004d9a70` | `FUN_004f4da0(位, 1, …)` | 同上（全队口径） | 全体治疗 |
| `FUN_004d9ba0` | `FUN_004f5070(位, 0, …)` | 目标的**当前精** | 单体攻击：**按还剩多少血挑术** |
| `FUN_004d9d00` | `FUN_004f5070(位, 1, …)` | —— | 全体攻击 |
| `FUN_004d9e20` | `FUN_004f5330(位, 0)` | —— | 单体增益 |
| `FUN_004daa40` | `FUN_004f5d00(位, 0, 精上限)` | 自身精上限 | 复活 |
| `FUN_004dadd0` | `FUN_004f6370(位, k, 0)` | 状态号来自 `param_3+0xc` | 解状态 |

选中后统一走 `FUN_00515b20(排程入口, …, cmd)` 排进行动队列，
`cmd[0]` 是动作码、`cmd[2]` 施术者、`cmd[3]` 目标。

**普攻的额外规则**（`FUN_004d9740`，0x4d9740）：

```c
if (目标 有 k=0x17「隐形」)  return 0;                  // 绝不打
if (目标 有 k=0x15「避」 且 有 k=0x14「镜」) {
    if (施术者是我方 0..4)   return 0;                  // 我方绝不打
    if (rand15() % 1024 < 0x2cd)  return 0;             // 怪物 ~70% 放弃
}                                                        // 即 ~30% 硬上
```

## 5. 行为体的结构：优先级阶梯 + 随机闸 + 用量计数

以 `FUN_004d71e0`（满血/半血常态）为例，`FUN_004d7820` / `FUN_004d7ef0` /
`FUN_004d8580` / `FUN_004d8760` / `FUN_004d8af0` 都是同一形状：

### 5.1 自己的随机数

AI 用**另一颗种子** `DAT_005dfdec`，算法与战斗主随机数相同：

```c
DAT_017ad310 += 1;                                       // 抽取计数器
DAT_005dfdec = DAT_005dfdec * 0x343fd + 0x269ec3;
r = (DAT_005dfdec >> 16) & 0x7fff;
```

### 5.2 先随机挑一个"关注对象"

```c
for (位 = 0; 位 < 11; 位++)
    if (rand15() % 3 == 1 && 在场(位)) break;            // 命中即停
if (位 == 10) 位 = 0;
else if (位 > 10) return 0;                              // 扫空了就不行动
```

即**每个位有 1/3 概率被选中**，从 0 号位起第一个命中的即为关注对象。

### 5.3 阶梯（2026-09-13 逐行逆完）

`FUN_004d7120`：`FUN_004f3a50` 血档 1、2 → `FUN_004d71e0`，3 → `FUN_004d7820`，
4 → `FUN_004d7ef0`，5 不行动；中了乱转 `FUN_004d8580`（血档 5 除外）。三个阶梯都用
战斗那一个发生器 `DAT_005dfdec`。

起点：从 0 号位往后每位掷 `rand % 3 == 1` 且在场，第一个命中的；**落在 10 号位时改成 0**
（`local_8 == 10 → 0`）；扫空了返回 0（下一帧再试）。然后从起点往后（不回绕）逐位 t，
t 要在场、站着、`+0x247 != 1`：

**闸**（值 < 100 才放行）。`FUN_004d7100` 每帧先 `FUN_004d94f0` 重算、再 `FUN_004d93d0`
把「登记过的行动还没演完」的闸锁成 100。每道闸是 {值, 任务句柄, 锁} 16 字节。
**撤回「用量计数 / 这招用过几次」的 [推断]**——没有任何地方累加。

| 闸 | 地址 | `FUN_004d94f0` 写的值 |
|---|---|---|
| 单体治疗（按 t） | `+0x640 + t*0xa0` | 血档 < 3：100；否则 0x28；血档 4：10 |
| 复活（按 t） | `+0x650 + t*0xa0` | 倒下 0，站着 100 |
| 解状态（按 t） | `+0x670 + t*0xa0` | `FUN_004f3c70`（有要解的状态）→ 0x32 并记下 `FUN_004f3dc0`；否则 100 |
| 怪物那边全体治疗 | `+0xd20` | 位 5..10 在场且血档 > 2 的个数 v：<2 → 110，2 → 70，3 → 50，≥4 → 30 |
| 我方全体攻击 | `+0xe00` | 位 0..4 同样算：<2 → 100，2 → 60，3 → 40，≥4 → 20 |
| 普攻 / 单体仙术攻击 | `+0x690` / `+0x6a0` / `+0x6b0` / `+0x6c0` | 不写，恒 0 |

（`+0xd60 = 100 − v`、`+0xdc0 = v + 10` 给托管那一套用。）

**阶梯一 `FUN_004d71e0`（血档 1、2）**：
1. 重楼变身（id 0x2e3）神满 → 放 0x1e1d（`FUN_004db160`，不看付不付得起，放特效组 0x22f）。
2. t 是我方 → 普攻；t 是自己这边 → 狂两成、乱两成（`rand % 10 > 7`）才普攻。
3. 全体治疗（`+0xd20`）。
4. t 是自己这边：单体治疗（闸）；解状态（闸 + 50%）。
5. `+0xe00`：37%（0x17b）全体攻击；道具那一支 `FUN_004014f0` **恒返回 0**（boss 旗的怪
   还会先掷一次 0x133）。
6. t 是我方：15%（0x9a）→ 全体攻击、单体仙术攻击；t 是自己这边：30% → 单体治疗（闸）、
   再 30% → `FUN_004d9e20`（辅助类单体仙术，`FUN_004f5330` 在付得起的里随机挑）。
7. 同第 2 步再来一次普攻。

**阶梯二 `FUN_004d7820`（血档 3）**：第 2 步同上；全体治疗；t 是自己时单体治疗；
自己这边的单体治疗、解状态；`+0xe00` 25%（0x100）全体攻击；然后 t 是我方：
70%（0x2cd）单体仙术攻击 → 70% 普攻 → 单体仙术攻击 → 25% 单体仙术攻击 →
10%（0x66）全体攻击、单体仙术攻击 → 普攻；t 是自己这边：狂两成才普攻。

**阶梯三 `FUN_004d7ef0`（血档 4）**：同阶梯二，只是开头对自己这边只看狂，t 是自己时
单体治疗不成再试全体治疗。

- 动作函数就是托管那二十个（`FUN_004d9740` 普攻 … `FUN_004dadd0` 解状态），怪物的六个
  开关开局全开（`FUN_004f8bb0`）。
- `FUN_004d9740` 普攻还要过 `FUN_004f0210`：怪物没有竖列打法时，打不到站在后位
  （`FUN_004fa6a0(战场五灵)`）的我方，只要盘心有人站着。
- 怪物的挑选器都扫 `skill_ids[0..4]`（`+0x2f8..+0x308`），boss 那招也在里面。

移植（2026-09-13）：`ai::monster` 三个阶梯，闸当场算（移植端一次只有一个行动在出手段，
锁不会生效）；原来那个简化的 `ai::choose` 删掉。没搬：`+0x247`、boss 旗的那一掷、0x22f 特效。

### 6.5 两个行为体

**`FUN_004d8760`（谨慎）**，从 0 号位往后：
1. 我方倒下的：特技复活 `4dab70` → 仙术复活 `4daa40` → 道具复活 `4daca0`；
2. 站着的（任何一方）且群补条件成立：仙术全补 `4d9a70` → 特技全体 `4da0a0` → 道具全补 `4da640`；
3. 我方血档 ≥ 3：仙术单补 `4d9920` → 特技单体 `4d9f50` → 道具单补 `4da4f0`；
4. 我方有毛病且 50%：仙术解 `4dadd0` → 特技解 `4daf00` → 道具解 `4db030`。

**`FUN_004d8af0`（进攻）**，从 0 号位往后找站着的：先全体（仙术 `4d9d00` → 特技 `4da350` →
道具 `4da900`）；是敌方就普攻 `4d9740` → 仙术 `4d9ba0` → 特技 `4da1d0` → 道具 `4da770`，
**同一套连试两遍**（原版两段一样的阶梯）；我方位只有自己中了 0x13 才有 2/10 机会被当目标。

中了乱（0x12）时两个行为体各有一支纯随机分派（`rand % 0x40` 选 9 种 / `rand % 11`），移植没搬。

## 6.8 回合开头的状态分支（主调度 `LAB_00513840`，0x513925 起）

```text
眠 0x11 或 定 0x0e              → 0x513ab8：FUN_004db750(k,0,0,0)，这一回合跳过
+0x345（托管）或 乱 0x12 或 狂 0x13 → 0x513a36：战斗对白 → FUN_004d86d0 → 没排出来再 FUN_004d7120
其余：+0x36d / +0x36c 两种自动方式（FUN_004d8f20 / FUN_004d9130），再其余我方出控制盘
```

- 乱：`FUN_004d7120` 查到 0x12 走 `FUN_004d8580`——`rand % 11` 挑在场、不是自己的位
  （两边都可能，最多 0x200 次），`rand & 7`：1 全体治疗、2 单体治疗、4 全体攻击、
  5 单体攻击，其余普攻。所以乱了会打自己人。这是**怪物**中乱的走法。
- 我方中乱走 `FUN_004d86d0`，两个行为体各有一支随机分派：
  - `FUN_004d8760`（谨慎时先走）：每个在场的位掷一次 `rand & 0x3f`，落在 0..8 才做，
    对这个位（哪一边都行）依次是 特技复活 / 仙术复活 / 道具复活 / 仙术群补 / 特技群补 /
    道具群补 / 仙术单补 / 特技单补 / 道具单补（跳表 0x4d89d8）；
  - `FUN_004d8af0`（0x4d8d41）：`rand % 11` 抽位，要「在场、`+0x370 != 0`、不是自己」才停——
    `+0x370`（战斗位 `+0x598`）怪物初始化清零、我方从不写，恒为 0，所以总是**抽满 0x400 次**、
    用最后一次抽到的（可能是自己）；再 `rand % 11`：0 仙术群攻、1 特技群攻、2 道具群攻、
    3/10 普攻、4/7 仙术单攻、5/8 特技单攻、6/9 道具单攻。
  移植端照搬（`Delegate::support` / `Delegate::offense_confused`）。
- 狂：动作闸里 0x13 只放行普攻（`FUN_004d9740`），其余一律拒；`FUN_004d8af0` 让自己人
  以 2/10 的机会也成为目标。
- 状态编号见 `combat_hud.md` §12（k = 枚举 + 1：0xe 定、0x11 眠、0x12 乱、0x13 狂）。
- 移植（2026-09-13）：眠 / 定跳过；我方乱 / 狂 / 托管走 `ai::delegate`；怪物乱走
  `ai::confused`（`FUN_004d8580`）。**之前移植把乱当「这一回合空过」是看错了编号（0x11 是
  眠不是乱），已改。**
- **挑不出行动 = 下一帧再试**：我方（0x513a36 之后到 0x513ac7）、怪物（0x513ab1 之后到
  0x513ac7）都不清行动条。移植端 `Battle` 拆成 `advance` / `due(skip)`，`CombatSession::tick`
  一帧里没挑出行动的人进 `skip`、接着看下一个就绪的人，下一帧再试；另外有人还在出手段
  （`pending` 没结算）时，就绪的人也这样等——调度器一次只排一个行动任务。
- 0x513925 起那一串（眠 / 定 / `+0x345` / 乱 / 狂）只对我方：前面 `FUN_004ed040`
  （`+0x243`）为 1 才进来。怪物走 0x513a48 那条：眠 / 定跳过、`+0x36f` 跳过，其余一律
  `FUN_004d7120`（乱在里面转 `FUN_004d8580`）。所以怪物开局托管开关全是 1
  （`FUN_004f8bb0`）并不会让它们走托管——之前的 `[未核]` 到此结案，移植端怪物本来就是这样。
- 托管挑不出东西：原版下一帧重试，移植端照做（见上一条）。
