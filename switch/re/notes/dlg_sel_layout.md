# PAL3.exe v1.4 — 对话选择框（SCE 65）逆向布局笔记

来源：`re/PAL3_unpacked.exe`（StarForce 脱壳后），Ghidra 反编译 `re/out/decompiled.c`
+ capstone 反汇编。所有坐标均为 800×600 原生像素。标注 [推断] 的条目未在代码里 100% 闭环。
实现在 `yaobow/shared/src/scripting/sce/commands/dlg_sel.rs`。

## 对象与建立

选择框是场景界面里一个常驻对象，实例在 0xdba260。场景界面初始化（`FUN_0044f130` 那一串，和
`ui\dlg\bigbk.tga` 大对话框、`ui\dlg\headbk.tga` 头像框同一处）里：

```text
FUN_00451980(0x3f3, &(0, 0, 414, 125), 父窗口, "ui\dlg\selbk.tga")
```

`FUN_00451980`：
- `FUN_00445b90`：窗口基类初始化（id、rect、父窗口）；
- `FUN_004450a0(0, rect, this, "ui\flex\note")`：九宫格外框，按 `"%s%d.tga"` 贴 `note0..8.tga`（各 32×32）；
- 列表控件：名字 `_seldlg`（`FUN_0043e560`），偏移 (8, 0)；
- 文字色：`ColorQuadFmt` 为 0 取 0xfafaff，否则取 0xfffafa，都接近白；
- 高亮条 `ui\scene\SelPic.tga`（128×16）；
- 行高 20（`this[300] = 0x14`，`FUN_0043f640(0x14)`）；
- 初始隐藏。

`selbk.tga`（512×128）作为第四个参数传进来，但 `FUN_00451980` 里没看到用它 [推断：是给别的版本留的背景，或被基类吞掉]。

虚表 0x56b178：0 号槽 0x451b40（显示 / 排版）、1 号槽 0x451c10（绘制）、6 号槽 0x451aa0（事件）。

## SCE 65（`LAB_00436940`）

1. `FUN_00451ad0`：清空列表（`FUN_0043f360`），`+0x54`（最长一项的字节数）置 −1；
2. 每一项 `FUN_00451af0(文本, 序号)`：加进列表（`FUN_0043e5c0` / `FUN_0043f6a0`），`FUN_0043f5b0(-1)` 不选中任何一项；`+0x54 = max(+0x54, strlen)`；
3. 调虚表 0 号槽显示。

## 排版（0x451b40）

- 框高 = (项数 + 2) × 20；框宽 = (最长字节数 + 6) × 10（GBK，一个汉字两字节，相当于每字 20 像素）；
- 外框（`+0x510`）与框同尺寸；
- 列表（`+0x58`）尺寸是框宽、框高各减 20，`FUN_00445db0(this)` 居中在框里，即四边各内缩 10；
- 框本身 `FUN_00445db0(0)` 居中在屏幕上（父窗口为空时用屏幕尺寸 `DAT_00bfd6d0 / d4`）。

`FUN_00445db0(父)`：`x = (父宽 − 自宽)/2 + 父左`，`y` 同理。`FUN_00445fa0`：设 rect 后给自己发 0x3fe 事件。

## 选中

列表选中时发 0x3ef 事件；6 号槽 0x451aa0 把序号存进 `+0x50`，序号不是 −1 就调 0 号槽收起框。
SCE 66 取的就是 `+0x50`。

## 绘制（0x451c10）

可见时画外框子控件 `+0x510`；状态 `+0x5bc == 2` 时再画列表 `+0x58`。列表控件（构造 `FUN_0043f7f0`，
虚表 0x56ad64）的逐项绘制与输入没有逐字段读完。

## 移植端的取舍 [推断]

- 九宫格排法按对话框那套（0 左上、1 左下、2 右下、3 右上、4 左、5 下、6 右、7 上、8 中）；
- 行内文字左缩 8 像素、竖直居中（按已确认的界面文字模型：rect 内缩 8、16 像素字格）；
- 原版开场不高亮任何一项、靠鼠标悬停选择；移植端开场先高亮第一项，并加上十字键 / 方向键上下、
  A / 空格确认——Switch 上没有数字键，原先只认数字键 1..9、0 的实现在真机上选不了剧情分支。
  鼠标（触屏）悬停高亮、点击选中，数字键直选保留。

## 高亮条（2026-10-11 跟上原版）

列表控件画行的那段 `0x43e8e0`：行循环 `0x43e94b..0x43ea67` 只画文字，出口之后
才算条的矩形（`0x43eab4`）并画（`0x43eb66` 的 `FUN_00540c60(x0,y0,x1,y1,&色,&图)`），
所以**条压在文字上面**。条 = 贴图 `[+0x480]`（`ui\scene\SelPic.tga`）× 颜色
`[+0x498..0x49b]`，这四个字节在列表构造 `0x43e045`..`0x43e062` 写死
(0xa8, 0xa8, 0xa8, α=0xc8)，全 exe 只此一处写。行文字的颜色和选中与否无关
（`0x43e9bf` / `0x43e9d3` 两条路都不看选中）。

**条是「加」上去的**：`FUN_00540c60` 用的效果 `DAT_01895058` =
`gfxscript\ui_tex_color.gbf`，`SrcBlend = SRCALPHA; DestBlend = ONE`
（见 `ui_render_states.md`）。`SelPic.tga` 是 128×16、32 位带 alpha 的一条
**橙色光带**：RGB 基本是 (252,200,65) 不变，alpha 从两头的 0 鼓到文件第 7 行的
193，横向两头也收；乘上色之后加上去那一份峰值约 (99,83,28)。所以选中行是被暖光
提亮一圈，字照样看得见。

移植端原先是先条后字、不染色；2026-10-11 改成照原版，条在文字之后画。imgui 后端
只有一种混合状态，所以在装贴图时就把该加的那份折成 alpha
（`openpal3::ui_tex::bake_additive`，误差 `dst·A`，A 峰值 99/255）。

## 验证

调试口 `dlg_sel ["是", "否", "我再想想"]` 弹框：框居中、蓝色 note 外框、高亮条在第一项；按下移到
「否」；空格确认后框收起。框下方留一行空白，是 (项数 + 2) × 20 的公式本身。
（没有实机画面可比对，只能说画法和原版一致。）
