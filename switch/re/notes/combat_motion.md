## 2. 两套名字：`+0x243`

舞台初始化 0x509843：`FUN_004ed040(slot)`（战斗位 `+0x243`）非零写 0x20（z04），
否则写 0x32（z1）。敌人上场 `FUN_004f8bb0` 先 `rep stosd` 清零整个战斗位（eax=0），

从冒险角色记录整块拷来。`combat_flow.md` 里原先把它记作「已行动完毕 / 退场」，
那是推断，已经撤回。`FUN_004db7a0` 选下一个出手者时会跳过 `+0x243` 非零的人，
这一处的用意还没查。

## 4. 移植端怎么接（时序是自己定的）

规则层不管动画，舞台每帧对比战斗位的状态（血、是否活着、防御、睡着、出手段里登记的
行动）决定换什么，纯函数是 `motion::react`：

- 出手段结束（结算那一刻）：攻击 → z01/g，仙术 → z06/x1，道具按目标阵营分 z11/z12；
- 进出手段：仙术摆 z061 循环；逃跑播 z19 循环；
- 掉血：z05/b，防御中是 z142；
- 开始防御 z14，之后歇着时循环 z141；睡着循环 z16；
- 倒下：我方 z18 播完停住；怪物没有倒地动作，播一下 b，0.6 秒后隐藏 [推断]。

- 回避 z15（2026-09-13）：普攻结算 `FUN_004f0a10` 里「`local_6` 为假且伤害 < 0」才落血，

## 6. 歇着的动作：`FUN_0050bbd0`

任务表空了时 `FUN_0050b430` 用 `FUN_0050bbd0` 的返回值当动作编号：

```
不在场：位 < 5 → 0x20（z04），否则 0x32
+0x243 == 0（怪物那套）   → 0x32  z1
状况 == 5（倒下）          → 0x2f  z18
+0x19a4 == 4（仙术预备中） → 0x22  z061
战斗位 +0x474（防御）      → 0x2a  z141（先 FUN_0050aa60(0.25)）
状态 0x11（睡）或 0x0e（封）→ 0x2d  z16
状况 == 4                  → 0x2e  z17
否则                       → 0x20  z04
```

`FUN_004ee870(slot)` 返回的是战斗位 `+0x228`，所以这里的 `+0x24c` 落在战斗位
`+0x474`，就是防御标志。状况 `FUN_004f3a50`：精 == 上限 → 1；≥ 上限/2 → 2；
≥ 上限/4 → 3；< 1 → 5；其余 4（**濒死 = 不到四分之一**）。

## 7. 走位：`FUN_0050da90`

由 `FUN_00500550`（一次攻击的编排）在 0x5008eb 经 `FUN_0050ad30` 登记，参数一是目标、
参数二是自己（任务项 +0x10 / +0x14，取整后当战斗位号）：

- 终点 = 目标位置 + 朝自己的单位向量 × 32，再朝自己 × 10 → **停在离目标 42**；
- 速度 = 单位方向 × **480**，每帧乘帧时长；动作 0x1f（z03；怪物用 52 = z3）；
- 离终点 < 4 就对齐到终点、任务完成；朝向和出发时差到 90° 以上（走过头）也算到；
- 自己中途不在场（`FUN_004ed010` 假）直接结束。

初始朝向（`FUN_005096d0`）：我方 45°（0x42340000），怪物那套 −135°，偷袭（+0x218/
+0x219）再加 180°。两种量角方式都落在 (+x,+z) 对角线上，与 `[RolePos]` 我方重心→
敌方重心的方向（42°~48°）一致，所以移植端直接 `look_at(位置 + (±1,±1))`。

回程的任务没单独逆，按同样的 480 走回站位 **[推断]**。

## 9. 出手的时序（撤回 §8 那条「到了跟前等 1.5 秒」）

原版一次行动的顺序（行动任务 `FUN_00514870`，笔记 combat_flow §9.2.1 记了前半）：

1. 进出手段：`FUN_004db730`（phase = 1），并 `FUN_0050a8e0(actor, 4)` 写舞台角色
   `+0x19a4 = 4` → `FUN_0050bbd0` 让它歇着时摆 **z061**。不分行动种类。
2. 每帧 0x514a2a 查 `FUN_004db6c0`（出手条满）。满了才把任务换成 **0x514ae0**
   （`FUN_00515b20`）。
3. 0x514ae0：`FUN_004db920(k, 1)` 冻结**出手者自己**的行动条（+0x2f，dt 记 0），
   按行动种类用 `FUN_004fc7d0` 排一串步骤（都是 `FUN_004fe550` 开头、`FUN_004fe600`
   收尾），走位、出手、结算都是步骤。步骤全部完成后 `FUN_004fc8f0` 清理、解冻。
   另一个编排入口 0x514220 还会 `FUN_004db910(1)` 让**全场**停住（`+0x1c5`，
   `FUN_004db5c0` 里全体 dt 记 0），完成后 `FUN_004db910(0)`；0x514ae0 没有这一步。
4. 主调度 `LAB_00513840` 对每个人要求舞台角色任务表空（`FUN_0050a6f0`）才会让他
   开始下一次行动。

步骤表：`FUN_004fc7d0(组, 步骤函数, …, 向量参数, 时长参数, …)`，每项 0x50 字节、最多
32 项，记开始时刻；步骤函数（如道具编排 `FUN_00500550`）按「现在 − 开始」对照
数据表里的几个时间点依次放特效、最后 `FUN_004ef8b0` 结算。

**移植端**：`CombatSession::stage_driven` 打开时，出手条满先不结算，记进
`staging`；舞台（`combat.rs::drive_staging`）演：攻击走过去（§7）→ 出手 → 隔
`HIT_DELAY` = 0.3 秒 [推断] 调 `strike()` 结算 → 走回站位 → `release()`。仙术、道具
原地出手。两处简化：

- 演出期间**整个时钟停住**（原版 0x514ae0 只冻结出手者，别人照走）——移植端规则层
  同时只挂得住一个行动。
- 结算时刻用固定的 0.3 秒，没读攻击编排那一格的时间点。

实机（2026-09-11）隔 0.25 秒截 20 帧：景天原地摆 z061 约 1.75 秒 → 跑出去 → 到跟前
出手 → 对方挨打 → 走回站位。

## 普攻的结算时刻（2026-09-13 逆完，撤回 HIT_DELAY 的 [推断]）

- 攻击步骤 `FUN_004fe540` 用 `FUN_0050ad30` 在舞台角色上挂任务，回调是 `0x50e550`（`ret 4`，一个参数）。
  舞台角色开场 `FUN_005092b0` 存几个名字的 CRC32：`+0x19f4` over、`+0x19f8` work、`+0x19fc` work1、
  之后 pause / store / flyup / flydown——正是 MV3 `action_desc` 里标记的名字。
- 回调：参数等于 work 或 work1 才往下走；放打击音效（景天 wd023/wd025、雪见 wd028、龙葵 wd030/wd024、
  其余 wd026/027/029）；怪物按 gdb `+0x310`（`properties[0]`）0x79..0x86 放特效组 0x144..0x14f
  和 `wd%03d`；然后 `FUN_004ef8b0` 结算：
  - 敌方（位 5..10）只在 work；
  - 龙葵（2 号位）武器类型 5 时 work 不算，每个标记结算武器 `combo_count`（`+0x2fc`）次；
  - 景天另记魔剑蓄能（走不到）；其余我方每个标记一次。
- 实测（临时测试读包里的 MV3，tick ÷ 4580）：101 z01 work 0.664 s；102 z01 work 0.664 s + work1 1.083 s；
  104 z01 work 0.699 s + work1 1.048 s；怪物 g：301 0.105 s、305 0.978 s、332 0.384 s、B01 0.140 s。
  所以动作里有 work1 的人普攻打两下，每下都是完整的 `FUN_004f0a10`。
- 移植：`motion::attack_hits`、`StageActor::attack_hits`（开场读攻击动作 MV3）、`CombatSession::attack_hit`；
  `HIT_DELAY` 只在没标记时兜底。没搬：打击音效、怪物的打击特效。
