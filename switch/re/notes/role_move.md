# 脚本驱动的角色移动（SCE 20 / 214）

两条命令，同一套实现：

| opcode | handler | 名字 | 参数 |
|---|---|---|---|
| 20 | `00434f90` | `ActorPathToCommand` | int int int int |
| 214 | `00435010` | `ActorMoveToCommand` | int int int int |

参数是 `角色号, tile x, tile y, 方式`。两者只差一句：20 会额外把
`+0x5b4` 清零，然后 20 走 `FUN_004132b0`（寻路）、214 走 `FUN_00412a90`
（直线）。**第四个参数两者完全一样**，都过 `FUN_00434f60`。

地址都是 PAL3 v1.4 未加壳 `PAL3_unpacked.exe`。

## 1. 第四个参数是「怎么走」

```text
FUN_00434f60(param):
    param == 1 → 2
    param == 2 → 3
    其余（含 0） → 1
```

这个内部值存进角色的 `+0x504`（`FUN_00412b60`：距离 < 12 就不动，否则
`+0x4f4 = 4` 进移动状态，目标存 `+0x540..`）。

`FUN_00412710` 拿 `+0x504` 分两件事——挑动作、挑速度。

### 动作（`FUN_00412940` → `FUN_004126d0`）

```text
FUN_004126d0(内部值, 角色类型 +0xad):
    角色类型 ∈ {0,1,2,4} 且 内部值 != 0:
        内部值 == 1 → 0x34
        内部值 == 2 → 0x3a
    否则 → 0x32
```

**但 `FUN_004126d0` 不是唯一的路**。`FUN_00412940` 一开头就分岔：

```text
if (+0xae == '1') { FUN_00412a14(内部值); return; }   // 直接当动作号播，倍速 1.0
iVar1 = FUN_004126d0(内部值, +0xad);                  // 否则才映射
```

动作名表 `(&PTR_DAT_00570904)[id]` 前几项：

| id | 名字 | | id | 名字 |
|---|---|---|---|---|
| 0 | `c01` | | 0x32 (50) | `z1` |
| 1 | `c02` | | 0x34 (52) | `z3` |
| 2 | `c03` | | 0x3a (58) | `z3` |
| 3 | `c15` | | | |

于是两套角色的表现不一样：

- **`+0xae == '1'`（主角那一类，有完整 `c` 系列）**：内部值 1/2/3 直接落在
  `c02`（走）/ `c03`（跑）/ `c15` 上，**各有各的动画**，`FUN_00412a14`
  末尾把倍速写死 1.0。
- **其余角色（只有 `z` 系列）**：`FUN_004126d0` 只会返回
  `0x32`/`0x34`/`0x3a`，走和跑落到**同一条 `z3`**，只能靠倍速区分：

  ```text
  FUN_00412940 末尾：
      if (+0x504 != 2) FUN_00536d00(1.0);
      else             FUN_00536d00(2.4);      // 0x4019999a
  ```

（这一节先前只写了 z 系列那一半，说「走和跑播同一条动画」——对主角类
不成立，订正。移植端 `RoleController` 的 `walk()` 挑 `c02`、`run()` 挑
`c03`，正好就是 c 系列的行为。）

### 速度（`FUN_00412710` 的 `switch (+0x504)`）

```text
case 0/5/7 → 速度 0（不动）
case 2     → +0x508 = PRunSpeed;  +0x50c = RunForce
case 1/3   → +0x50c = WalkForce
             角色类型 +0xad == -1（主角） → +0x508 = PWalkSpeed
             +0xad == 2（怪物）           → 按 +0x58c 的 +0x2f4 取
                                            AttackSpeedS / M / L
             其余 NPC                     → 角色自带的 +0x1fc，为 0 才取
                                            WalkSpeed
```

**跑那一支无条件用主角的跑速**，脚本让 NPC 跑也一样。

### 汇总

| 脚本第四参数 | 内部值 | 动作 | 动画倍速 | 速度 |
|---|---|---|---|---|
| 0（和其他值） | 1 | c 系列 `c02` / z 系列 `z3` | 1.0 | 主角 `PWalkSpeed` / NPC 自带或 `WalkSpeed` |
| 1 | 2 | c 系列 `c03` / z 系列 `z3` | c 系列 1.0，z 系列 **2.4** | `PRunSpeed` |
| 2 | 3 | c 系列 `c15` / z 系列 `z1` | 1.0 | 同上一行 |

参数 2 是「保持站立姿势被挪过去」，实机看着就是倒退或被拖。

## 2. 速度常数从哪来

不在 exe 里。`FUN_0041efa0` 启动时读 **`datascript\scene.txt`**：

```text
FUN_004318b0("datascript\scene.txt")
FUN_004319f0("role")                       // 找 role 节
循环：读一个词，和名字表比对（从 0x58b37c "TalkRange" 起，步长 0x14）
      命中 → 读下一个词转 float → (&DAT_0058b378)[i * 5] = 值
FUN_004319f0("monster")                    // 再读 monster 节
```

`(&DAT_0058b378)[i*5]` 是 float 数组，`i*5` 个 float = `i*0x14` 字节。
名字表从 0x58b37c 起、值数组从 0x58b378 起——**每条记录是
`[值 4 字节][名字 16 字节]`，值在名字前面**。这一点定下来之后，代码里那些
`DAT_0058b3xx` 才对得上语义：

| 代码里的 | 名字在 | 是哪一项 |
|---|---|---|
| `DAT_0058b328` | 0x58b32c | AttackSpeedS |
| `DAT_0058b33c` | 0x58b340 | AttackSpeedM |
| `DAT_0058b350` | 0x58b354 | AttackSpeedL |
| `DAT_0058b38c` | 0x58b390 | **WalkSpeed** |
| `DAT_0058b3b4` | 0x58b3b8 | **WalkForce** |
| `DAT_0058b3c8` | 0x58b3cc | **RunForce** |
| `DAT_0058b3dc` | 0x58b3e0 | **PWalkSpeed** |
| `DAT_0058b3f0` | 0x58b3f4 | **PRunSpeed** |

（先按「值在名字后 +0x10」推过一版，那样走路速度会取到 `TalkRange`、跑
会取到 `PWalkSpeed`，语义讲不通；`FUN_0041efa0` 里两个基址差 4 定死了是
前面。）

出厂的 `role` 一节，连原版的注释一起：

```text
TalkRange    40
WalkSpeed    80     ;NPC走的速度
RunSpeed     180    ;NPC跑的速度
WalkForce    800    ;NPC走的加速度
RunForce     1200   ;NPC跑的加速度
PWalkSpeed   100    ;主角走的速度
PRunSpeed    200    ;主角跑的速度
JumpHeight   64     ;跳高
JumpDist     160    ;跳远
GForce       392    ;重力加速度,9.8*40
```

`monster` 一节另有 `FreeRange*` / `FreeSpeed*` / `FindFov` /
`FindRadius*` / `AttackSpeed*` / `AttackRange`，是怪物 AI 用的。

## 3. 最小移动距离

`FUN_00412b60` 一进来先量一次距离：

```text
fVar1 = gbVec3D::Length(目标 − 当前);
if (fVar1 < 12.0) { +0x4f4 = 0; return; }    // 连移动状态都不进
+0x4f4 = 4;                                   // 否则才开始走
```

**不到 12 个世界单位就当已经到了**，一步都不迈，也不播走路动作。

## 4. 队伍散开与合并（SCE 25 / 26 / 211 / 212）

四条命令都是「**先摆起点、再走到终点、脚本等走完**」——每个成员都挂一个
`FUN_00434c40` 等待任务，走完才继续。

| opcode | handler | 起点 | 终点 | 走法 |
|---|---|---|---|---|
| 25 玩家队伍散开 | `FUN_0040de10(1)` | 主角 + 局部 −Z × 12 | 主角 + 表 × 1 | 走 |
| 26 玩家队伍合并 | `FUN_0040e0a0(1)` | 原地 | 主角位置 | 走 |
| 211 进情节关散开 | `FUN_0040e110(1)` | 主角 + 局部 −Z × 12 | 主角 + 表 × (−3) | 走 |
| 212 出情节关合并 | `FUN_0040e3c0(1)` | **瞬移**到 主角 + 表 × 2 | 主角位置 | **跑** |

「表」是队形表 `DAT_00c042f8`，五行三个 float，`FUN_00408be0` 里写死：

```text
21.59  0   -37.31
-42.37 0   -32.08
-25.69 0   -73.67
28.96  0   -82.99
28.96  0  -122.99
```

偏移是在主角自己的基上合成的：`表.x × 右 + 表.y × 上 + 表.z × backward`
（backward 就是 `主角 + 0x14`）。起点那一下是 `主角[+0x14] × −12.0`，
和队形表共用同一个基。

走法怎么定的：

- 25 / 211 用 `FUN_00416fa0(目标)`，26 用 `FUN_00416fe0(目标)`。两者几乎
  一样（只差 `+0x4cc` 是 4 还是 5），都以 **`FUN_00412b60(目标, 1)`** 收尾
  ——第二个参数直接写进 `+0x504`，**1 就是 §1 的内部值 1 = 走**。
- 212 用 `FUN_004198c0(主角位置, 2)`，同样直接把 **2** 写进 `+0x504`，
  也就是**跑**。四条里只有它是跑的。

这几条都不管成员是不是激活——那是 opcode 28 的事。

## 5. 移植

- 规则：`states/role_move.rs`——`MoveMode` 三态、`RoleConstants` 解析
  `scene.txt` 的 `role` 节、`speed()` 照 §1 的表挑速度，单测覆盖。
- 常数在 `GlobalState::new` 读一次（原版也是启动读一次），
  `GlobalState::role_constants()` 取。
- 两条命令：`commands/role_move_to.rs`（214）和 `role_path_to.rs`（20）
  共用 `apply_move_action` / `move_speed`。
- 队伍那四条在 `commands/team.rs`：`FormationWalk` 每帧把还没到位的成员
  往各自目标推一步，全部到位才让脚本继续；速度也走 `move_speed`。
  改之前四条都是**瞬移到终点**，起点那一下和等待都没有。
- `pal3_scene_constants_census` 拿实机 `scene.txt` 核对十个字段，并核对
  三种方式各挑到哪个速度。

### 改之前是什么样

- **214 `RoleMoveTo`：第四个参数叫 `unknown`，从来没用过**，`initialize`
  里无条件 `run()`，速度硬编码 175。也就是说**全游戏由脚本驱动的角色移动
  都是跑的**，且不分主角和 NPC。
- 20 `RolePathTo`：已经按 `run == 1` 分了走跑，走 80（碰巧就是
  `WalkSpeed`）、跑 175（应为 `PRunSpeed` = 200），主角和 NPC 不分。
  `run == 2` 时把朝向反过来——这一条和 §1 的「站立姿势移动」对得上，作者
  应该是从实机行为观察到的，保留了。

### 还没做的

- **z 系列角色的 2.4 倍速**。c 系列（主角那一类）不需要——`run()` 挑
  `c03` 就是对的。只有 `z` 系列角色跑起来该加速播，`play_anim` 没有速度
  参数，要改 radiance 的动画组件才能照抄。`ActionSet` 已经把两套分开，
  但还没有「这个角色属于哪一套」（原版的 `+0xae`）的通路。
- **角色自带的速度 `+0x1fc`**。NPC 走路时它优先于 `WalkSpeed`，移植端还
  没有对应的通路，一律当 0 处理。
- **怪物那一支**（`+0xad == 2` 的 `AttackSpeedS/M/L`）没接，脚本驱动的
  移动基本不会走到它。
- 「是不是主角」原版看角色类型 `+0xad == -1`，移植端按角色号在
  `PLAYER_ACTOR_IDS` 里判。
- **玩家自己在冒险模式的移动速度**还是 `adv_director::move_role` 里硬编码
  的 175，而且无条件 `run()`。175 不是 `scene.txt` 里的任何一个值
  （走 100、跑 200）。查过一轮没定死：`FUN_00417c50`（`+0x4f0` 的 case 1，
  玩家控制）里三处写 `+0x504` 全在闲置动画和 `+0x104` 那两个特殊状态的
  分支里，正常按键移动那条路径上没有人写它——速度沿用上一次
  `FUN_00412710` 设的值。要么它在输入处理侧、要么在 `+0x4f0` 从 1 切到 4
  的地方，**还没找到**。
- 冒险模式下队友**不跟着队长走**——原版也不跟：PAL3 平时只显示队长，
  队友是靠 25/211 散开时才摆出来的。
