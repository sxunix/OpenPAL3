来源：`re/PAL3_unpacked.exe`（StarForce 脱壳后），Ghidra 反编译 `re/out/decompiled.c`
+ capstone 反汇编（`switch/re/x86dis.py`）。所有公式都注明了取自哪条指令的地址，
可以直接回查。标 `[推断]` 的没有在代码里 100% 闭环，标 `[存疑]` 的是读出来了但

## 0. 两个基础设施

### 0.1 随机数

全局种子 `DAT_005dfdec`，标准 MSVC LCG，**在各处内联**（全二进制 112 处）：

```c
seed = seed * 0x343FD + 0x269EC3;
rand15() = (seed >> 16) & 0x7FFF;          // 0..32767
```

`DAT_017ad310` 是调用计数器（每次 +1 或 +2），只用于统计，不影响数值。

两个高频写法：

```c
// 掷硬币：取 rand15() % 1024，< 512 为真
coin() : seed 推进一次；((seed>>16)&0x7FFF) % 1024 < 0x200
// 有符号取模的编译惯用法 and 0x800003ff / jns / dec / or 0xfffffc00 / inc
// 因为被 &0x7fff 过，值恒为非负，等价于普通 % 1024
```

**总开关 `DAT_005dfdeb`**：为 0 时所有随机浮动被跳过，伤害取确定值。
（调试/固定种子用。移植时保留这个分支，默认置 1。）

### 0.2 战斗角色结构（步长 `0x37c`）

`stage + 角色下标 * 0x37c + 偏移`。下标 0–4 = 我方主角，5–10 = 敌方。

| 偏移 | 含义 | 出处 |
|---|---|---|
| 0x228 | 特殊标记（== 0x2e2 时死亡改为直接移出场） | 0x4f2eb1 |
| 0x241 | 该槽位有人 | 0x4f9e70 |
| 0x242 | 存活标记（0 = 已死） | 0x4f2c94 |
| 0x248 | 等级 | 0x4f9ff9 |
| 0x24c / 0x250 | 精 当前 / 上限 | `FUN_004f2bb0` |
| 0x254 / 0x258 | 气 当前 / 上限 | `FUN_004f2bf0` |
| 0x25c / 0x260 | 神 当前 / 上限 | `FUN_004f2c30` |
| 0x264 | 武 | `FUN_004f37a0` |
| 0x268 | 防 | `FUN_004f3820` |
| 0x26c | 速 | `FUN_004f3920` |
| 0x270 | 运 | `FUN_004f38a0` |
| 0x290 (f32) | 装备累计：气消耗减少 % | `FUN_004edf10` |
| 0x294 (f32) | 装备累计：神消耗减少 % | 同上 |
| 0x298 (f32) | 装备累计：暴击伤害增加 % | 同上 |
| 0x29c (f32) | 装备累计：特技成功率增加 % | 同上 |
| 0x2a0/0x2a4/0x2a8 (f32) | 装备累计：精 / 气 / 神 上限加成 | 同上 |
| 0x2b4 (f32) | 道具效果增强 % | 0x4ef1c8 |
| 0x2e8 + n*4 | 已装备仙术格（6 组 × 8 格） | `FUN_004fa620` |
| 0x454 + e*4 | 五灵值，e = 1..5 | `FUN_004ef710` |
| 0x470 | 本体五灵属性（单值 1..5） | 0x4f9c30 |
| 0x474 | 受击伤害减半标记 | 0x4f2ce0 |
| **0x475 + k** | **状态标记，k = 状态号** | `FUN_004f3d90` |
| 0x490 + k*2 (i16) | 状态的**起效延迟**回合数 | `FUN_004f48c0` |
| 0x4c6 + k*2 (i16) | 状态的**剩余**回合数，`0x7fff` = 永久 | 同上 |
| 0x598 | 免疫一切精变化 | 0x4f2ca6 |

**状态号 k 比数据库的 `ActorCombatStateType` 大 1**（k = 枚举值 + 1，k=0 不用）。
三处互相印证：

- k=6/7 → 0x47b/0x47c，正是 `FUN_004f37a0` 里加减 25% **武** 的那对标记
  → 枚举 5/6 = 武+/武− ✓
- 受到伤害时清 k=0x11 → 枚举 16 = 眠（挨打醒来）✓ (0x4f2d9d)
- 物理攻击遇 k=0x15 / 0x17 直接 0 伤害 → 枚举 20 避（物理无效）/ 22 隐形 ✓
  (`FUN_004ef7e0`)

**引擎只跟踪 27 个状态槽（k = 0..26，即枚举 0..25）**。死亡时的清零循环写
0x475 起 27 字节、0x490 起 54 字节、0x4c6 起 54 字节 (0x4f4270 附近)。
枚举 26–30（任意毒/辟邪/退魔/神眼/精进）在战斗中没有对应槽位，
[推断] 由装备或别处单独处理。

## 2. 物理攻击伤害（kind 7 + `FUN_004ef7e0`）

### 2.1 有效武 / 防（`FUN_004f37a0` / `FUN_004f3820`）

```c
武_eff(x) = 有 k6(武+) ? 武 + round(武 * 0.25)
          : 有 k7(武−) ? 武 + round(武 * -0.25)
          : 武
防_eff(x) = 有 k8(防+) ? 防 + round(防 * 0.25)
          : 有 k9(防−) ? 防 + round(防 * -0.25)
          : 防
```

运（`FUN_004f38a0`，k10/k11）与速（`FUN_004f3920`，k12/k13）同构。

> **注意：增减幅度是 ±25%，不是 ±10%。** 数据库那份枚举的注释写的是
> "临时增加 10%"，与可执行文件不符，以这里为准。常数 0.25 见 0x4f37c9。

### 2.2 主体（kind 7，0x4f9fdc–0x4fa1ee）

```c
atk  = 武_eff(攻方);                                    // 0x4f9fdc
def  = 防_eff(守方);                                    // 0x4f9fe9
dmg  = -ftol( (攻方.等级 * 0.005f + 1.0f) * (atk - def) );
       // fmul [0x56fcf4]=0.005, fadd [0x56a63c]=1.0    // 0x4f9ff6..0x4fa016
       // 负数表示扣血

// —— 随机浮动 ±10% ——                                  // 0x4fa02f
if (DAT_005dfdeb) {
    spread = |ftol(dmg * 0.1f)|;                        // [0x56a624] = 0.1
    if (spread != 0) {
        r = rand15() % spread;
        if (coin()) r = -r;                             // 0x4fa0bc
        dmg += r;
    }
}

// —— 偷袭/背击加成 ——                                  // 0x4fa0cf
if (攻方.flag[0x28a] || 攻方.flag[0x289]) {
    t = DAT_005dfdeb ? (coin() ? 100 + rand15()%5 : 100 - rand15()%5) : 100;
    dmg = ((t - 45) * dmg) / 100;                       // 0x4fa19d，0x2d = 45
}

// —— 五灵修正 ±5% ——                                   // 0x4fa1c0
n   = 五灵关系(攻方, 守方);        // ∈ {-1, 0, 1}
dmg = ftol( (1.0f - n * 0.05f) * dmg );                 // [0x56a778] = 0.05
return dmg;
```

`0x289` / `0x28a` 这对标记在 `FUN_004ed8c0`（战斗开始建角色）里按角色的
`+0x265` 分档随机置位，是**先手/偷袭**的两种档 [推断]。
注意 `(t-45)/100`：t≈100 时系数约 **0.55**，即这条分支实际是**削弱**伤害。

### 2.3 外层：连击与暴击（`FUN_004ef7e0`）

```c
if (守方 有 k21(避) 或 k23(隐形)) return 0;             // 0x4ef7f0

dmg = FUN_004f98b0(7, 攻方, 守方, 0, 0);

// 连击：武器 combo_count > 1 时，单次伤害按次数均分
if (0 <= 攻方 <= 4 && 装备武器.combo_count > 1)
    dmg /= 装备武器.combo_count;                        // 0x4ef83c

if (攻方.flag[0x488]) dmg *= 2;                         // [推断] 蓄力/必杀

if (dmg < 0) return dmg;                                // 正常路径（负 = 扣血）
return rand15() % 5 + 1;                                // 伤害算成正数时保底 1..5
```

> `combo_count` 是**除法**不是乘法：总伤害不变，拆成 N 段播放。

### 2.4 五灵关系（`FUN_004fa700` / `FUN_004fa6a0` / `FUN_004ef710`）

元素编号 **1 水 · 2 火 · 3 风 · 4 雷 · 5 土**。

```c
克(e)   = FUN_004fa700(e):  1→2, 2→4, 3→5, 4→3, 5→1
被克(e) = FUN_004fa6a0(e):  1→5, 2→1, 3→4, 4→2, 5→3   // 前者的逆
```

即相克链是一个五元环：**水 → 火 → 雷 → 风 → 土 → 水**。

`FUN_004ef710(攻, 守)` 返回 −1 / 0 / 1：

```c
// 守方 0x458 起（e=1..5）全为 0 → 返回 0
// 取攻方第一个高 16 位非零的五灵 e，然后
return (守方.五灵[被克(e)] != 0) - (守方.五灵[克(e)] != 0);
```

代回 2.2：n = 1 → 伤害 ×0.95；n = −1 → ×1.05。**物理攻击的五灵修正只有 ±5%。**

## 3. 仙术命中（kind 1 + `FUN_004ee990`）

```c
bool 命中(skill, 施法者, 目标) {
    if (skill.id == 0x105) return true;                 // 0x4ee9ad
    r = skill.success_rate_level;                       // 记录 +0x268
    if (r < 2) {
        p = FUN_004f98b0(1, 施法者, 目标, 0, 0);
        if (p <= 0) return false;
        return rand15() % 1024 < round(p * 10.24f);     // 0x4ee9ec
    }
    if (r == 100) return true;
    return false;                                       // 2..99 及 >100 恒不中
}
```

**数据库实测**：187 条仙术里 `success_rate_level` 只出现 0（161 条）、
1（9 条）、100（17 条）三种取值，所以上面三个分支正好覆盖全部数据，
不存在"落到 return false"的情况。

命中率本体（kind 1，0x4f98d9–0x4f99e4）：

```c
p = (8 - 运_eff(目标) + 运_eff(施法者)) * 10;
p += ftol( p * 施法者.f32[0x29c] * 0.01f );   // 装备的特技成功率加成
                                              // [0x56aa9c] = 0.01
if (DAT_005dfdeb) {                           // ±20% 浮动
    spread = |ftol(p * 0.2f)|;                // [0x56aa08] = 0.2
    if (spread != 0) {
        r = rand15() % spread;
        p = coin() ? p + r : p - r;           // 0x4f9997
    }
}
```

`p` 是百分数；`p * 10.24` 把 0–100 映到 0–1024 与 `rand%1024` 比较。

## 4. 仙术 / 道具的属性影响（kind 2 + `FUN_004eef20`）

### 4.1 数值来源

`FUN_004eef20(cmd[11], 目标)` 按 `cmd[0]` 分五种动作，循环 i = 0..11 遍历
12 个 `ActorAttributeType` 槽：

| cmd[0] | 来源 | 影响值 | 影响类型 |
|---|---|---|---|
| 0x104 | 仙术（直接值） | `skill+0x250+i*2` | 强制 1（百分比），见下 |
| 0x105 | 仙术（走公式） | `skill+0x250+i*2` → kind 2 | `skill+0x243+i` |
| 0x106 | 道具 | `item+0x284+i*2` | `item+0x277+i` |
| 0x10d | 仙术（直接值） | `skill+0x250+i*2` | 强制 1 |
| 0x10e | 合击技 | `combo+0x25e+i*2` | 由 `FUN_004f2800` 算 |

（0x250 = `SkillInfo.attribute_impact_value`，0x243 = `attribute_impact_type`；
0x284 / 0x277 = `GameItemInfo` 的同名字段。全部与 gdb 记录对齐。）

**cmd 0x104**：对敌方（下标 5..10）加 ±10% 浮动；对我方（0..4）强制把影响
类型改成 1（百分比）。特例：`skill.id == 0x1006` 时数值改为 `等级*2 + 40` [推断]。

**cmd 0x106**（道具）：数值为正且使用者是主角时
`v += round(v * 使用者.f32[0x2b4] * 0.01f)`。

### 4.2 kind 2 的主体（0x4f99e7–0x4f9dfe）

```c
v0 = |ftol( (施法者.等级 * 0.05f + 1.0f) * 影响值 )|;
     // fmul [0x56c5ac]=0.05, fadd [0x56a63c]=1.0        // 0x4f9a20
if (DAT_005dfdeb) {                                       // ±10%
    spread = |ftol(v0 * 0.1f)|;
    if (spread) { r = rand15() % spread; v0 = coin() ? v0 - r : v0 + r; }
}
if (影响值 < 1) v0 = -v0;          // 负影响 = 扣，正影响 = 补
```

再叠五灵修正。取 `(e1, e2) = FUN_004ef6c0(skill)`（仙术记录 +8 起的 5 个
i32，值为 1 的即该元素，最多取两个）：

**施法者是主角（0 ≤ a ≤ 4，0x4f9c09–0x4f9cb2）**——比较对象是**施法者自己**的
`0x470`：

```c
if (e1 == 施法者.元素 || e2 == 施法者.元素)  v += v/2;      // +50%
if (被克(e1) == 施法者.元素)                 v -= v/2;      // −50%
if (被克(e2) == 施法者.元素)                 v -= v/2;      // −50%
```

**施法者是敌方（0x4f9cbb–0x4f9dfe）**——比较对象是**另一方**的 `0x470`：

```c
if (克(e1) == 对方.元素) v += v/10;                         // +10%
if (克(e2) == 对方.元素) v += v/10;                         // +10%
if (被克(e1) == 对方.元素) v -= v/2;                        // −50%
if (被克(e2) == 对方.元素) v -= v/2;                        // −50%
```

> [存疑] 两条分支比较的对象不同（一个是施法者自身、一个是对方），加成规则
> 也不同（同属性 +50% vs 相克 +10%）。反复核过反汇编确实如此，但这种不对称
> 很反直觉，建议实机对照。相关地址：0x4f9c37 / 0x4f9c4d（主角分支的两次
> `FUN_004f07d0(e, [iVar6+0x470])`，`iVar6 = stage + 施法者*0x37c`）。

`FUN_004f07d0(a, b)` 只是"a == b 且 a ∈ 1..5"的相等判断。

### 4.3 影响类型如何落地（0x4ef43a 起）

**只有 i = 0（精）、1（气）、2（神）会被真正应用**；i ≥ 3 落到
`FUN_005159a0(&DAT_005d8e98, 0, 0x40)`（断言/日志）。也就是说数据库里
仙术和道具对武防速运、五灵的影响字段在战斗中**不生效**。

对 i = 0（精）：

| 类型 | 处理 |
|---|---|
| 0 Absolute | 数值直接用 |
| 1 Percentage | `v = 精上限(目标) * v / 100` |
| 2 RecoverToMax | `v = 精上限 − 精当前` |
| 3 IncreaseMax | `目标.精上限 += v`，本次不改当前值 |

i = 1（气）、i = 2（神）同构（气用 `FUN_004f3020`、神用 `FUN_004f31c0` 落地；
神的类型 3 加到 `0x260`；**气没有类型 3 分支**）。

音效：只回精 `wd001`、只回神 `wd002`、两者都回 `wd003`（0x4ef45c 附近）。

## 5. 精的增减与死亡（`FUN_004f2c70`）

```c
int 改精(目标, delta, 弹数字, 来源) {
    if (!目标.flag[0x242]) { 目标.精 = 0; return 0; }        // 已死
    if (目标.flag[0x598])  return 0;                          // 免疫
    if (目标 有 k23(隐形)) return 0;                          // 0x4f2cb4

    if (delta < -1 && 目标.flag[0x474]) delta /= 2;           // 伤害减半

    if (delta < 0 && 目标.flag[0x2bc]) {                      // 护盾吸收
        a = FUN_004f3420();
        if (-delta <= a) { FUN_004f3430(目标, delta); return 0; }
        delta += a;  FUN_004f3430(目标, -a);
    }

    old = 精;
    精 = old + delta;
    精 = (精 <= 上限) ? max(精, 0) : 上限;                    // 0x4f2d3a

    if (delta < 0 && 目标 有 k17(眠)) 解除 k17;               // 挨打醒来

    if (精 < 1) {
        if (目标.[0x228] == 0x2e2) { 退场(目标); return -old; }
        精 = 0;
        目标.[0x574] = 当前时间;                              // 死亡时刻
        目标.[0x570] = 来源;                                  // 凶手
        FUN_005136d0(目标);                                   // 倒地
    }
    ...
}
```

**死亡本体**不在 `FUN_004f3e20` 里，而在改精那一支 `FUN_004f2c70` 的尾巴上：

```c
if (精 < 1) {
    if (怪物 id == 0x2e2) {                    // 会变身的那只
        FUN_005136d0(slot);                    // 倒地
        FUN_004f8fa0(slot);                    // = FUN_004f8bb0(slot, 0x2e3)，原地换成另一只
        return;
    }
    精 = 0;
    +0x574 = stage->+0x50;                     // 倒下的时刻
    +0x570 = param_4;                          // 谁打的
    FUN_005136d0(slot);                        // 倒地
}
```

`FUN_005136d0(slot)` 清 `+0x475` 起的状态标记、`+0x490` 值、`+0x4c6` 计时器和
`+0x474`（防御减半），停掉这个角色正在做的事，把它的两个渲染标记
（显示对象的 `+0x118` / `+0x112`）关掉。

> **更正**：先前把 `FUN_004f3e20(目标, 0x19, 0, 播音效)` 记成"死亡本体"，是把
> **解除**当成了施加。`FUN_004f3e20(slot, k, on, sound)` 的第三个参数就是开关，
> 函数里两个 switch 分别对应 `on == 0`（解除，0x4f44 一带）和 `on != 0`
> （施加，0x4f3ffc 一带），状态位本身写在 `+0x475 + k`。所以
> `(…, 0x19, 0, …)` 那一支是**复活**：`+0x242` 置 1、精归零（调用方随后自己把
> 血填回去）、清掉三组状态数组和 `+0x474`、放 0x1df2 起身动作、播 `wd004`。
>
> 全二进制唯一调它的地方是开发者调试对话框（`GetDlgItem` 那一片，0x533ce0
> 一带）：读血量输入框，`存活位 == 0 且 血 > 0` 就调复活、`存活位 == 1 且
> 血 == 0` 就调 `FUN_005136d0` + 施加死亡。**也就是说战斗内没有复活途径**，
> 战后由 `FUN_004ed870` 把倒下的队员抬到 1 精（见 `combat_flow.md` 第 9.8 节）。

> [未解决] **谁把存活位 `+0x242` 清成 0**。整张 `.text` 里对这个字节的写只有
> 两处，**都是置 1**（复活分支 0x4f44c1、建位 0x4f8bea）——字面偏移扫、
> `lea`/`add` 折叠扫、以及按 4 字节位移的逐字节反汇编扫（连邻近的 0x23e..0x241
> 一起）三种办法都跑过，没有第四处。`+0x241`（在场）和 `+0x598` 也是同样的
> 形状：只有置位或清零一次，没有配对的另一半。可 `FUN_004ed0a0` /
> `FUN_004ed100` 的胜负判定用的偏偏是旗标那一档（两个函数都只被以 mode 0 调
> 用）。这中间还缺一环，**移植不要照抄旗标语义**，继续按「精 ≤ 0」判死。

## 6. 状态的施加、持续与结算

### 6.1 施加（`FUN_004f3e20(角色, k, 值, 播音效)`）

`值 != 0` = 施加，`值 == 0` = 解除（k=0x19 除外，见上）。

前置规则：

- 目标有 k23（隐形）且要设的不是 k23 → **直接返回**，什么都加不上。
- k ∈ 1..5（五毒）：先查 `FUN_004f3cc0`（免疫），命中则返回；
  施加时先清掉 0x476..0x47a（k=1..5）——**五毒互斥**；
  若 `0x48f`（k=26 避毒）已置位则返回。
- k ∈ 14..23：先把 14..23 全部清掉——**定/封/禁/眠/乱/狂/镜/避/界/隐形
  这十种互斥**。

### 6.3 每回合结算（`FUN_004f48c0(角色)`）

对 **k = 1..23** 逐个：

```c
if (!flag[k]) continue;
if (A[k] > 0) { A[k]--; continue; }        // 起效前的延迟
if (B[k] < 1) goto 递减;

switch (k) {                                // 五毒的每回合伤害
  case 1: 改精(-(精上限 * 3 / 4));  break;   // 0x4f4960  [存疑]
  case 2: 改精(-(精上限 / 2));      break;   // 0x4f498b
  case 3: 改精(-(精当前 / 2));      break;   // 同上，取当前值
  case 4: 改精(-(精上限 * 5 / 100)); break;  // 0x4f49b0，每回合 5%
  case 5:                                    // 递增型
     if (B == 0x7fff) acc[角色] = 精上限 * -0.02f;
     改精(round(acc[角色]));
     acc[角色] *= 1.5f;                      // 0x4f4a10
     break;
}
递减: if (--B[k] < 1) { 解除状态 k; B[k] = 0; }
```

> [存疑] 风毒 75% / 雷毒 50% / 水毒 50% 是**每回合**、且风毒还要连续 5 回合，
> 与火毒 5%、土毒 2%×1.5^n 完全不在一个量级。反汇编读数无误
> （`FUN_004f2bb0(x,1)` 确为精上限），但数值反常，建议实机核。

k ≥ 24 不参与每回合结算（循环上界 `iVar5 > 0x17` 退出）。

## 附：两处 [存疑] 的结论

### 五毒的量级 —— **不是读错，是设计**

把每种毒的**伤害算式**和它的**持续时间**（`FUN_004f3e20`，0x4f3fdc 起）
并排看，五种毒立刻变成一套自洽的设计：

| 毒 | 潜伏 | 持续 | 每回合 | 取值来源 | 结果 |
|---|---|---|---|---|---|
| 风 | 3 | 5 | −75% | **上限** | 三回合宽限期，不解必死 |
| 雷 | 3 | 2 | −50% | **上限** | 同上 |
| 水 | 0 | 5 | −50% | **当前** | 每回合减半，永远杀不死 |
| 火 | 0 | 永久 | −5% | 上限 | 慢性消耗 |
| 土 | 0 | 永久 | −2% ×1.5ⁿ | 上限 | 越拖越重 |

关键证据是**水毒取当前值、其余取上限**：同一个函数、只差一个参数
（`FUN_004f2bb0(x,0)` 与 `(x,1)`）。这个区分不可能是巧合 —— 它正好让水毒
成为一条渐近线而不是死刑。所以风毒/雷毒是**倒计时型死刑**，给三回合解毒
窗口；水毒是消耗；火土是慢毒。

结算频率也核实了：`FUN_004ecb20` 里每个战斗位有自己的回合计数器
（`+0x590`），追平全局回合数时才调一次 `FUN_004f48c0` —— 确实是**每回合一次**。
顺带确认了"第 10 号位出手时全局回合 +1"是字面写死的。

**结论：照抄，不改。** 疑点撤销。

### 主角打不过小兵 —— **是我摆的战斗不现实**

三处独立确认双方数值都没错：
- 怪物侧:`FUN_004f8bb0` 把 gdb 的 `attribute_values` 原样拷进战斗记录
  （`+0x250` 上限精 ← gdb `+0x27c`），霹雳堂弟子甲 Lv2 就是 350 精、武 60。
- 我方侧:成长曲线算出的一级景天精 88，与原版状态页显示的 …/88 一致。

怪物表里**等级中位数只有 4，精的中位数却是 420**。也就是说 PAL3 的怪普遍是
高血量低防御（弟子甲防 8），战斗靠磨。我那个测试拿"表里前两只"当对手，
它们是剧情战的敌人，不是五级队伍该遇到的杂兵 —— 是取样问题，不是公式问题。

**结论：公式无误，疑点撤销。**

### 濒死（k=24）与即死（k=25）：施加当场就改精，不落状态槽

## 普攻逐目标结算（`FUN_004f0a10`，2026-09-13 逆完）

几率都用同一种掷法：百分数 < 1 不掷；否则 `rand & 0x3ff < round(p × 10.24)`。
常数 1.3 / 0.01 / 10.24 都是 float。

1. 开头掷一次暴击（kind 6，攻击方），整次出手共用。
2. 对每个目标：目标舞台站在原位（`FUN_0050a700`：离家 ≤ 13）、在场站着
   （`FUN_004ed010`）、没有避（0x15）才结算；否则只弹数字（`FUN_004fdb10` / `FUN_004fdd90`），
   不播回避。
3. 目标是我方（位 0..4）时掷回避（kind 5）；目标有镜 0x14 / 定 0x0e / 眠 0x11 时回避作废
   （骰子照掷）。
4. 伤害 `FUN_004ef7e0`。回避了或伤害 ≥ 0 → 排回避步骤 `FUN_004feef0`，不落血。
5. 暴击：`d = round(伤害 × 1.3)`，`伤害 = d + round(d × 攻击方 +0x298 × 0.01)`。
6. 目标有镜 → 弹回；没镜则掷 `rand & 0x3ff`，`≤ 0x28` 且目标 `+0x2bd`（青铜护镜）→ 弹回。
   弹回 = `FUN_004f2c70(攻击方, 伤害, 0, 目标)`，后面全不走、不放暴击特效。
7. 援护成立（`FUN_004eee60`）→ 伤害落 0 号位、被护的人情 +1；否则先打断目标出手
   （`FUN_004db8b0`）再落血。暴击时在挨打的人身上放特效组 0x1d6（`FUN_004ce340`）。
8. 目标在我方：`FUN_004f3020(目标, 攻击方 +0x284, 0)`——**挨怪物一下加气**，量是怪物 gdb
   `sp_impact_value`（全部怪物都 > 0）。掉气时才按 `+0x290` 减免。
9. 依次（援护时都落在 0 号位身上）：
   - `FUN_004f1cc0`：攻击方是怪物（位 5..10），掷 kind 4，按 `+0x280`（`normal_attack_mode_id`）
     − 0x385：0→k3，1/0x11/0x19→k4，2→k1，3→k2，4/0x13/0x1a→k5，5 定，6/0x12/0x14 封，
     7/0x1b 禁，8 眠，9/0xf 乱，10/0x10 狂，0xb 吸神吸气各 10，0xc 偷钱（算式恒 ≤ 0，
     偷不到），0xd 吃道具（饿鬼：背包里回复类道具随机一种整格吃掉），0xe 随机一种毒；
     最常见的 21/22/23 不附带。
   - `FUN_004f2560`：攻击方是我方，武器 `combat_state_impact_types[i]` 非 0 且
     `value[i] > 0`（i < 0x17）逐个掷，中一个就停，上状态 k = i + 1。
   - `+0x2b8 > 0` 时掷一次，中了 `FUN_004f17c0` 偷（和飞龙探云手同一个函数）。
