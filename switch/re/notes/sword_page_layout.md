## 9. 一处与仙术有关的采集

init 里有一段循环（0x4ac6d3 起）：

```
n = FUN_004790f0()                      // 全局技能表 0x975ed8 的条目数
for i in 0..n:
    e = FUN_00479080(FUN_00479100(i))
    if *(byte*)(e + 4) == 4:            // SkillType == 4 (WeaponMagic 武器技)
        memcpy(this + 0x224 + k*760, e, 760)   // 760 = gdb SkillInfo 记录长度
        k++
```

即**本页把全部 `SkillType == 4`（武器技/剑术）的技能收集到 `this+0x224`**，
每条 760 字节，正是 gdb `SkillInfo` 的记录长度。
数据库里 type 4 共 24 条，且几乎都带 2 种以上五灵属性
（`风刃裂地` 风+土、`幻水惊雷` 水+雷、`天地元灵斩` 五灵齐全 …）。

[推断] 御剑页的目标就是**把装备投进龙晶石以调整魔剑的五灵阴阳，
从而解锁这些多属性武器技**；`perfect` 状态对应某一元素阴阳皆满。

## 3D 视图（源码 `gamemainui/swordui.cpp`、`ui/ui3dctrl.cpp`）

- 剑 `Sword.pol`：`SetOrthosize(100)` 后 `SetOriginPt(392, 400)`（正看，相机平移按半宽 100 定死）。
  页面每次打开（`UIWM_ACTIVE`）：`m_Orthosize = 1000`，每帧 `-= 500·dt` 到 100，只改半宽不改平移，所以剑从
  画面中间附近一边变大一边走到位；同时 `rot` 从 −1080 每帧 `+= 460·dt` 到 0（`SetRotate(rot)` 直接写角度）。
  到 0 后 `SetRotSpeed(98)`、`SetRotate(0)`、`SetRotateMode(2, 180)`，再用每秒 98° 转半圈。
- 阴/阳按钮（`Sword\Lunar0/1/2`、`Positive0/1/2`，(291,466) 200×60，打开时是阴）：入场完了
  （`m_CanCtrlBtn`）、景天拿着魔剑 6603（`m_bHasWeapon`）、上一次转完（`IsRotateTo`）才翻面——
  `SetRotateMode(2, 180)`，放 wa001；否则 wa004。
- 模式 2（`UI3DCtrl::Update` case 2，exe `FUN_00439a20`）：角度加 `速度·dt`；越过目标就停在目标上，但目标本来
  就比当前角小时归 0。`SetRotateMode` 里那步「与 360 对齐」是浮点 `x/360*360`，等于没做。

### 算法

- 同步率 = 原同步率 + 非武器件数 / 5 − 武器件数 / 2，夹在 1..20（景天初值 10）。
- 魔剑的武 = (武器武均值 + 佩戴武均值 + round(防具防均值 × (0.9 + 防具件数/100) / 5) + 佩戴防均值) × (1 + 次数/50)，
  四舍五入后按次数夹在 `InitPURGEINFO` 的上下限（40–70、60–90、70–110、90–120、90–130、95–145、110–160、120–185、
  140–200、150–220）。初值 35。
- 武器技：仙术表里类型 4 的那些，五灵和五块的「完全净化」一致（页面第 2、3 块对调成数据库顺序）就是它，没有就残影剑 2224。
- 属性加成：拿着魔剑（6603）的人，武 += 魔剑的武，当前属性那一灵 +1（exe `FUN_0040be80` 里对 0x19cb 的特判，
  `[0x58615c]` = 35、`[0x5d0750]` = 3 风）。
- 剑的贴图：净化过的那一面，把 `J131Dst` 上那一块字（`dstRect`，自下而上数的行）拷到 `J131Src` 的
  `Purge_rectA`（阳，x 69）/ `Purge_rectB`（阴，x 326）。

移植端的差别：装备在「是」的时候才从背包扣（原版放进列表就扣，关页面还回去），列表照样显示扣过的数；剑身火光
粒子、净化粒子、刻字渐显没做；std::sort 不稳定，同值排序的先后可能和原版不同。
