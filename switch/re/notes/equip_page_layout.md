# PAL3.exe v1.4 — 装备页 (GameMainUI/Equip) 逆向布局笔记

来源：`re/PAL3_unpacked.exe`（StarForce 脱壳后），Ghidra 反编译 `re/out/decompiled.c`
+ capstone 反汇编（`switch/re/x86dis.py`）。所有坐标均为 800×600 原生像素。
标注 [推断] 的条目未在代码里 100% 闭环，其余均直接读自指令。

**渲染模型见 `state_page_layout.md` 第 0 节**；**列表 / 滚动条 / 网格 / 底部工具栏
的通用机制见 `item_page_layout.md`**。本页只列本页数字，与道具页相同处写"同道具页"。
本页所有文本控件同样调 `FUN_004427a0(0)`，即 16px 字格。

## 2. 五个角色面板（FUN_00496190 里的 5 次循环）

init 里有一个 `[esp+0x24] = 5` 的循环，每轮 `esi += 0x26fc`（每名角色一个
9980 字节的控件块，`FUN_00491c30` / `FUN_00491f20` 里的 `param_1 * 0x26fc`
印证了这一点）。每轮建：

| 元素 | init 里的 rect | id | 贴图 |
|---|---|---|---|
| 竖排文本 (+0x279e0) | (316,0,348,64) | 0xa00330 | — |
| Weapon_Ctrl (+0x27a78) | (368,4,400,112) | 0xa00319 | `Equip\Weapon_Ctrl` / `Weapon_Ctrl2.tga` |
| Equip_Ctrl ×5 | (426, 2+20k, 574, 34+20k)，k=0..4 | 0xa00320..0xa00324 | `Equip\Equip_Ctrl` / `Equip_Ctrl2.tga` |

即五行装备槽的 y1 = 2 / 22 / 42 / 62 / 82，每行 rect 高 32、行距 20（相邻行重叠 12）。
`Weapon_Ctrl` 是**武器槽**的按钮（竖长条，32×108，在五行左边），
`Equip_Ctrl` 是**其余五个槽**的按钮（横条 148×32）。

**五轮用的是同一组 rect**，说明真正的分列摆放在别处（类比状态页的
`FUN_004a4c20`），本页对应的排布函数尚未定位。
[推断] 装备页同一时刻只显示一名角色的面板，由第 3 节的 SelRole 按钮切换，
所以五份控件块共用同一位置。

竖排文本 rect 宽 32，内缩后只剩 16px → 每行一个汉字（同状态页等级栏的做法）。
另有一个独立的竖排文本控件 (+0x31e88) rect **(368,16,400,124)**，压在 Weapon_Ctrl 上，
色 RGB(0x0c,0x1f,0x00)，文本来自 `DAT_00c10d38`。

## 4. 顶栏边框与属性比较区（FUN_00491f20(i, rect)）

init 传 `rect = (12,0,590,126)`（同道具页顶栏）。函数建：

- 九宫格顶栏：`Communal\EquipTopFrame\TopFrameL / TopFrameLM / TopFrameM`
  + `Communal\PropTopFrame\TopFrameRM` + `EquipTopFrame\TopFrameR`，
  首块 TopFrameL rect = (12,0,41,119)，其后按 +0xf0(240) 等步进 —— 同道具页。
- `Communal\AttFrameHead0.tga` + `param_1 * 0x100` → **每名角色一张头像框
  `AttFrameHead<n>.tga`**（道具页没有这一块）。
- **五行属性文本**，全部 x 恒 118..256（`rect.x1+0x6a` .. `rect.x1+0xf4`），
  高 32，色 RGB(0x0c,0x1f,0x00)，16px：

| 行 | rect | 控件偏移（三个重叠控件） |
|---|---|---|
| 0 | (118, 0, 256, 32) | +0x268a8 / +0x26e98 / +0x27488 |
| 1 | (118, 22, 256, 54) | +0x26810 / +0x26e00 / +0x273f0 |
| 2 | (118, 42, 256, 74) | +0x26940 / +0x26f30 / +0x27520 |
| 3 | (118, 66, 256, 98) | +0x269d8 / +0x26fc8 / +0x275b8 |
| 4 | (118, 88, 256, 120) | +0x26a70 / … / … |

三列控件各自的数组步长都是 0x98；第一列的数组基址是 +0x26778（那一个是图片控件，
不是文本）。三个控件**共用同一个 rect**，同一时刻只可能显示一个。
[推断] 这就是"高亮某件装备后属性会怎么变"的三态显示（不变 / 变高 / 变低 各一份
文本控件，靠可见性切换），而不是"标签 / 当前值 / 新值"三列 —— 后者需要三个不同的 x。
id 取自按角色索引的表 `0x56d604`（`[esi*4 + 0x56d604]`）。

[未解决] 五行分别对应哪四项属性（武/防/速/运 只有四项，这里是五行）。

## 7. 穿装备 / 脱装备（FUN_00469eb0）

签名：`FUN_00469eb0(角色号 param_1, 槽号 param_2, 物品下标 param_3)`。

**槽号 → 要求的 ItemType**（读自各 case 的 `*(char*)(itemInfo + 0x264) != n` 判断）：

| 槽号 | ItemType | 部位 |
|---|---|---|
| 0 | 7 | 衣服 |
| 1 | 11 | 武器 |
| 2 | 10 | 饰品 |
| 3 | 8 | 帽子 |
| 4 | 9 | 鞋子 |
| 5 | 10 | 饰品（第二格） |

流程：

1. 页面忙标志 `this+0x19dac` 非 0、或 `param_3 < 0`、或该物品持有数 < 1 → 直接返回 0。
2. 若该槽当前装的就是这件（`this+0x16d24 + (槽 + 角色*6)*4 == param_3`）→ 返回 0。
3. **类型校验**：物品的 `+0x264`（ItemType）必须等于上表的值；
   **可用角色校验**：`*(char*)(itemInfo + 0x266 + 角色号)` 必须非 0。
   任一不过 → 走 default 分支（拒绝）。
   > `+0x264` 与 `+0x266` 正好是 gdb `GameItemInfo` 记录里 `item_type`(612)
   > 和 `applicable_actors`(614) 的偏移 —— **运行时的"物品信息块"就是 gdb 记录本身**。
4. 背包该物品计数 −1，"已装备"计数（`this+0x16d9c` 那张表）+1。
5. **原来穿着的那件退回背包**：旧槽的三元组被复制到备份区
   （`角色*0x580 + 0x493c` 一带），旧物品的背包计数 +1、已装备计数 −1。
6. 写入新装备：三元组 = `(物品ID, 1, 物品信息指针)`。

**角色结构里的装备数组**：基址 `role + 0x354`，步长 **12 字节**（三个 dword），
顺序是 **帽 (+0x354) / 衣 (+0x360) / 鞋 (+0x36c) / 饰品1 (+0x378) /
饰品2 (+0x384) / 武器 (+0x390)**。
（全局符号即 `DAT_00c046f4` / `c04700` / `c0470c` / `c04718` / `c04724` / `c04730`，
角色数组基址 `DAT_00c043a0`、步长 0x580 —— 与状态页笔记一致。）

**装备槽行上显示什么**（`FUN_00494040(id, count, infoPtr)`）：
拿物品描述（`infoPtr + 0x60`）按 **`$`** 切分（分隔符常量在 `0x5b74b8`），
取得到的那一段；切不出来才退回用物品名（`FUN_00457f90`）。
即槽行显示的是**属性行**（例如 `防+28 速-1`），不是物品名。

## 附：排布函数已定位 —— 队伍牌在右侧，与状态页同一套坐标

原先记"真正的分列摆放在一个尚未定位的排布函数里"。该函数已找到：

| 页面 | 排布函数 |
|---|---|

| 道具 | `FUN_0049aaf0` |
| 装备 | `FUN_00494660` |

四个都用**同一组数字**：基准 rect (686,62,796,157)，游标从 y=60 起，

`FUN_004929e0(i, rect)` 与状态页的 `FUN_004a3730` 逐条对应：

**所以并不存在"顶部队伍条"**：队伍牌一律在右侧那一列，
