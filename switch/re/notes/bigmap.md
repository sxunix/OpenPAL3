# 大地图（`SwitchMode(13)`）与游戏模式表

## 指令 102 不是"选择渲染状态"

`sce_opcodes.md` 里 102 记的是 `GameSwitchRenderingStateCommand / 选择当前
渲染状态`，按处理函数看不对。`LAB_00436f90` 只做一件事：

```text
arg = 取参数();
FUN_0044f610(this = 0xdb9fd0, arg);
```

`FUN_0044f610` 是**全局游戏模式切换**（战斗笔记里"战败走 `SwitchMode(0xf)`
回标题"说的就是它）：把新模式存进 `[管理器+0x38c8]`、旧的存进 `+0x38cc`，
再让 `FUN_0044f8d0(模式)` 造出这个模式的状态对象放进 `+0x38c4`。之后每帧
的更新、输入、绘制全走那个对象的虚表。

脚本里 102 只出现 16 处，参数只有两种：**13** 出现在 11 个
「从XX进入大地图」里，**0** 出现在 5 个 `T_mXX` 里。所以对移植来说
102 = `SwitchMode`，而 13 就是大地图。

## 大地图怎么运转

状态类是 `new(0x5660)` + `FUN_004460d0`，虚表在 0x56af80（`+0x08` 是每帧
更新 `FUN_0044a1b0`）。要点只有三条：

**一、它有自己的脚本。** `FUN_00432170(procId, 1)` 跑的是
`ui\bigmap\bigmap.sce`（另外两个上下文是 `init.sce` 和当前场景）。这个文件
有 40 个过程：0 号是全局变量声明，**100..137 是 38 个目的地**，2000 号是
「大地图开启测试」。

**二、选中目的地 n 就跑过程 n+100，然后回冒险模式。**
`FUN_0044a4f0(n)`：

```text
if (0 <= n < 0x26) {          // 0x26 = 38，正好是 100..137
    FUN_00432170(n + 0x64, 1);   // 跑 bigmap.sce 的 n+100 号过程
    SwitchMode(0);
}
```

目的地过程自己完成后续，例如 135「从大地图进入雪岭镇」：

```text
2  2                  脚本运行模式
63 "Q15", "Q15"       切换场景
102 0                 SwitchMode(0)
23 -1, 6              角色朝向
21 -1, 228, 23        角色位置
68 "雪岭镇"           提示框
2  1
211                   进情节关时队伍散开
```

**三、哪些点亮、能不能去由指令 125 决定。** `LAB_00436bd0` 写两个数组：

```text
[0xdba014 + id*4] = option;        // i32 状态[38]
[0xdba0ac + id]   = (option > 0);  // u8  「新点亮」标记[38]
```

**更正（2026-09-12）**：先前把 u8 数组当成「可见」、说 1 和 2 没区别，是把闪烁循环
0x44a366（在 `FUN_0044a2e0` 里）错当成了绘制循环。实际是：

* 进图时 `FUN_0044a3d0` 对每个目的地调 `FUN_004499a0(i, 状态[i])`：
  0 = 藏起；**1 = 显示但不能去**（元件 `+0x54` = 0）；**2 = 显示且能去**（`+0x54` = 1）。
* u8 数组是「新点亮、要闪」：`FUN_0044a3d0` 看到有任何一个为真，就把闪烁 alpha 置 0、
  次数 `+0x565c = 2`；`FUN_0044a2e0` 每帧 alpha ±10（0→255→0 为一轮），闪完两轮把这些
  标记清零。只改有标记的那几个元件的颜色 (255,255,255,alpha)。

## 点下去之后（事件 `0x44a540`，按钮 id 0xf1..0x116 对应 38 个目的地）

小人正在走时（`+0x4988`）不理。否则按 0x598c14 起每项 64 字节的场景代号表
（`Q07, Q16, Q02, M01, …`，和 38 个目的地一一对应）到 `datascript\SceneName.txt`
那一节取 `default` 当地名，然后：

* 元件 `+0x54 == 0`（状态 1）：提示框 `+0x4ef0`（种类 3，`Flex\Note` 九宫格）写
  「不能去“地名”」（AssisLang 381 + 地名 + 382），按任意键关；
* 否则：确认框 `+0x4998`（种类 2，是/否）写「要去“地名”吗？」（354 + 地名 + 355），
  记下 `+0x4994 = i`。

两个框的 rect 都是 (250,200,550,300)，`FUN_004a14d0(0x1f,0xfb,0xff,0xff)` = 字色
RGB(0xff,0xfb,0x1f)。每帧 `FUN_0044a1b0` 取确认框的一次性结果（`FUN_004a1cf0`），
0（点了「是」）就把所有目的地设成不可点（`FUN_0044a180(0)`），让小人走过去
（`FUN_00449f70(i)`）。

### 小人（`Spirit`）

`+0x48b8` 是一个帧动画控件（构造 `FUN_0043a160`，虚表 0x56ac4c）：`FUN_0043a4c0(基名)`
按 `"%s%d.tga"` 从 0 读到读不到为止，`FUN_0043a4b0(5.0)` 设每秒 5 帧。贴图
`ui\BigMap\Spirit_{LU,RU,LD,RD}{0,1}.tga`，都是 64×64 散文件。

* 起点（`FUN_00449b90`）：按当前场景代号在上面那张表里找到目的地，小人左上角放在
  那个目的地的中心（`x2 − (x2−x1)/2`，`FUN_00449ab0`）；再 `FUN_00443ce0(x2, y2)` 把
  地图卷到那个目的地的右下角在屏幕内。
* 走（`FUN_00449f00` 设目标 + `FUN_00449fe0(dt)` 每帧挪）：目标是目的地中心；x、y
  **各自**以 `dt × 120.0 × 1` 像素逼近（先斜走再直走），到了置 `+0x4989`。
* 朝向（`FUN_00449e60`）：目标在右下 RD、右上 RU、左下 LD、左上 LU；到达时换成
  LU/RU 站定，然后 `FUN_0044a4f0(i)` 跑过程。

### 卷动（背景是一个大图控件，构造 `FUN_004434c0`，虚表 0x56ae64）

24 张 256×256 拼成 1536×1024，窗口 800×600。`FUN_00443fc0` 只在鼠标**贴到窗口边上**
时卷：左右边（x ≤ 左、x ≥ 右 − 1）、上下边按三等分再分斜向，一共 8 个方向（跳转表
0x4441b4）。每个方向一步 `dt × +0x90 × +0x74`（进图时 `+0x74` 设 3.0），卷到图边
（`FUN_00443ba0` 那类检查：最后一块的右边不小于窗口右边）就停。目的地和小人跟着
一起挪（`FUN_00449cf0`）；`FUN_00449c50` 把完全出了窗口的目的地藏起来。

## 移植侧

* 目的地表：`yaobow/shared/src/openpal3/bigmap.rs`（38 条，坐标/图标/过程号）。
* 指令 102：`scripting/sce/commands/switch_mode.rs`。13 起大地图，0 什么都不做
  （移植本来就在冒险模式），15 同 147 回标题，其余记日志放过。
* 指令 125：存进 `PersistentState::bigmap_elements`，跟着存档走；`bigmap_element_visible`
  （1、2）/ `bigmap_element_enterable`（2）。「新点亮」另记在 `bigmap_new`，`#[serde(skip)]`
  不进存档，进图时 `take_bigmap_new` 取走。
* 这一屏（`switch_mode.rs` 的 `BigMapScreen`）：800×600 视口、贴边卷动、小人从当前场景
  那个目的地走过去、确认框 / 提示框（MUIDialog 底图和钮从图集取）、新点亮的闪两轮。
  移植加的：十字键在亮着的目的地之间按下标轮换并把图挪到它、选中描一圈边、B 当「否」；
  鼠标没动过就不贴边卷（没鼠标时 imgui 的鼠标位置停在角上会一直卷）。闪烁按帧走，
  原版帧率下的快慢没核 [推断]。
* 调试口：`bigmap` 直接开图，`bigmap_set [s0, s1, …]` 按下标设状态。
* 跨脚本调用：`SceExecutionContext::call_proc_in` —— `SceProcContext` 本来就
  自带一份 `Rc<SceFile>`，所以 `bigmap.sce` 的过程可以直接压进当前场景的
  过程栈。
* census：`yaobow/shared/tests/pal3_bigmap_census.rs`。三条——表里 38 个下标
  和实机 `bigmap.sce` 的 100..137 逐个对上（名字要能在过程名里找到）、24 张
  背景和 38 张图标在包里都在、2000 号过程的字节形状正好是
  「一条 2 + 38 条 125 + 一条 2」= 472 字节且按 0..37 顺序设一遍。
  （顺带确认了 SCE 的参数在文件里是**倒序**存的，先 `option` 后 `id`。）

数据里有一处照留不改：**神魔之井（下标 21）的 `y + h = 1025`**，比图底多一个
像素。0x448870 一带 exe 写的就是 `x=0xe2, w=0x8d, h=0x91`，不是抽错的。

## 悬停的样子（`basedata.cpk` 源码，`gameui/UIBigMap.cpp`）

目的地是 `UIButtonEXA`（`ui/uibutton.cpp`）。三件事：

* **命中判定采贴图的 alpha**：`Update`（`:728`）先 `PtInRect`，再按鼠标相对
  控件左上角的 (x, y) 取那一点的 alpha，`>= 6` 才算点到。所以热区是图标的
  不透明部分，不是矩形。
* **悬停 `MOUSEON` 这一支**（`Render`，`:662`）走
  `UIRenderQuad(l, t, r, b, m_color, tex, mode = 1, info)`，mode 1 取
  `UI_EFFECT_TEX_VCOLOR` = `gfxscript\ui_tex_vcolor.gbf`——普通 alpha 混合，
  但 `ColorOp = ADD`，**把顶点色加到贴图上**。
* 常态 `NORMAL` 走普通那条（`ui_TL`），按下 `MOUSEDOWN` 则整块往右下挪 2 像素
  （`drawrc` 的 `left+2` / `top+2`）、用 `m_surecolor`。
