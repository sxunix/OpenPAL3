### 页签 → 仙术的归类方式

页面为**每名角色**预建 **8 个仙术桶**，桶数组基址 `this+0xd1c`，
每桶跨度 `0x4a8`（1192 字节），每桶内每条 12 字节（`{id, ?, 信息指针}`）；
寻址式子读自 `FUN_0048c610`：

```
条目地址 = this + 行下标*0xc + 0xd1c + (桶号 + 选中角色*8) * 0x4a8
```

`FUN_0048b8f0` 按上表的桶号顺序重填八个列表 —— 即页签只是**选桶**，
不是现场按属性过滤。桶号顺序是 0 / 4 / 3 / 1 / 2 / 5 / 6，
换算成"桶号 → 属性"就是 **1 雷 · 2 风 · 3 火 · 4 水 · 5 土**，
与数据库 `ElementType`（水1 火2 风3 雷4 土5）**正好前四项相反**。

[未解决] 往桶里塞仙术的那段代码没找到（写 `+0xd1c` 的函数不在 0x487000–0x48e000
这一段里，寻址用的是滚动指针而非常量偏移），所以"某条仙术进哪个桶"的判据
——是 `SkillInfo.element_attributes`、`SkillType`，还是两者组合——尚未闭环。
桶 0 收的是"技"（[推断] `SkillType` 4 WeaponMagic / 特技），桶 6 是"双"（[推断] 双系法术），
页签 7 不是合击技，是**合成术**（第 9 节）；列头 Com1/Com2/Com3/Percent 是材料一/二/三和成功率。（撤回先前「桶 7 是合击技」的推断。）

## 7. 施放（FUN_0048c610(行下标, 桶号, 确认标志)）

`确认标志 = 1` 时是"真的要放"，失败会写提示文本并播音效 `wa003`
（`FUN_004a1530(1)` 弹提示框）；`= 0` 时只做判定。

按顺序检查：

1. 条目 `+8`（仙术信息指针）非 0，否则直接 0。
2. **有合法目标**：遍历五名角色，在队（`this+0x36d+i`）且 `FUN_0048c520(仙术, i)`
   为真的至少一个；一个都没有就报错返回。
3. **可在战斗外使用**：`*(char*)(信息 + 0x241)` 必须是 1 或 2，否则报错。
   （信息块是**运行时结构**，不是 gdb 原始记录 —— 0x241 落在 gdb `SkillInfo`
   的描述字段里，对不上，与物品那边"运行时块就是 gdb 记录"的情况不同。）
4. **气/神够用**：角色的 `+0x2b0`（气）、`+0x2b4`（神）不得小于需求，否则按
   `桶号 == 0` 与否选两种不同的提示串。
5. **特殊消耗**：`*(int*)(信息 + 0x2b8) == 10`（= 钱，对应 gdb
   `SkillInfo.special_consume_type` 的 10 钱）时，按各在队角色的缺量算总价，
   与 `DAT_00c05f54`（金钱）比较，不够就报错。
6. **效果量 > 0**：把每名在队角色每项属性的"上限 − 当前"（`DAT_00c0473c` −
   `DAT_00c0476c`，12 项）以及若干状态位的加成累加，总和必须为正。

全部通过才返回 1。

### 7a. 冒险中施法全流程（参考源码 `magicui.cpp`，2026-10-17；规则在 `states/magic_use.rs`）

上面的 `FUN_0048c610` 就是源码的 `CheckUsable`，逐段对得上。其余几段：

- **双击列表**（`UIWM_LB_DBCLICK`，移植端：再点已选中的行）：`CheckUsable(行, 页, true)`，过了就
  `CheckNeedTo` 亮箭头、列表禁用、进选人；一律放 wa002。提示框 `m_Msg` (300,200)+218×96
  `DLG_MSGBOX`、字色 (31,251,255)：没人用得上 / 不是我方 / 没影响都是 108（只有「没人用得上」放
  wa003），气不够 238（技）、神不够 109（仙术），钱不够 244。
- **选人**：鼠标停在头像上、或单击头像（wa001）——单体仙术：这人用得上就只亮他，用不上按
  `CheckNeedTo`；单击时全体仙术把用得上的都亮上。**双击头像**（移植端：对同一个人再点一次）施放
  `UsingMagicRole`：
  - 单体目标用不上：108 + wa004，留在选人；
  - 消耗比的是**基值**（`rolevalue`）不是当前值；
  - 特殊消耗 10 且 `tutype == 0`（景天「洒金笺」）：每个在队的人补 `min(缺的精, 40 + 2×施术者等级)`，
    扣同样多的钱、扣气，记次数但不升级；
  - 其余：每项 `n = |效果 × (施术者等级 / 20) × 1.5|`，`Warp(n, 0.1)` ±10%（**n < 10 时 Warp 返回 0**，
    小效果全没了，照留），按效果正负加减；单体支状态码拷 13..30、全体支拷 0..4 和 13..30（全体仙术
    会把不解毒的毒清掉，照留），状态码 ≥2 的毒清零；扣气、神，次数 +1；
  - `UpdateMagicLV`（「技」页不升）：次数 ≥ `lvup[级+1]` 升一级（与战斗结算的门槛下标不同），提示
    `"\n\n    <人> <仙术> 376<级+1>55\n"`，到 3 级且人级 ≥ `rolelv`、仙术级 ≥ `magiclv` 学会
    `nextid`（再加一行 377）；提示框 `m_Dlg` (300,200)+256×156；升级后退出选人。
  - 收尾：五个人（不看在不在队）都不缺了，或 `CheckUsable(…, false)` 不过，就退出选人。
- 右键 / Esc（`UIWM_RCLICK`）、换页签（`ControlPage`）退出选人。
- 施放时目标头像上的粒子（`SetParEffect`，`PAR_RISE`/`PAR_RAINBOW`）见粒子那一节。

**分页签**（`GetRoleSkill`）：type 0（特技）进「技」；仙术里风、雷、水、火、土某一个非 0、其余四个都
不是 1 的进那一页（按这个次序判），否则「双」；`user[角色]` 为 0 的不列。旧的「按属性个数分」作废。
