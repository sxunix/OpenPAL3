# PAL3.exe v1.4 — 道具页 (GameMainUI/Prop) 逆向布局笔记

来源：`re/PAL3_unpacked.exe`（StarForce 脱壳后），Ghidra 反编译 `re/out/decompiled.c`
+ capstone 反汇编（`switch/re/x86dis.py`）。所有坐标均为 800×600 原生像素。
标注 [推断] 的条目未在代码里 100% 闭环，其余均直接读自指令。

**渲染模型见 `state_page_layout.md` 第 0 节**（贴图按 TLI 原生尺寸贴在 rect 左上角、
不拉伸；文本 rect 四边内缩 8、字号档 1 = 16px 字格、ASCII 前进 8 / 汉字 16、行距 16）。
本页所有文本控件同样调 `FUN_004427a0(0)`，即 16px。

入口：
- `FUN_0049f2e0` —— 页面 init（框架、Info 面板、列表框、说明文本、排序按钮、确认对话框）。
- `FUN_0049e8e0` —— 六个分类页签 + 六个列表 + 滚动条 + 12 行网格 + 三个排序按钮，
  由 init 以 `ListFrame` 的 rect 作参数调用，页内所有相对坐标都基于它。
- `FUN_004993d0` —— 底部工具栏（与状态页同一套数字，见第 6 节）。
- `FUN_0049b2e0(tab)` —— 切页签；`PTR_LAB_0049c2a8` 是 6 项跳转表。
- `FUN_0040d010(cat)` —— 背包过滤器，全局背包对象在 `DAT_00c05f30`。

> `FUN_00471590` 也引用同一组页签贴图，但它整页用 `UI\Assistant\*`
> （Add/Sub/SaleFlag/Sale_Grid/ListBoxSelPic），是**商店（assistant）界面**，
> 不是道具页。只是复用了分类图标。

### 页签 → ItemType 映射（`FUN_0040d010`，跳转表 0x49c2a8 逐项确认）

每个页签处理程序都执行 `push <n>; mov ecx, 0xc05f30; call 0x40d010`，
n 与页签下标一一相同，因此映射直接读自 `FUN_0040d010` 的 switch：

| 页签 | 过滤条件（ItemType） |
|---|---|
| 0 恢复 | `== 1` Healing 治疗 |
| 1 仙宝 | `== 3` Treasure 仙宝 |
| 2 攻击 | `== 2` Throwable 投掷 |
| 3 炼制 | `== 5` Ore 矿石 **或** `== 12` Corpse 尸块（两者都收） |
| 4 古董 | `== 4` Antique 古董 |
| 5 特殊 | `== 6` Plot 剧情 |

（同一个过滤器的 6..13 号分类给装备页用：6 = 7/8/9/10/11 全装备，7 = 11 武器，
8 = 7/8/9 衣帽鞋，9 = 10 饰品，10 = 12 尸块，11 = 7 衣，12 = 8 帽，13 = 9 鞋；
14/15 号是"能加属性的治疗品"和"能解状态的治疗品"，战斗中用。）

**排序行为**（参考源码 `mainpropui.cpp` `IDB_MPROP_SORT_*` + `playermgr.h` `PlayerItemSortFun`）：
- 「使用序」= `m_SortState = -1` 不排序，按 `Inventory::m_items` 的先后（新物品 `push_back`、
  已有的只加数量、用光 `erase`）；「价格序」= `SORT_PRICE` 按 `price`；「功能序」= `SORT_FUNC`
  实际按物品 id。都升序、`std::sort`（不稳定；32 件内 MSVC 走插入排序，相等项保持原序）。
- `m_SortState` 是页面对象的成员，只在构造时置 -1，之后每次 `FillList` 都按它排——关页再开、
  换分页都不变，直到再点按钮。排序后行号和滚动位置不变（`FillList` 记下再恢复）。
- 音效：成功 wa001；`m_IsCanUse`（物品正在使用流程里）时三个都拒绝，wa004。
- 移植：`shared/src/openpal3/states/item_sort.rs`；先后存在 `PersistentState::inventory_order`
  （旧存档没有这一项，当作更早拿到的、按 id 排在前）[移植]；选人态当作 `m_IsCanUse` [推断]。
