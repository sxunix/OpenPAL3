# 当铺经营（SCE 103）

（2026-09-13 更新）经营本体已照原版做完：界面见 §10、死当物池见 §11。还没做的只剩陈列、休息两项。

永安当那套经营玩法。实机只有 Q01 的 proc 1326「当铺投资」调过一次
（传 1297）。地址都是 PAL3 v1.4 未加壳 `PAL3_unpacked.exe`。

## 1. 入口与收尾

`LAB_00436c60`（一个 int 参数）：

```text
FUN_0044f610(7)              // 进模式 7 = 当铺
DAT_00dba244 = 参数           // **过程号**，不是标志位
new 等待任务 FUN_00434ca0(7) → FUN_00434c40   // 脚本挂起到模式结束
```

按「聊天」时（`FUN_0051f1b0` 里按钮 `0xa01b05`，字是 AssisLang 163「聊 天」）：

```text
FUN_00523820(5)                     // 切到「离开」那一页
FUN_00432170(DAT_00dba244, 0)       // 把参数当过程跑
放 wa001
```

**更正**：先前把 0xa01b05 当成「离开」钮。「退出」是 0xa01b08，只 `FUN_00523820(5)`，
不跑过程；参数过程只在「聊天」时跑（和冶炼 146 同一个套路）。

## 2. 存档里的当铺状态 `DAT_00d92788`

这块**在存档里**：读档时 `rep movsd` 从存档缓冲拷进 `0xd92788`
（0x537de5 一带），新游戏时头几个 dword 清零（0x407923，所以**等级默认 0**）。
块很大（后面还有 `+0x27848` 之后的东西）。

五个查询 opcode 读的字段：

| opcode | 名字 | 偏移 | 取值 |
|---|---|---|---|
| 101 | 当铺等级 | `+8` | 0..4 |
| 120 | Manage 类型 | `+0x27844` | 0..3 |
| 121 | Period 类型 | `+0x27838` | 0..2 |
| 122 | Accrual 类型 | `+0x2783c` | 0..2 |
| 123 | UnHock 类型 | `+0x27840` | 0..2 |

五个 opcode 的写法一样：当前模式是 7 就问界面对象（`FUN_00523e70`），否则
直接读存档块，再走一张跳表把值写进脚本变量。

经营对象把这四个类型抄进自己的 `+0x50160..+0x5016c`、等级抄进 `+0x5015c`
（0x521b00 一带）。

## 4. 等级表 `SubGame\HockShop\Data\HockShopLevel.hsl`

**当铺的整套设定是带注释的文本文件**，随游戏发出来了（关键字表在 0x5824fa
起，每项 30 字节，分词器和 DealScript 同一套）。五段 `HL_E`…`HL_A` 对应存档
里的等级 0..4，每段：

| 键 | 含义 |
|---|---|
| `Sale` / `Buy` / `MelonCutting` / `DealIn` / `Invest` / `Rest` / `Exhibit` | 这一级开放哪些功能（卖 / 买死当物 / 分红 / 经营 / 增资 / 休息 / 陈列）|
| `BuyDiscount` | 买死当物打几折（1 = 原价，A 级 0.7）|
| `PropNum` | 剧情段内死当物的总数量（E 0、D 10、C 20、B 30、A 40）|
| `DisMinNum` / `DisMaxNum` | 每次进店显示几件 |
| `CATHOLICON` / `CHANDLERY` / `JEWELLERY` / `ANY` | 四种经营方针下 `RESUME`（恢复类）/ `ATTACK`（攻击+仙宝）/ `ANCIENT`（古董）的比例，各自加起来是 1 |
| `BaseDividend` | 基础红利百分比（E 0、D–B 0.2、A 0.25）|
| `DIVIDEND_*` | 每种方针下当期 / 利率 / 拆当率三档各自的加权值 |

功能是逐级放开的：E 只能卖和增资，D 起有买/分红/陈列，C 起有经营，B 起有
休息，A 什么都能做但**不能再增资**（顶格）。

红利率 = `BaseDividend + 当期加权 + 利率加权 + 拆当率加权`。加权值随等级放大
（E 全 0、D ±0.1、C ±0.15、B ±0.2、A ±0.25），**最差的组合会算出负数**——
A 级奇珍异宝挑「短当期 + 高利率 + 高拆当率」就是 0.25 − 0.25 × 3 = −0.5。
这是数据本来的样子。

另外同目录还有 `source.txt`：**原版的一段 C++ 源码**，写着进店时怎么按比例
随机取死当物（`_TotalDieNum` 件，逐件按 `_ResumeProportion` /
`_AttackProportion` / `_AncientProportion` 掷，取到重复的重掷；攻击类里排除
五灵珠 6119–6125 和土灵珠 6427，古董类里排除仙术书 6409–6413）。

## 6. 等级是投出来的（`FUN_00524e00`）

存档里的等级不是自己涨的，是**累计投资额（资本）算出来的**：

```text
资本 = this->+0x1488
if (资本 < 1) 保持传进来的值
if (资本 > 500000) 等级 = 4                 // A 顶格
比例 = (100.0 / (500000.0 / 资本)) * 0.01   // 就是 资本 / 500000
比例 < 0.25          → 0 (E)
0.25 ≤ 比例 < 0.5    → 1 (D)
0.5  ≤ 比例 < 0.75   → 2 (C)
0.75 ≤ 比例 < 1.0    → 3 (B)
比例 ≥ 1.0           → 4 (A)
```

换算成钱：**E < 125000 ≤ D < 250000 ≤ C < 375000 ≤ B < 500000 ≤ A**。
`+0x8b8` 存着那个比例（界面上大概是进度条）。

增资那一步（`FUN_00524b00` 一带）：

```text
投入 = +0x148c                 // 拖动条选的数，夹在
                               //   [0, min(身上的钱, 500000 − 资本)]（0x5249fe）
资本 += 投入                    // +0x1488
钱   -= 投入                    // DAT_00c05f54
再走上面那把梯子重算等级
```

`SubGame\HockShop\Data\InvestHS.sce` 只有一个过程 1001「当铺建成后的对话」，
按等级说「巳建成 E/D/C/B/A 级当铺…」——**只是旁白，不参与算账**。

移植：`states/hockshop.rs` 的 `CAPITAL_FOR_TOP` / `level_for_capital` /
`max_investment` / `invest`，边界值都有单测。

## 7. 分红怎么算（`FUN_0051f130`）

先在切页时算出「基础红利钱」（0x521058 一带）：

```text
记录 = FUN_00523090(等级)          // this->+0x214 + 等级 × 0xdc
资本 = (+0x1f4c)->+0x1488
+0x50154 = 资本
+0x50158 = ftol(资本 × 记录[+0xd8])   // 记录的最后一个 float 就是 BaseDividend
```

再按玩家选的三档折算（`FUN_0051f130`，FPU 那几步）：

```text
st0 = 基础红利钱                                   // fild +0x50158
st0 = 记录[利率项] + 记录[拆当率项] + 记录[当期项]   // 三次 fld/fadd
st0 = st0 × 基础红利钱 + 基础红利钱                 // fmul st(1); fadd st(1)
红利 = ftol(st0) → +0x5015c
```

也就是

```text
红利 = 资本 × BaseDividend × (1 + 当期加权 + 利率加权 + 拆当率加权)
```

**加权是乘上去的，不是加上去的**。先前笔记里写成「基础值加三个加权」是错的
——那样 A 级奇珍异宝最差的组合会算出负红利；乘法这一版最差是 ×0.25，永远
为正。

顺带把记录的字段位置钉死了（三个索引式子反推出来的，0xdc 字节正好填满）：

```text
+0x00  七个功能开关，各一字节（Sale/Buy/MelonCutting/DealIn/Invest/Rest/Exhibit）
+0x08  BuyDiscount (float)
+0x0c  PropNum   +0x10 DisMinNum   +0x14 DisMaxNum
+0x18  四种经营方针，每种 48 字节：
         +0   resume / attack / ancient   （三个比例）
         +12  period[3]                   （当期加权，代码里 +0x24 + 48×方针）
         +24  accrual[3]                  （利率加权，+0x30 + 48×方针）
         +36  unhock[3]                   （拆当率加权，+0x3c + 48×方针）
+0xd8  BaseDividend (float)
```

## 11. 死当物池（2026-09-13）

以前以为是「每期换一批」，其实 `+0xf1c` 是**升级标志**：

- 增资页（`FUN_005249a0`，0x524c0d 起）按新资本算出等级，比 `+0x1494` 里的旧等级高才把菜单对象
  `+0xf1c` 置 1（顺带 `srand(time)`），否则置 0。
- 经营本体 `FUN_0051f1b0` 下一次处理事件时读它、清零（0x5210b9）。是 1 就重摸死当物池（0x5210ce 起）：
  清掉 0x17ad5c4 起 12 个计数，按这一级的 `PropNum`（等级行 `+0xc`）掷 `PropNum` 次，每次按这一方针的
