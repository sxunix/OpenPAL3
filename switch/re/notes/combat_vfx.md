# 战斗特效：技能 / 道具 → 特效组

来源 `PAL3_unpacked.exe`（`D:\Project\PAL3\combat\CBStageEffect.cpp`、`EffMgr.cpp`）。
移植在 `yaobow/shared/src/openpal3/combat/linker.rs`，接入在 `commands/combat.rs::drive_staging`，
特效组本身的解析 / 渲染见 `flexeff_format.md` 与 `openpal3/scene/flexeff_*.rs`。

## 1. `cbdata\efflinker.dat`：384 × 60

`FUN_00508e30` 读 0x5a00 字节进 CBStageEffect `+0x98c`（`FUN_00508f30` 是写回，编辑器用）。
`FUN_00508880(id)` 线性查，查不到就占一条 id == 0 的空位。

| 偏移 | 含义 |
|---|---|
| +0x00 | id |
| +0x04 | 第一段特效组（-1 无） |
| +0x08 | 第一段挂点四字节 |
| +0x0c | 挂点全 0 时的坐标 |
| +0x18 | 第一段起播时刻 |
| +0x1c | **结算时刻**（道具编排 `FUN_00500550` 到点才 `FUN_004ef8b0`） |
| +0x20 / +0x24 / +0x28 / +0x34 | 第二段：特效组 / 挂点 / 坐标 / 起播时刻 |

id 的归属（拿 gdb 逐个对）：**187 个技能全部在表里**，59 个可投掷道具（61xx「梅花镖」
「袖箭」…），另有 501..510 十条对不上数据库；128 条 id 为 0 的空位。结算时刻分布：
2.0 秒 94 条、1.5 秒 87 条、0 秒 29 条、1.8 / 1.0 / 0.5 / 0.25 / 11 秒若干。第二段只有
1 条在用（2215 → 组 7）。

挂点（`FUN_00508930`，四个字节依次覆盖，最后置位的算数）：

| 字节 | 挂在哪 |
|---|---|
| 0 | 出手这一方的定点：我方 → CBStage `+0x384..+0x38c`，敌方 → 10 号位舞台角色的位置 |
| 1 | 目标那一方的定点（按目标在哪边；打整边时按技能种类判） |
| 2 | 出手的人（舞台角色 `+0x19c4`） |
| 3 | 目标（打整边退回目标那一方的定点） |
| 全 0 | 记录里的坐标 |

实机：字节 3 置位 121 条、字节 1 置位 47 条、全 0 88 条。

行动码 0x10d / 0x10e 播之前还会 `FUN_004ce460` 预载一次。

## 3. 特效里的镜头

特效类 `camera`（15 类里的第 4 类，11 条定义）由 `FUN_004c39a0` 驱动：开始时停掉当前镜头
序列，若自身一个 float 字段 > 0 就 `FUN_00505770(round(它))` 播那个 flexcam 序列；结束时
停掉。所以**仙术的镜头不是单独排的，是跟着特效组走的**。移植端的特效播放（`adv_director`）
目前只处理 `callback` / `audio` / `quad` / `cylinder`，`camera` 还没接。

## 4. 移植端

出手条满、舞台演出手动作那一刻起计时：到第一 / 第二段起播时刻就 `play_effect(组, 挂点)`，
到结算时刻才 `strike()`（普通攻击没有链接，仍按 0.3 秒 [推断]）。挂点里「我方定点」用
0..4 号位重心代替 CBStage `+0x384` [推断]。

## 5. 现在能画出多少（2026-09-11 统计）

顶层特效组几乎都只有 `callback` + `audio`（比如 413、371），画面在 callback 指向的下级组里。
**callback 子块 +0 / +32 的组号是 float**（`adv_director` 就是按 float 读的；按 i32 读会把整棵树
读成空的——统计时踩过一次）。

顺着 callback 展开到底，235 个被链接的特效组里：

- 77 组只含移植端已经会画的类（`quad` / `cylinder` / `audio` / `callback`），能完整画出；
- 137 组能画出一部分；
- 其余约 20 组一点都画不出。

展开后各类出现次数：quad 2490、cylinder 945、callback 467、meteor 254、audio 229、particle 208、
shock 98、model 67、grid 62、action 49、explosive 16、camera 13、quake 12、bink 7、time 1。

实机：夜游 / 日游出招放的是 413（展开为 meteor ×6 + particle「xue.par」）。particle 已接（§6，
截图见到雪片），meteor 还没接；1.5 秒后按链接表的结算时刻打倒景天，时序是对的。

## 6. `particle` 类（2026-09-11 接上）

vtable 0x56f8cc。关键在于 **exe 自己带了一份粒子系统**（0x4b8000–0x4be000，`FUN_004bc760` 造、
0x5896c 字节），和 gbengine.dll 的 `gbParticleGroup` 那份（par_format.md 写的）不是一回事，
几处行为不同。

### 6.1 实例时间线

- `+8` FUN_004c8b80（摆位）：`FUN_004bd7a0(0)` 先关发射；缩放 = 定义记录 **`+200`**
  （`FUN_004bd7c0`）；位置 = 播放点 + 定义记录 **`+0xb8..+0xc0`**；绕圈偏移清零。
- `+0x30` FUN_004c8e90（开实例）：124 字节子块抄进实例 `+0x18`，排三步：两步 `0x4ca400`
  （空步，时长 0，到点就完）+ 一步 `0x4c90c0`，后者由 `FUN_004c9320(.., 延迟 = 子块 +72,
  时长 = 子块 +76)` 排进去。
- 0x4c90c0（这一步里每帧）：
  - 第一次 `FUN_004bd7a0(1)` 开发射；
  - 子块 `+0` ≠ 0 时，缩放 += `+0` × dt（下限 0.001，`0x3a83126f`）；
  - 位置 += `+4..+12` × dt；
  - 转轴 `+20..+28` 归一化（`gbVec3D::Normalize` 零向量给 (0,1,0)），
    `SetAxisAngle(轴, (t − 起点) × +36)`，拿它转 `(+32, 0, 0)` 得绕圈偏移 `+0x44..`；
  - 过了 `+76` 秒这一步结束。
- `+0x14` FUN_004c8bf0（每帧）：推粒子（`FUN_004bc7e0(dt)`）、推时间线；实例全部步完就
  减计数，**计数 < 1 时 `FUN_004bd7a0(0)` 关发射**，已有粒子照常走完。
- `+0x18` FUN_004c8e10（渲染）：平移到位置 + 绕圈偏移再画，粒子是局部坐标；计数 < 1 且粒子
  画完就置 `+8` 结束。

所以 **particle 类的子块 `+76` 是「发射开着多久」**（flexeff_format.md 里「+76 语义未定」对
这个类就此定下）。`FUN_004bd7a0` 写的是每个发射器 `+0xa8`（exe 这份里文件 0xac 那一格），
是运行时启停位，不是循环位。

`SetAxisAngle`（gbengine 0x100259d0）把角度乘 0.5 × 0.017453292，所以 `+36` 是**度 / 秒**
（实机取值 ±150…±1500）。转向按右手 Rodrigues 实现 [推断]（`Rotate` 是行向量乘法，没逐项核对正负）。

实机 145 个启用的 particle 子块：`+76` 全部非零；`+72` 88 个；`+32` 64 个、`+36` 62 个；
`+4/+12` 21 个、`+8` 78 个；`+0` 只有 1 个（2.0）。定义记录 `+200`：10 ×17、20 ×26、25 ×6、
30 ×5、15 ×2、6 / 60 / 200 各 1——**全部 ≥ 6**，没有缩放的粒子在战场上小到看不见（尺寸曲线
多为 1），这就是先前「放了 413 什么都没有」的主因。

### 6.2 缩放乘在哪

`FUN_004bd7c0(s)` 先对整套乘 `1/旧值` 再乘 `s`（`FUN_004bb190`）：

- 每个发射器（`+0x3939c` 起、步长 0x7d58）`FUN_004bb0f0`：原点 `+0x40..` 和扩散 `+0x4c..`
  乘缩放，新值记在 `+0xb0`；
- 每个组参数（`+0x2428c` 起、步长 0x5444）`FUN_004bb180`：写 `+0x164`；
- 初始位置 `FUN_004ba800`：形状上取的点（盒 `+0x7cec`、半径 `+0x7d04`、网格）× `+0xb0`，再加原点
  和播放点；
- 渲染 `FUN_004bc8a0`：半边长 = 尺寸曲线 × 0.5 × 组参数 `+0x164`。

速度曲线和重力不乘。

### 6.3 两处和移植端原先不一样的地方（两个 `.par` 用户都改了）

- **初速不归一化**：exe 的 `FUN_004b91e0` 和 gbengine 的 `ComputeParticleInitVel`
  （0x1002a590）都是 `rand(速率) × 方向曲线原值 + rand(±扩散)`；方向曲线由 `FUN_004b8890`
  直接插值得到，也不归一化。移植端先前把「方向 + 扩散」归一化再乘速率，是写错了。
- **一律加法混合**：exe 这份画粒子时，在组循环之前无条件设置（0x4bcb06 起，D3D9）：
  - `ZENABLE = 1`、`ZWRITEENABLE = 0`、`LIGHTING = 0`；
  - `ALPHABLENDENABLE = 1`、`SRCBLEND = ONE`、`DESTBLEND = ONE`；
  - 颜色 = 贴图 × 顶点色。

  exe 里没有 `p_alpha.gbf` / `p_add.gbf` 字符串，`+0x164` 也被挪去存缩放。所以三个标成 alpha
  的 Snow 组在原版里也是加法——移植端按 alpha 画出了黑方块底，改成加法后黑底消失（截图已核）。

### 6.4 移植端

`scene/particles.rs`：`ParticleEffect::set_scale`、`stop`、`alive_count`；`build_particle_entity`
不再收混合参数。`adv_director::step_flexeff` 的 `particle` 分支读 `.par`、按 `+200` / `+0xb8` 建
`FlexParticle`，`drive()` 就是 0x4c90c0。调试口 `play_effect [组, x, y, z]`（agent 的 script/eval）
用来从已知起点截时间线。

桌面实测（M01 起战斗，`play_effect 413`）：日志 `CEft: 粒子 effect\gbParticle\xue.par 缩放 10
偏移 (250,−50,250) 延迟 0.5 发射 0.2 秒`，之后 2 秒内画面上方有白色雪片飘过、无黑底。
只核对了「看得见、混合对」；和原版的逐帧对比没做。
