# 客栈住店（SCE 119）

`UIShowHotelMenu`。地址都是 PAL3 v1.4 未加壳 `PAL3_unpacked.exe`。

## 1. 入口

分发表 0xd8c464 的第 119 项：handler `0x004369c0`，参数 `string int int int`。

```text
FUN_004369c0：取四个参数 → FUN_0044b630(配置文件, 钱够过程, 钱不够过程, 住完过程)

FUN_0044b630：
    FUN_0044b8a0(配置文件)         // 解析 DealScript\Rest\*.txt
    +0x2510 = 钱够过程
    +0x2514 = 钱不够过程
    +0x2518 = 住完过程
    虚调用 (*+0x18)(1000, 1, 0)     // 打开界面
    FUN_0044b470()                  // 画那一版布局
    +0x2528 = 1                     // 「客栈流程进行中」
```

每帧的函数在 **0x44b0f0**。Ghidra 没把它识别成函数（导出的 `decompiled.c`
里 0x44b000–0x44b470 之间只有 `FUN_0044b470` 起，前面那段是空的），下面是
读反汇编读出来的。

## 2. 每帧流程（0x44b0f0）

```text
if (+0x2528 == 0) return 0;              // 没在客栈流程里就不管

// —— 一、问「要不要住店」——
if (对话系统空闲 && +0xcd4 == 0) {
    格式化 "\n          %s%d%s"           // 0x59daec
        %s = DAT_00dd8d3c（本地化文本）
        %d = +0x210c                      // M_RestPrice
        %s = DAT_00dd8e3c
    FUN_004427c0(缓冲, 0)                 // 上屏
    FUN_004a1530(1)                       // 开是/否选择控件（+0x77c）
    +0xcd4 = 1
}

// —— 二、读玩家的选择（FUN_004a1cf0，控件在 +0x77c）——
0 = 住下：
    FUN_0044b690() + 虚调用 (**this)(0)   // 关界面
    if (DAT_00c05f54 < +0x210c)           // 钱 < 价格（jge，等于算够）
        +0x2520 = FUN_00432170(+0x2514, 0)   // 跑「钱不够」过程
    else
        +0x251c = FUN_00432170(+0x2510, 0)   // 跑「钱够」过程
        +0x2528 = 1;  +0xce8 = 0
1 = 不住：
    关界面，什么过程都不跑

// —— 三、「钱够」那段对白跑完（FUN_004324b0(+0x251c) == 0）——
if (+0xce8 == 0 && +0xce9 == 0) {
    +0xce8 = 1
    +0xcd8 = FUN_004be1a0(FUN_004be590(1))    // 淡出（黑屏）
}

// —— 四、黑屏之后等 1000 毫秒，然后真的住这一晚 ——
if (+0xce8 && 淡出完成 && GetTickCount() − +0xce0 > 0x3e8) {
    回血（见 §3）
    DAT_00c05f54 -= +0x210c                    // 扣钱
    g_story 特判（见 §4）
    +0xcd8 = FUN_004be1a0(FUN_004be590(2))     // 淡入
}

// —— 五、淡入完成 → 跑「住完」过程，清干净 ——
if (+0xce9 && 淡入完成) {
    +0x2524 = FUN_00432170(+0x2518, 0)
    +0x2510/2514/2518/251c/2520/2524 = 0
    +0xce8 = +0xce9 = +0xcd4 = +0x2528 = 0
    关界面
}

// —— 六、「住完」那段对白也跑完 → 再清一次，收工 ——
```

`+0x2520`（钱不够那个过程的句柄）**从头到尾没被检查过**——写进去就没人读。
所以钱不够时界面已经关了，但 `+0x2528` 还是 1，这个函数会一直空转到场景
切换。看着像原版的一处小疏漏。

## 3. 住一晚回哪几项（0x44b2d7）

```text
ecx = 0
eax = 0xc0476c                          // 角色 0 的 +0x3cc
do {
    if ((&DAT_00c05f58)[ecx] != 0) {     // 这个角色在队里
        [eax]     = [eax - 0x30]         // +0x3cc = +0x39c
        [eax + 8] = [eax - 0x28]         // +0x3d4 = +0x3a4
    }
    eax += 0x580;  ecx++;
} while (eax < 0xc062ec);                // 五个角色
```

角色表基址 `DAT_00c043a0`、跨度 0x580（和状态页笔记一致）：
`+0x39c/3a0/3a4` 是精/气/神**上限**，`+0x3cc/3d0/3d4` 是精/气/神**当前**。
`0xc0476c − 0xc043a0 = 0x3cc`，对得上。

于是：

| 项 | 上限 → 当前 | 住店回不回 |
|---|---|---|
| 精 | `+0x39c` → `+0x3cc` | **回满** |
| 气 | `+0x3a0` → `+0x3d0` | **不回** |
| 神 | `+0x3a4` → `+0x3d4` | **回满** |

中间那一项不是漏读——循环体里就只有那两条 `mov`，第三对指令不存在。

`DAT_00c05f58` 是队伍成员标志数组（宿营那段 `(&DAT_00c05f58)[i]` 用的也是
它）。不在队上的角色不回。

## 4. 住店会推进剧情（0x44b317）

```text
eax = FUN_004343f0("g_story")            // 0x59dae4
if (eax != 0) {
    if      ([eax+4] == 0x2b5d)   [eax+4] = 0x2bc0;    // 11101 → 11200
    else if ([eax+4] == 0x1d5ed)  [eax+4] = 0x1d5ee;   // 120301 → 120302
}
```

只有这两个值有特判，别的剧情号住店不动。`g_story` 就是脚本里的全局变量
**−32768**（滑雪那边 M22 proc 1001 的 `13 var-32768, 130400` 用的是同一个）。

## 5. 配置（`DealScript/Rest/*.txt`，`FUN_0044b8a0` 解析）

关键字表在 0x59ba98，节名 `sec1`。七个字段：

| 键 | 存到 | 含义 |
|---|---|---|
| `M_ID` | `+0x30c`（u16） | 掌柜的对话脚本编号，0 无效 |
| `M_Name` | `+0x30e` | 掌柜的名字 |
| `M_RestPrice` | `+0x410` | 住一晚多少钱，不是数字按 0 算 |
| `M_Rest` | `+0x414` | 问住不住 |
| `M_Enough` | `+0x514` | 钱够时的欢迎词 |
| `M_NoEnough` | `+0x614` | 钱不够时的话 |
| `M_RestEnd` | `+0x714` | 住宿完毕 |

（每帧函数里读价格用的是 `+0x210c`，配置对象挂在客栈对象内部另一个偏移
上，两者指的是同一个 `M_RestPrice`。）

随游戏出厂十三家，**价格一律 50 文**：

| 文件 | 掌柜编号 | 名字 |
|---|---|---|
| q01res2t / q01rest2 | 1802 | 客栈掌柜 / 李澜 |
| q01rest | 1416 | 客栈掌柜 |
| q02rest | 1406 | 客栈老板 |
| q03rest | 1406 | 裴万金 |
| q06rest / q09rest / q11rest / q13rest / q16rest | 1408 | 沈福英 / 客栈老板 / 韩朴山 / 麻婶 / 客栈老板 |
| q07rest | 1405 | 客栈老板 |
| q12rest / q15rest | 1404 | 齐炳昌 / 芙蓉 |

配置里的 `M_Enough` / `M_NoEnough` / `M_RestEnd` 和三个过程号的对白是重复的
——实机那三个过程（Q01 的 1421/1422/1423）也各只有一句话。

## 6. 移植

- 规则：`states/inn.rs`——回哪两项、钱够的判据（`jge`，等于也算够）、
  剧情号特判，单测覆盖。配置解析仍是 `states/shop::RestScript`。
- 命令：`commands/show_chat_rest.rs`（这之前是个直接 `return true` 的空桩，
  住店不扣钱也不回血）。
- `pal3_inn_census` 拿实机那十三个文件核对：字段都读得出来、`\n` 转义开、
  末尾的 `&` 去掉、价格为正；再在每一家上算一遍住店（钱正好够 / 差一文）。
- 和原版的差别：
  - **没有那一秒黑屏**。原版是「钱够的对白 → 淡出 → 等 1000 ms 回血扣钱 →
    淡入 → 住完的对白」；移植端在两段对白之前就把账结了，玩家看不出来，
    两段对白的先后一致（`call_proc` 是压栈，所以后压的先跑）。
  - 钱不够时原版会空转到场景切换（§2 末尾那个疏漏），移植端跑完「钱不够」
    的过程就结束命令。
  - 界面是 800×600 上的文字浮层，不是原版的布局（`FUN_0044b470`）。
