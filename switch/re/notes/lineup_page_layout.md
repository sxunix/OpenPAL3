## 2. 顶部五个队伍槽（FUN_00483650 后半）

`RoleFrame.tga`(485×108) 铺在 (0,0)，其上是**横排五个 55×57 的角色槽**。
五个 rect 存在 `this+0x2699c` 起、步长 0x10 的数组里：

| 槽 | rect | 备注 |
|---|---|---|
| 0 | (50,24,105,81) | 队长固定占这一格（见第 5 节） |
| 1 | (136,24,191,81) | |
| 2 | (216,24,271,81) | |
| 3 | (296,24,351,81) | |
| 4 | **(296,24,351,81)** | **与槽 3 完全重合** |

槽 4 的重合已用反汇编确认不是反编译误差：
`mov ecx, 0x128` / `mov eax, 0x15f` 之后，
`[esi+0x269cc]`（槽3.x1）与 `[esi+0x269dc]`（槽4.x1）都写 ecx，
`[esi+0x269d4]`（槽3.x2）与 `[esi+0x269e4]`（槽4.x2）都写 eax。
五个槽的 y 由前面那个 5 次循环统一写成 24，y2 = y1+0x39 = 81。
[推断] 原版的第五格是排版疏漏；实机上五人满队时槽 4 会盖在槽 3 上。

每个槽上叠三层控件，rect 都取自上表：

| 控件数组 | 步长 | 贴图 | id |
|---|---|---|---|
| `this+0x263ac` | 0x98 | `Lineup\NoBody.tga` 54×57 | 0xa00001（五个共用） |
| `this+0x25ce0` | 0x158 | `Lineup\Head<n>0/1/2.tga` 54×57 | **0xa00002..0xa00006** |
| `this+0x266a4` | 0x98 | `Lineup\<角色>_lead.tga` 54×57 | **0xa00634..0xa00638** |

- `Head<n>` 是三态按钮（0 常态 / 1 选中 / 2 悬停），n = 角色号。
- `<角色>_lead.tga` 五张（jingtian / xuejian / longkui / zixuan / changqing），
  init 里**五个都用槽 0 的 rect**，即"队长标记"始终画在最左那格。
- 三层在 init 里建完即 `SetVisible(0)`，由排布函数按在队情况打开。

## 3. 3D 五灵盘（FUN_00483650 尾部）

不是 2D 贴图，是一个真正的 3D 小场景：

- 模型 `ui\GameMainUI\Lineup\wl.pol`（五灵盘），
  `FUN_0047c6e0(0, 50.0f, 400.0f, 1)` + `FUN_0047d030(−30.0f, 30.0f, 0)`。
- 指针 `ui\GameMainUI\Lineup\pointer.cvd`：先建 5 个（循环基址 `&DAT_00c0600e`
  步长 0x2200，到 0xc10a0e 为止），再建 6 个（`iVar6 = 6` 的循环，
  控件数组 `this+0x27360` 步长 0x98）。
- 五个 3D 位置写在 `this+0x26f68` 起，每组三个 float（x, y, z），y 恒取
  `this+0x26fd4`：

  | # | x | z |
  |---|---|---|
  | 0 | −30.0 | −56.0 |
  | 1 | 25.0 | −18.0 |
  | 2 | 4.0 | 42.0 |
  | 3 | −65.0 | 42.0 |
  | 4 | −80.0 | −20.0 |

  第六组取 `this+0x26fd0/4/8`。这三个字段在 exe 里字面、折叠两种形式都扫不到写入，
  所以 y 和第六组都是 0 [推断：页对象构造时清零]。

### 3.1 节点类（`FUN_0047c590` 起，每个 0x98 字节）

- `FUN_0047cb90(名字, 动作)`：按扩展名载 `pol`（类型 1）/ `cvd`（类型 3）/ 其余当角色（类型 2，
  `FUN_00536d20` 载模型、`FUN_00536c50(动作, 0)` 设动作）。`FUN_0047cd70(名字)` 在同一节点上再挂
  一个附属模型（`+0xc`）。
- `FUN_0047d030(x, y, z)` 设位置 `+0x20`；`FUN_0047d130` 设朝向目标 `+0x2c`，`+0x74` 是朝那边的角度。
- 画（`FUN_0047d440`）：`Begin(节点的相机)`、`SetAsCurrent(3)`，`Push → Translate(+0x20) →
  Rotate(+0x3c, X) → Rotate(+0x38, Y) →（+0x78 置位时再转向 +0x74）→ Rotate(+0x40, Z) →
  Rotate(+0x44, X) → Rotate(+0x48, Y) → Rotate(+0x4c, Z) → 画 → Pop`；附属模型在
  `+0x14/+0x15` 都置位时另画在 `位置 + (0, +0x18, 0)`。
- 更新（`FUN_0047d690(dt)`）：放模型动画；`+0x79` 置位时按 `dt × 50 × +0x88` 度转 `+0x38`
  （`+0x90 == 1`）或绕 `+0x2c` 公转（`+0x90 == 0`），转到 `+0x84` 为止。

### 3.2 这一页怎么用

构造 `FUN_00482ed0` 写三个常数（0x48322a 起）：`+0x26f48 = −38.0`（相机俯角）、
`+0x26f4c = 1.8`（抄进每个节点的 `+0x88`，转速系数）、`+0x26f54 = 12.0`（指针抬高）。

- 相机（`FUN_0047c640`）：`gbCamera` 视角 `+0 = 50.0`（非 0，**透视**），`SetDimention(800, 600)`。
  `FUN_0047c6e0(0, 50, 400, 1)`：看向 (0, 50, 0)、距离 400；`FUN_0047c7e0(0, −38, 3.2)` 设偏航 / 俯仰 / 滚转，
  `FUN_0047c830(1)` 反算出眼睛 ≈ (0, 296, 315)，up ≈ (−0.056, 0.787, −0.615)。
- 节点：`wl.pol` 在 (−30, 30, 0)；五个角色节点（`&DAT_00c0600e` 起跨 0x2200 取模型名，动作 0x10 = `j01`），
  每个挂一个 `pointer.cvd`，抬高 `+0x18 = 自己的 y + 12`；另六个 `pointer.cvd` 节点摆在六个站位上、抬高 12。
- 站位（`FUN_00485980`）：角色状态第 5 字节（`&DAT_00c04919 + 角色 × 0x580 + 5`）取 1..6，
  对应上表 0 / 1 / 3 / 2 / 4 / 第六组（case 3、4 交叉，照原样）；第六组还把节点 `+0x38` 设成 90。
  有人站的站位，那一格的指针节点藏起来。
- 画（虚表 0x56ba34 的 `0x4850e0`）：盘 → 在队的角色（`this+0x169+i`）→ 六个站位指针，然后才画 2D 界面。
- 站位表和公转（`FUN_00483650`）：盘面节点在 `this+0x26fb0`，`FUN_0047d030(−30, 30, 0)` 把位置写进节点
  `+0x20`（即 `this+0x26fd0..d8`）；盘的 `+0x88 = 1.8`、模式 `+0x90 = 1`（自转）。五个角色节点：位置先放盘心、
  公转中心 `FUN_0047d130(盘心)` 写 `+0x2c`、`+0x88 = 1.8`、`+0x78 = 1`（画时再转向 `+0x74`）、模式 0（公转）。
  站位表 `this+0x26f68` 起六组：(−30, Y, −56)、(25, Y, −18)、(4, Y, 42)、(−65, Y, 42)、(−80, Y, −20)、
  (盘心 x, Y, 盘心 z)，**Y 全取盘面的 y = 30**——以前以为这几个字段没人写、当 0，其实是经 `ECX` 写的节点字段。
  六个站位指针绕 (−30, 42, 0) 公转，同样 `+0x78 = 1`。
- 转动（`FUN_0047d690(dt)`，`+0x79` 置位时）：每帧 `dt × 50 × +0x88` 度（= 90°/秒），模式 1 加到自转角 `+0x38`，
  模式 0 加到公转角 `+0x7c` 再由 `FUN_0047d320` 算回位置：`位置 = 中心 − r·(sin θ, 0, −cos θ)`，`r = +100`。
  走到 `+0x84` 为止，然后清 `+0x79`。
- 交互（同一虚表的 `0x485230`，Ghidra 没建函数，按反汇编读）：
  1. 鼠标在盘上（`FUN_0047db40(1)`）时把纵向位移（`0xbfad70` 对象 `+0x4c`）加到俯角上，夹在 [−86, −15]
     （0x56ba50 / 0x56ba54），`FUN_0047c7e0` 重算相机。
  2. 依次看五个角色节点有没有被点中（`FUN_0047da60`：节点 `+0x50` 可点、`+0x79` 不在转、`DAT_00bfc5f4 == 1`、
     射线打中 OBB），**第一个命中就停**：
     - 没选人（`+0x26f58 == 0`）：选中它（`+0x26f58 = 1`、`+0x26f5c = 第几个`、节点 `+0x15 = 1` 头顶指针出来），
       不在盘心的话，用 `FUN_0047d230` 算它相对盘心的角度，不在 [0, 1.5) ∪ (358.5, 360) 就把盘、五个角色、六个指针
       一起按同一个角度、走近的一边转（`0x485449` 起三段循环），转完它正对镜头（+z）；
     - 已选的就是它：取消选中（`0x48572c`）；
     - 已选别人：两人换站位（交换 `this+0x25c32` 的站位号、`FUN_0047d030` 交换节点位置），换进盘心的 `+0x38 = 90`，
       放音效（`FUN_0053df70(DAT_005c5ef8, 1)`），取消选中。
  3. 再看六个站位指针（`0x48573c`）：选了人又点中一个亮着的指针，就把人挪过去（位置 = 指针位置 − 抬高 12），
     这格的指针藏起来（`+0x50 = 0`）、原来那格的指针亮回来，站位号改掉，进盘心的转 90°，放音效，取消选中。
  4. 盘、角色、指针各自 `FUN_0047d690(dt)`；指针的 CVD 播完一轮回第 0 帧再按倍率 1 播（`FUN_0047cf40`）。

  **更正**：以前写的「点中角色进拖动、跟着鼠标挪」是读错了，原版没有拖着人走的操作，是「点人选中 → 点人换位 /
  点空格挪位」。鼠标按键表：`DAT_00bfc5f4 == 1` 当「这一帧点下」、`FUN_0047db40(1)` 当「按住」[推断，没核]；
  别处 `(DAT_00bfc5e8 & 0xf)` 取 1 / 2 成对出现，像是左键 / 右键。

### 3.3 移植端

`openpal3/lineup_disc.rs` + `IPal3Service::draw_lineup_disc`，`lineup_menu.p7` 在铺完底色后先画它、
再画 2D 界面。一个离屏透视场景：盘、在队角色（`j01`，按上面的规则转向）、六个站位指针（有人站的藏掉）；
相机照 `FUN_0047c830` 算，滚转在 `look_at` 之后绕视线转 3.2°；视角 50° 按 4:3 水平视角理解 [推断]。
按住鼠标、射线打中盘的包围盒时，把纵向位移（画布坐标）加到俯角上，夹在 [−86, −15]。
手柄右摇杆上下同样改俯角（满推每秒 90°，**原版没有**，移植端加的）。

点选照 §3.2 的交互做（`LineupDisc::click` → `DiscAction`，`service.rs` 把换位 / 挪位写回存档）：
整盘用一个转角表示，盘面自转、角色和指针绕盘心公转都按它算，90°/秒、走近的一边；转的时候点不中。
选中的人头顶挂一个 `pointer.cvd`，高度 = 节点 y + 模型高 + 12。`+0x1c` 查清（2026-09-14）：`FUN_0047cb90` 载完模型取包围盒（POL 走 `gbGeomNode::GetOBBox`，角色走几何节点虚表 +0x1c，写同一块栈上的 gbOBBox）的 `+0x44`；gbOBBox 边长在 `+0x40..+0x48`，`GetRadius` 乘 0.5，所以是整条边长——模型的高。
角色的包围盒算的时候跳过脚下的影子（`ROLE_SHADOW`，60×60），不然五个人都是 ±30、互相挡；
射线打 AABB（原版是 OBB），按编号取第一个命中的，和原版一样。换位 / 挪位放 `wa028`
（`0x485718`：`FUN_0053e2e0(DAT_005c5ef8 → "wa028", 1)`，取消选中那一支不放；日志里读到了，声音没法在这边听）。
选中时把 `j01` 从头再放一遍（`FUN_00536c50(节点 +0x94, 0)`，`+0x94` 是载入时的 0x10）[推断：重设同一个动作即从头播]。
龙葵的模型按存档里的形象取（`role_model`：opcode 42 改的就是角色记录 `+0xe` 的模型名，105 蓝 / 106 红），
形象变了盘面整个重建。

手柄（移植端加的，原版只有鼠标）：方向键左右让光标在六个站位间走（0→1→2→3→4 正好绕盘一圈，5 是盘心），
光标标记是一个 `pointer.cvd`，比普通指针再高 20；A 键等于点光标那一格（有人点人、空着点指针）；
一用鼠标点就收起光标。截图核过：方向键出光标 → A 选中景天（转 180°）→ 方向键到 1 号 → A 景天和雪见换位。
测试钩子：agent 的 `lineup_click [x, y]` 让下一帧当作在画布这点点了一下。
截图核过：点雪见 → 整盘转 108° 她到正前方、头顶出指针；再点紫萱 → 两人换位、右侧按钮跟着变；
点景天（转 180°）、右摇杆压到俯视、点盘心指针 → 景天站进盘心、原来那格的指针亮回来。注意选中的人转到正前方后
正好挡在镜头和盘心之间，平视时点盘心会先点中他（原版也是先查人）。
移植端的站位号 0..4 就是按钮下标，也就是站位表的下标（`FUN_00485980` 的 case 1/2/3/4/5 →
按钮 0/1/3/2/4 → 站位表 0/1/3/2/4，两边一致）。

`wl.pol` 只是一张四边形，五块元素砖都画在 `wl.tga` 上。起初指针全落在砖与砖之间（五边形朝向反了），
原因是 TGA 行序：单贴图 POL 的材质（`Pal3GeomMaterialDef`）以前按 image crate 上行在前解，
改成和 CVD 一样最下一行在前之后，指针正好落在砖上（`cvd_playback.md` §7）。

截图确认过：盘、五人按 0..4 站到五块砖上、有人的站位指针藏掉。角色背朝盘心（朝向按盘心 (−30, 30, 0) 算，
以前按原点算是错的）[推断：MV3 前方是 −z，和原版一致未对照]。站位的 y 改成 30 以后人站在盘面上，
以前「脚在 y=0、会不会被盘挡住」的问题不存在了。右侧的阵位按钮仍然只能点 / 触屏。

**第六个站位不是「总开关」**：合击技的站位要求（gdb `element_position_requirements`）里有 6（504–507、509、510
都要景天站 6），7 / 8 是「风火雷任意」「水火土任意」。原版 `FUN_00485980` 的 case 6 把人放到第六组（原点）并转 90°，
所以 6 就是盘心那一格 [推断：6 = 盘心，未在代码里读到名字]。移植端 `lineup_menu.p7` 把第六个按钮当成不能点的总开关、
站位只收 0..4——**已改（2026-09-12，和合击技一起）**：第六个按钮能点、站位收 0..5；关页写回的值是
格子号 + 1（`FUN_004845f0`：0..5 → 1..6），战斗里 `Combatant::element_position` 按这个换算；新游戏的
默认阵形照 `FUN_00408fd0`（景天 3、雪见 5、龙葵 1、紫萱 2、长卿 4，存成格子号 2/4/0/1/3）。站盘心的人

## 6. 阵位状态表与刷新（FUN_004844a0）

状态表在 `this+0x25c14`，**每名角色 6 字节**（`+ 角色*6 + 阵位`），
每字节三态：

| 值 | 含义 |
|---|---|
| 0 | 该阵位不可选 —— 按钮 `FUN_00445e50(0)` 置灰，选中标志清 0 |
| 1 | 可选未选 —— 按钮可用，`+0x50`/`+0x44` = 0 |
| 2 | 已选 —— 按钮可用，`+0x50`/`+0x44` = 1（画成选中态 `Lineup<n>1.tga`） |

刷新时对每名在队角色遍历六个阵位；**第 6 个（下标 5）是特例**：

- `state[5] == 2` → `FUN_00484e30(角色, 1)` 打开该角色全部六个按钮，
  并把 `this+0x27dd4 + 角色*0x798` 处的标志置 1；
- 否则 → 清空该角色整张 6 字节状态表、`FUN_00484e30(角色, 0)` 关掉六个按钮，
  再把六个控件的 `+0xc`/`+0x0` 标志逐个清 0。

[推断] 下标 5 是"入阵/确定"一类的总开关：选中它才允许配置其余五个阵位，
取消它就把该角色整组阵位清空。五个普通阵位对应五灵（水火风雷土），
与 gdb `ElementPositionRequirementType`（Any/水/火/风/雷/土/中/…）里的
1..5 相合 [推断：未在代码里读到阵位号→五灵的显式映射]。

## 光照（2026-09-14）

- 这一页不挂灯：节点绘制 `FUN_0047d440` 只 `Begin(节点相机)` + `SetAsCurrent(3)`，页面绘制 0x4850e0 也没有；
  PAL3 的导入表里没有 `gbGfxManager::SetAmbientLight` / `GetAmbientLight`，全程序不改全局环境光。
- gbengine：全局环境光在 gbGfxManager `+0x1ac`，初始化 0x1d9b9–0x1d9f7 写 (0.2, 0.2, 0.2)。场景图给每个物体算
  着色器变量 `ambient`（0x15979–0x15a6b）：(全局环境光 + 灯的环境分量 `[esi+0x24..]`) × 材质 `+0x10..+0x1c`
  + `+0x1bc` × 材质 `+0x30..+0x3c`。变量名表在 .data 0x11fc54：alltm bonetm fogplane lightpos ambient
  diffuse specular lightatten。`CalEffectiveVolMod`（0x14dc0）每个物体最多挑两盏各类灯。
- 角色走 `skin.gbf`：顶点色 `Diffuse = ambient`，不看法线；`geom.gbf` 是固定管线 贴图 × 顶点光照。
- 移植端没有材质 ambient / emissive 和这套全局环境光，`lineup_disc` 仍用满环境光——亮度和原版不同，要在渲染器里补。
- 自发光（2026-09-14 补）：公式里的 `+0x1bc` 是 gbGfxManager 的自发光系数（导出 `EnableEmissive` 0x4ff0 /
  `SetEmissiveFactor` 0x5020 / `GetEmissiveFactor` 0x5030），初始化清 0；PAL3 导入表里没有这几个，gbengine 内部也没有
  调用，所以一直是 0。角色 MV3 材质（每个贴图记录前 17 个 float = D3D 材质 diffuse/ambient/specular/emissive/power）
  ambient 都是 (1,1,1)，emissive 景天/龙葵/B30 为 1、雪见 0.9、怪 301 为 0。于是这一页角色的顶点色 =
  0.2 + 场景图里挂着的灯的环境分量（`CalEffectiveVolMod` 挑的，可能来自当时冒险场景留在全局场景图里的光源）——
  静态分析定不出固定值。对照原版实机截图（逗游网 https://www.doyo.cn/article/29258 的配图，400×300：左上「隊列」、
  五灵盘上景天雪见龙葵等人、右边每人的指令格）：盘上的人是正常亮度，不是 0.2 那种暗；移植端满环境光的截图（M01，
  只有景天）亮度相当，照用。（先前一张 924×458 的截图里盘的下半截没画出来，是窗口被手动缩小了；正常 2560×1856 下整个盘完整。）
